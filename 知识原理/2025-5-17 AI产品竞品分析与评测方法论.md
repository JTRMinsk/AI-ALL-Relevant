# AI产品竞品分析与评测方法论

> 课程笔记 | 2025年4月 · 两节课程整合整理

---

## 一、为什么学竞品分析

### 1.1 行业背景

- AI训练师的标准工作范围不一定包含竞品分析，但早期AI产品上线前需要做**版本迭代**和**功能上线评估**，竞品分析是产品迭代的核心输入。
- 当前AI产品处于**爆发式增长**阶段，一天能看到100个新产品出现。
- **AI产品岗位五项核心能力**：
  1. 提示词（PE）撰写
  2. SFT（监督微调）能力
  3. Agent搭建
  4. 模型底层架构了解
  5. 模型选型

### 1.2 AI产品门槛已大幅降低

- **Cursor / 任意AI IDE + 一个API模型 = 产品**
- 实战案例：用Claude写PRD文档 → 丢进CC自动开发 → 一周出一个标注平台（有bug还需内测）
- 核心转变：**最难的不再是技术实现，而是挖掘用户需求**
- 典型案例——3D打印：一年前还需要人工建模，现在AI 3D生成已经完全满足需求

### 1.3 AI产品的本质

- 以"宠物翻译硬件"为例——让猫狗"开口说话"，底层原理只是 **TTS（文本转语音）+ ASR（语音识别）+ 翻译**，极其简单
- 现在的AI产品80%~90%都是**模型能力的封装**：
  - API嵌入基础模型
  - 顶多加PE（提示工程）
  - 简单Agent架构
  - SFT微调
  - RAG（检索增强生成）
- 这些技术都是已学过的内容，差异化不在于技术本身

### 1.4 通往AGI的五个阶段（OpenAI提出）

| 阶段 | 名称 | 特征 |
|------|------|------|
| 第一阶段 | **Chatbot（聊天机器人）** | GPT-3.5阶段，基础对话能力 |
| 第二阶段 | **Reasoner（推理者）** | 具备CoT（思维链）能力，会思考推理 |
| 第三阶段 | **Agent（智能体）** | 推理 + 聊天 + 工具调用 = 有了"手"，能执行任务 |
| 第四阶段 | **Innovator（创新者）** | AI帮助做科研突破，如蛋白质序列研究（AlphaFold，DeepMind，诺贝尔奖级别成就） |
| 第五阶段 | **Organization（组织）** | 一个AI就是一个公司，人类给AI打工 |

## 二、竞品分析基础认知

### 2.1 什么是竞品分析

找到**形态相似**的产品，对其以下三者进行**综合对比**：

- **产品形态**
- **功能模块**
- **模型能力**

### 2.2 分析方法

- 打分对比
- 对比判定
- 用户访谈

### 2.3 目标

看竞品在功能和表现上有什么**优势**，为自身产品决策提供依据。

### 2.4 经典案例：拼多多如何在淘宝市场中突围

拼多多发现了一个关键需求锚点：**80%的用户爱买便宜货**。围绕这个核心洞察建立产品战略，在看似饱和的电商市场中杀出重围。

## 三、AI产品的四层架构

以**Kimi**为案例进行拆解，理解一个AI产品的分层结构：

### 四层架构

```
用户层  →  功能模块（对话、问答、PPT、Agent）
              C端 vs B端定位（Kimi → C端；智谱 → B端）

技术层  →  在模型基础上叠加 Agent能力 + RAG能力 + 工具调用能力

模型层  →  可选择的模型（如 Kimi 右下角的 2.6 版本）

基础层  →  算法、数据处理（暂时不用关注）
```

### 竞品分析聚焦点

实际做竞品分析时，只需关注两个层面：

- 有什么**模型**
- 有什么**功能模块**

基础层（算法、数据处理）在竞品分析中无需关注。

---

## 四、竞品分析的四大维度

### 4.1 维度总览

**1. 市场定位**

- 产品定位
- 目标人群
- 市场规模
- 商业模式

**2. 模型技术**

- 基础模型
- 模型性能评估
- 技术架构
- 性价比（token价格、首字延迟、上下文窗口）

**3. 产品功能**

- 核心功能
- 功能矩阵（显性功能 + 隐性功能）

**4. 用户体验**

- 交互流程
- 界面设计
- 内容质量

### 4.2 显性功能 vs 隐性功能

| 类型 | 定义 | 举例 |
|------|------|------|
| **显性功能** | 界面上能点击的、能看到的功能模块 | 按钮、菜单、Tab页 |
| **隐性功能** | 不会在界面上标出来，只能通过输入prompt测试才知道的能力 | Claude能生成交互分析图/Excel，GPT不行 |

隐性功能是评测中的关键发现点——这类能力需要通过**实测prompt**来挖掘。

## 五、竞品分析全流程

### 5.1 流程总览

```
明确目标 → 选择竞品 → 确定分析维度 → 数据收集与评测 → 产出报告
```

### 5.2 第一步：明确目标

搞清楚分析是给谁做的——不同受众需要不同信息：

| 受众 | 关注点 |
|------|--------|
| **老板** | 全都要——市场格局、对手优劣势、整体竞争力 |
| **产品团队** | 功能差异 + 用户反馈 |
| **研发团队** | 技术模块、实现路径 |
| **运营团队** | 用户体验 + 商业模式（怎么赚钱） |

### 5.3 第二步：选择竞品

三类竞品的定义与识别：

1. **直接竞品**：重合度极高，功能几乎一模一样
   - 例：抖音 vs 快手、美团 vs 饿了么

2. **间接竞品**：解决相同痛点、争夺相同用户时间
   - 例：滴滴 vs 共享单车 vs 地铁

3. **潜在竞品**：目前不是对手，但未来可能形成威胁
   - 例：微信 vs 抖音聊天（社交领域的潜在入侵）

### 5.4 第三步：确定分析维度

从四大维度（市场定位、模型技术、产品功能、用户体验）中，根据目标选取子维度进行聚焦分析。

### 5.5 第四步：数据收集与评测

三种收集方式（见下一章详述）。

### 5.6 第五步：产出最终报告

将分析结果整理为结构化报告（报告写法见第九章）。

## 六、数据收集的三种方式

### 6.1 公开检索

通过公开渠道获取数据：

- **行业报告**：了解市场格局和趋势
- **七麦数据（Qimai）**：应用商店数据、下载量、排名
- **AIXC（arxiv）论文网站**：获取技术论文和模型评测数据

> 公开检索能解决**市场定位**和**模型技术**两个维度的分析需求。

### 6.2 产品体验（核心方法）

打开产品，亲自使用：

- **能点的都点**——探索所有功能入口
- **完成典型用户任务**——走通完整的用户流程
- **记录每一步**——截图、笔记、感受

这是竞品分析中最有价值的数据来源。

### 6.3 用户调研

通过用户反馈获取洞察：

- **问卷调研**：大规模收集量化数据
- **现场访谈**：深度了解用户痛点、满意度、不使用的原因

**案例**：字节跳动做PPT功能的用户访谈，设计了**60分钟**的完整访谈流程，包含热身环节、核心体验环节和反馈环节。

> 用户调研的关键产出是：用户**为什么不满意**、**为什么不使用**——这些才是改进的入口。

## 七、不同需求场景的分析侧重点

竞品分析不是千篇一律的模板，要根据实际需求调整焦点：

### 场景一：全面对标

- 触发语："我们也要做Agent产品，直接对标Loveable，去抄一下"
- 需求方：老板
- 侧重点：从头到尾全面拆解，产品形态、功能矩阵、技术实现、用户体验全覆盖

### 场景二：单功能对标

- 触发语："其他产品都出了Deep Research，分析一下效果"
- 需求方：产品团队
- 侧重点：围绕**这一个功能点**精准分析，不需要展开全产品

### 场景三：单模块能力评测

- 触发语："生图能力大家都说是天花板，看看我们差在哪"
- 需求方：研发团队
- 侧重点：**只评生图这一个模块**，深挖技术差异

## 八、评测关键提醒

### 8.1 评测集构建原则

- **从用户反馈差的数据中构建**评测集，不能纯用模型生成评测题
- **评测题要有区分度**：
  - 太简单 → 全100分，无区分度
  - 太难 → 全低分，也无区分度
  - 目标是**中等难度**场景，能拉开能力梯度
- **打分标准要拉齐**，去除人为主观性——这是面试中的高频问题

### 8.2 评测质量控制

- 用截图展示评测结果时，要**画红框标注**问题点
- 打低分时：截图 + 红框 + 写原因，质检可以快速阅览重点
- GOOD CASE 和 BAD CASE 都要有
- 如果所有打分都是5分——要么评测题太简单，要么打分标准有问题
- **论据要真实**：纯靠AI生成的结论不要用，必须是**人评 + 人构建评审点**

### 8.3 面试必问题

> "你怎么拉齐打分标准？怎么去除人为主观性？"

——准备好答案，这是竞品分析岗位的经典面试题。

1. **系统**（Systematic）
2. **全面**（Comprehensive）
3. **客观**（Objective）
4. **可量化**（Quantifiable）

## 十、Deep Research 案例拆解

### 10.1 什么是Deep Research

**Deep Research** 是一种深度研究型搜索，核心特征：

- 与普通搜索的关键区别：不是一次性检索 → 返回结果，而是反复循环：
  > 检索 → 分析 → 不满足 → 再检索 → 再分析 → 再返回

- 典型产品：**Perplexity**，研究报告耗时 **10-30分钟**
- 与RAG的最大区别：能**反复复盘检索结果**，不满足当前结果会继续深挖
- 一句话总结：**让AI从简单问答升级为智能研究员**
- 适用场景：长期研究型任务（写论文、查资料、深度调研）

### 10.2 竞品格局（2025年4月）

**直接竞品：**
- 智谱 AutoGLM
- 百度
- 字节 Coze空间

**间接竞品：**
- Gemini
- OpenAI

### 10.3 功能矩阵分析

按需求层次分级：

- **初级需求**：基础生成
- **中级需求**：中级生成
- **高级需求**：深度研究
- **进阶需求**：跨领域综合研究

### 10.4 评测维度设计

**核心功能层面：**
- 体验每种产品Deep Research的**入口**、**界面**、**附加操作**

**功能矩阵层面：**
- 不同场景推荐（学术、写论文、医疗、金融等）
- 采集各产品的推荐prompt → 构建评测集

**内容质量层面：**
- 通过评测集评估生成结果

### 10.5 评测集构建

**题目来源：**
- 用户query（尤其是**点踩数据**，这是最有价值的来源）
- 开源社区
- 网上评测

**设计原则：**
- 要能**试探出模型边界能力**
- 用**中等难度**场景区分能力等级

**评测方向（四个）：**
1. **新闻整合**
2. **金融分析**
3. **行业研究**
4. **学术论文**

### 10.6 长文本报告评测技巧

Deep Research生成的都是几千字的长报告，评测时：

- 在回复中**截图标注**问题
- 打低分时执行：**截图 + 红框 + 写原因**
- 这样质检可以快速阅览重点

**评测维度示例：**

- 生成稳定性
- 逻辑严密度
- 信息准确性
- 引用源质量
- 内容深度和专业性

- 打分使用**高 / 中 / 低**分级

## 十一、评测报告怎么写

### 11.1 报告标准结构

```
1. 行业现状
   ↓
2. 结论前置（先让老板看到关键信息）
   ↓
3. 产品背景分析（逐个竞品）
   ↓
4. 评测过程（按场景逐一展开）
   ↓
5. 每个场景下：评测结论 → 问题罗列 → 案例截图（带标注）→ 数据
   ↓
6. 最终汇总：综合对比数据
```

### 11.2 报告关键原则

**1. 结论前置**
- 先给结论，再给论据
- 让阅读者（尤其是老板）第一时间看到关键信息："哪家在哪方面强/弱"

**2. 一定要有案例**
- 没有截图/案例的评测报告 = 白做
- 案例是报告的核心说服力

**3. 一定要有数据**
- 不能只说"极梦生成好"——要说好在哪里、哪个维度、什么表现
- 数据展示形式：胜出率、平均分、分值分布

**4. 论据要真实**
- 纯靠AI生成的分析结论不要用
- 必须是人评 + 人构建评审点

**5. 用截图展示置信度**
- 框架红框标注具体问题
- 让阅读者能看到具体的"证据"

### 11.3 按场景展开报告

以Deep Research为例，按四个评测方向逐一展开：

- **新闻整合**：评测结论 → 问题 → 案例截图 → 数据
- **金融分析**：同上结构
- **行业研究**：同上结构
- **学术文献**：同上结构

最后给出综合对比数据汇总。

## 十二、模型选型

### 12.1 模型选型 vs 模型评测

| | 模型评测 | 模型选型 |
|------|------|------|
| 前提 | 公司已有自有模型 | 公司还没有模型 / 要换模型 |
| 目标 | 分析自家模型和竞品模型的差异 | 从市场中选出最合适的模型 |
| 深度 | 聚焦对比 | 更深、更广、更综合 |

### 12.2 模型选型四大核心考量

**1. 质量**
- 生成效果

**2. 成本**
- Token价格（输入/输出分别计算）

**3. 时延**
- 回复速度、首字延迟

**4. 可控性**
- PE是否稳定可控
- 是否兼容Agent链路

### 12.3 选型步骤

1. **确定模态**：产品需要哪种模型？
   - 图生文 / 生视频 / 纯文本

2. **确定能力需求**：
   - 是否需要推理能力
   - 是否需要刷屏能力（长文本生成）
   - 是否需要理解能力
   - 是否需要控制力

3. **确定形态**：
   - API调用
   - 开源模型
   - 本地部署

4. **综合评估**：质量 + 成本 + 时延 + 可控性，找出**最优解**

> 关键认知：最优解**不一定是质量最高的**模型。

### 12.4 实战案例

**案例一：企查查类产品**
- 学长在做类似企查查的产品
- 为什么选择智谱（生成效果一般）？
- 答案："**不要钱**"——成本是决定性因素

**案例二：手表智能对话产品**
- 能内嵌多大的模型？→ **4B或10B的小模型**
- 选型逻辑：最便宜 + 性价比最高 + 生成效果最好

### 12.5 模型选型的时效性

模型市场变化极快，一份模型选型报告有时效性——2025年9月的报告只能适配当时。选型需要定期更新。

### 12.6 找模型的渠道

- **模型竞技场（LMSYS Chatbot Arena）**：匿名A/B评测排名，业界参考标准
- **模型广场 / 内部平台**
- **论文网站**（AIXC / arxiv）
- **关注市场动态**：了解当前最牛的文本模型、生图模型、视频模型及它们的性价比

## 十三、Agent评测要点

### 13.1 评测维度

- **联网检索**：能否正确调用搜索工具
- **数据分析**：能否理解和处理数据
- **图片理解**：多模态理解能力
- **多能力组合**：多项能力协同完成复杂任务
- **多动态交互**：能否生成网页 / PPT / 音视频

### 13.2 可视化展示

用**雷达图**展示多维度对比，直观呈现各竞品在不同维度上的表现。

### 13.3 规划与思考路径

评测重点：Agent的**执行逻辑**是否符合人类逻辑，是否选择了**最优解**。

- 不是只看最终结果，还要看Agent"怎么想的"
- 思考路径是否合理、高效

### 13.4 产品交互对比

- 分析入口模块
- 分析思考规划模式
- 每个界面都要截图

### 13.5 评测集难度分级

按难度对评测题分级：
- **L1**：基础任务
- **L2**：中等难度
- **L3**：高难度

通过分级可以更精准地评估Agent在不同复杂度下的表现。

---

## 十四、视频评测要点

### 14.1 评测维度

- **主体契合度**：生成内容是否与prompt描述的主体一致
- **情节与连贯性**：视频是否有合理的叙事逻辑
- **生成速度**：从输入到产出的耗时
- **稳定性**：多次生成结果的一致性

### 14.2 减少主观偏差

- 使用**投票 / 盲评**方式
- 评测者不知道视频来自哪个模型，避免品牌偏见

### 14.3 打分方法

- 每个维度**单独打分**
- 然后**汇总排名**

### 14.4 Prompt设计思路

不同场景 → 不同子维度 → 对应评价标准

评测的prompt不是随便写的，要能覆盖各个评测维度，每个prompt对应特定的评价维度。

## 十五、小组作业注意事项（综合提醒）

### 报告结构

- **结论前置** + **案例展示** + **数据展示**

### 评测集

- 不能纯用AI生成评测题——要**自己体验、调整**
- 评测集要有区分度，不能太简单也不能太难

### 打分标准

- 要有**案例支撑**，不能只有干巴巴的条文
- 打分标准要拉齐，去除人为主观性

### 数据展示

- 胜出率、平均分、分值分布
- 不只是数字，要能看出差异

### 案例

- **GOOD CASE 和 BAD CASE 都要有**
- 截图 + 红框标注问题点

### 自检

- 如果所有打分都是5分 → 要么评测题太简单，要么打分标准有问题

## 附录：快速参考卡

### 竞品分析四大维度速查

1. **市场定位**：产品定位、目标人群、市场规模、商业模式
2. **模型技术**：基础模型、模型性能、技术架构、性价比
3. **产品功能**：核心功能、功能矩阵（显性+隐性）
4. **用户体验**：交互流程、界面设计、内容质量

### 竞品分析五步流程

1. 明确目标（给谁做？）
2. 选择竞品（直接/间接/潜在）
3. 确定维度（从四大维度中选取）
4. 数据收集（公开检索+产品体验+用户调研）
5. 产出报告（结论前置+案例+数据）

### 三类竞品速查

- **直接竞品**：功能几乎一模一样
- **间接竞品**：解决相同痛点
- **潜在竞品**：未来可能形成威胁

### 评测报告金句

- **结论前置**——让老板第一眼就看到关键判断
- **截图+红框**——打低分必须标注原因
- **GOOD + BAD**——两个方向的案例都要有
- **论据真实**——AI生成的结论不能用

### 模型选型四要素

- **质量**：好不好
- **成本**：贵不贵
- **时延**：快不快
- **可控性**：稳不稳

> 最优解 ≠ 质量最高
