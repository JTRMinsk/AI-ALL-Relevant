## 12. 完整概念因果链

### 12.1 总览图

```
┌──────────────────────────────────────────────────────────────┐
│                  多模态大模型完整生命周期                       │
└──────────────────────────────────────────────────────────────┘

输入侧                  主体                  输出侧
──────                  ────                  ──────

文字 ─→ Tokenizer ─┐                       ┌─→ Detokenizer ─→ 文字
                    │                       │
图片 ─→ ViT ────────┤                       ├─→ Image Decoder ─→ 像素
                    │                       │
音频 ─→ AudioEnc ───┼─→ 统一向量序列 ─→ ────┼─→ Audio Decoder ─→ 波形
                    │      ↓                │
视频 ─→ FrameEnc ───┘   Prefill             └─→ Video Decoder ─→ 帧
                        (LLM 80 层)
                            ↓
                        KV Cache
                            ↓
                         Decode
                       (逐 Token 吐)

        ↑ Encode 阶段        ↑ LLM 主体        ↑ 解码到原始模态
       (翻译进 LLM)         (和纯文本一样)   (翻译回去)

  流派 A:右侧只有"Detokenizer → 文字"这条线
  流派 B:右侧四条线都有
```

### 12.2 四种模态的处理路径

#### 文本路径

```
文字
  ↓ Tokenizer (BPE) — CPU 毫秒级
Token ID 序列 [123, 456, 789]
  ↓ Embedding 查表 (15万行 × 4096维)
向量序列 [v1, v2, v3]
  ↓ 进入 LLM 输入层
[准备 Prefill]
```

#### 图像路径

```
图片 (1024×1024 RGB)
  ↓ 切 Patch (14×14 像素)
5329 个 patch
  ↓ 线性投影 + 位置编码
5329 个 1024 维向量
  ↓ ViT (24 层 Transformer)
5329 个上下文化的 1024 维向量
  ↓ Q-Former / Resampler 压缩
256 个 1024 维向量
  ↓ Projector (2 层 MLP)
256 个 4096 维向量
  ↓ 拼进 LLM 输入序列
[准备 Prefill]
```

#### 音频路径

```
原始波形 (16 kHz 采样)
  ↓ STFT + 转梅尔刻度
梅尔频谱图 (80 维 × N 帧)
  ↓ Whisper Encoder (32 层 Transformer)
1500 个 1024 维向量 (30 秒音频)
  ↓ Projector
1500 个 4096 维向量
  ↓ 拼进 LLM 输入序列
[准备 Prefill]
```

#### 视频路径

```
原视频 (30 fps, 2 分钟)
  ↓ 抽帧 (1 fps)
120 帧图片
  ↓ 每帧过 Vision Encoder
120 × 256 = 30720 个 patch token
  ↓ 时序压缩 (Temporal Pooling / Q-Former)
压缩到几百到几千个 token
  ↓ Projector + 时间位置编码
N 个 4096 维向量
  ↓ 视频里的音频走音频路径
  ↓ 拼进 LLM 输入序列
[准备 Prefill]
```

### 12.3 LLM 内部三阶段

```
[输入向量序列]
       ↓
   Prefill 阶段 (LLM 80 层)
       ↓ 算力密集,GPU 跑满
   每层产生 K, V → KV Cache
       ↓
   输出第一个 Token
       ↓ TTFT 终点
   Decode 阶段
       ↓ 带宽密集,逐字吐
   每次读 KV Cache + 计算下一个 Token
       ↓
   完整回答
```

### 12.4 Token / Embedding / KV Cache 因果链

```
文字
   ↓ Tokenizer
Token ID (整数, 4 字节)
   ↓ Embedding 查表
Embedding 向量 (4096 维, 8 KB) ── 固定,查表得到
   ↓ 拼接入 LLM 输入序列
   ↓
进入 LLM Layer 1
   ↓ Self-Attention + FFN
K₁, V₁ → KV Cache 第 1 层 ── 上下文相关
   ↓
进入 LLM Layer 2 ...
   ↓
   ...
   ↓
进入 LLM Layer 80
   ↓
K₈₀, V₈₀ → KV Cache 第 80 层

总计:1 个 Token → 160 个 KV Cache 向量
```

## 14. 术语精确对照

### 14.1 "向量化" 系列

| 中文 | 对应英文 | 用在哪 |
|---|---|---|
| **向量化** | **Vectorization** | 最通用、最泛的伞形术语 |
| **嵌入** | **Embedding** | 当指代"把离散物变成向量"时 |
| **编码** | **Encoding** | 当指代"用模型把原始数据压成向量"时 |
| **表征** | **Representation** | 学术语境,强调"用向量表示某物" |
| **特征化** | **Featurization** | 传统机器学习语境 |
| **分词** | **Tokenization** | 特指文字切成 Token |

**关键认知**:

> **"向量化"是个**伞形术语(umbrella term)**——它能罩住 Embedding、Encoding、Featurization 等更精确的术语。**
>
> **用在口语和泛指时完全合适;写技术文档时建议用更精确的词。**

### 14.2 Token 系列

| 概念 | 性质 | 在词表里吗 | 能反查回字符串吗 |
|---|---|---|---|
| **文字 Token** | 整数 ID | ✅ 在 | ✅ 能 |
| **视觉 Token / 软 Token** | 4096 维浮点向量 | ❌ 不在 | ❌ 不能 |
| **VQ-VAE 视觉 Token / 硬 Token** | 整数 ID(视觉词表) | ✅ 在视觉词表 | 部分能(重建图片) |
| **Token Embedding** | 4096 维浮点向量 | — | — |

### 14.3 Token / Embedding / KV Cache 三角关系

| 概念 | 是什么 | 数量(单 Token) | 是否上下文相关 | 占用空间 |
|---|---|---|---|---|
| **Token ID** | 整数 | 1 个数 | ❌ 固定 | 4 字节 |
| **Embedding** | 浮点向量 | 1 个 4096 维向量 | ❌ 固定(查表的) | 8 KB |
| **KV Cache** | 浮点向量集合 | 160 个 4096 维向量 | ✅ 上下文相关 | 1.3 MB |

**用 Salim 笔记的比喻**:

```
Token = 身份(这是哪个词)
Embedding = 含义(这个词什么意思)
KV Cache = 记忆(模型当前对它的理解状态)
```

### 14.4 Encode / Prefill / Decode

| 阶段 | 干什么 | 谁做 | 瓶颈 |
|---|---|---|---|
| **Encode** | 模态翻译成向量 | Encoder(ViT/Whisper 等) | 算力 |
| **Prefill** | 向量灌进 LLM 一次性消化 | LLM 80 层 | 算力 |
| **Decode** | 逐字生成回答 | LLM 80 层 | 带宽 |

### 14.5 VLM vs 文生图

| 维度 | VLM | 文生图模型 |
|---|---|---|
| 方向 | 图 → 文 | 文 → 图 |
| 架构 | Transformer LLM | Diffusion Model |
| 代表 | GPT-4V、Claude、Qwen-VL | Midjourney、SD、通义万相 |
| 上下文需求 | 4K ~ 2M(被视频逼大) | 50 ~ 500 Token(很短) |

### 14.6 数据类型

| 名字 | 类型 | 位数 | 字节 |
|---|---|---|---|
| FP32 | 浮点 | 32 | 4 |
| FP16 | 浮点 | 16 | 2 |
| BF16 | 浮点 | 16 | 2 |
| FP8 | 浮点 | 8 | 1 |
| INT8 | 整数 | 8 | 1 |
| INT4 | 整数 | 4 | 0.5 |

**规则**:FP=浮点,INT=整数,数字是 bit 数,÷8 是字节数。

## 15. 速记口诀汇编

### 15.1 总览口诀

> **万语归宗:文字、图片、音频、视频,最终都翻译成 LLM 听得懂的向量序列,然后一视同仁地处理。**

### 15.2 三段式口诀

> **Encode 是"翻译外语"——把图、音、视频翻译成 LLM 听得懂的话**
>
> **Prefill 是"看完全文"——把整段输入读一遍并记笔记(KV Cache)**
>
> **Decode 是"逐字开口"——根据笔记一个字一个字地吐出回答**

### 15.3 Token 经济学口诀

> **文本是稀饭,图片是肉,视频是整头牛。**
>
> **稀饭一勺一个 Token,肉一块上千个,整头牛能把你的 Context 撑死。**

### 15.4 VLM vs 文生图口诀

> **VLM 看图,扩散模型生图,两者底层架构不一样、对"上下文"的需求也不一样。**
>
> **Midjourney 的 prompt 短到几乎可以忽略不计,跟"长上下文"半毛钱关系都没有。**

### 15.5 人脑对比口诀

> **LLM 的多模态:万语归宗,所有模态都翻译成类语言 token,再让 LLM 主体一视同仁地处理。**
>
> **人脑的多模态:各司其职,每种感官有专门皮层并行处理,高层联合区做概念整合,语言只是其中一个模块。**

### 15.6 Encoder 是大模型口诀

> **Encoder 不是简单的翻译官,它是一个**专门读图/听音/看视频的大模型**。**
>
> **整个多模态系统是 "Encoder 大模型群 + LLM 大模型 + Decoder 大模型群" 的复合体——你看到的"一个多模态模型",其实背后是一支由七八个大模型组成的乐队。**

### 15.7 软 Token 口诀

> **Encoder 不是翻译机,是嵌入机。**
>
> **它不把图像"翻译"成文字,而是把图像"嵌入"到文字 Token 共享的语义空间里——成为一种 LLM 能理解但人类读不出来的"软 Token"。**
>
> **离 Token 很近,但中间没有 Token。**

### 15.8 Token 数据格式口诀

> **Token = 一个整数 ID = 词表里的索引位置 = 4 字节的"门牌号"**
>
> **它本身没有任何语义,含义全在"查词表"和"查 Embedding 表"这两个动作里。**

### 15.9 Embedding 数学形态口诀

> **Embedding = 4096 个浮点数 = 高维空间里的一个固定坐标 = Token 的"标准语义位置"**
>
> **KV Cache = 这个 Token 经过 LLM 80 层加工后的 160 个上下文相关向量 = "语义位置在当前上下文里被丰富后的足迹"**

### 15.10 Tokenizer 口诀

> **Tokenizer = "训练出来的查表程序"——训练阶段在海量文本上统计常见字符组合并合并成 token;推理阶段拿到文字按训练好的规则机械合并,输出整数 ID 序列。CPU 毫秒级,永远确定。**

### 15.11 数据类型口诀

> **FP = 浮点(小数),INT = 整数,后面跟着的数字就是占的 bit 数,÷8 就是字节数。**
>
> **位数 = 精度 = 显存代价,三者一损俱损一荣俱荣。**

### 15.12 ViT + Projector 口诀

> **ViT = "图片版的 Transformer",专门用 Self-Attention 让 patch 互相看、看懂全图。**
>
> **Projector = "一个 2 层 MLP 的小翻译官",把 ViT 输出翻译成 LLM 能直接吃的格式。**
>
> **两者协作 = 给 LLM 装上"眼睛"——ViT 看,Projector 翻译,LLM 思考。**

## 16. 常见误解纠正

### 16.1 误解 1:Encoder 把图片变成文字 Token

❌ **错**。Encoder 输出的是**向量**(在 LLM 的 Embedding 空间里),不是文字 Token。这些向量不在词表里,不能反查回字符串。

✅ **正确**:Encoder 把图片**嵌入**到文字 Token 共享的语义空间里——离相关文字 Token 很近,但本身不是 Token。

### 16.2 误解 2:Encoder 直接产生 KV Cache 放进 LLM

❌ **错**。Encoder 输出的是"LLM 输入级别的向量",还要走完 LLM 80 层才会产生 KV Cache。

✅ **正确**:Encoder 输出 ≈ Embedding 查表的结果(都是输入向量)。KV Cache 是 LLM 自己在 Prefill 时 80 层逐层产生的。

### 16.3 误解 3:Midjourney 是 VLM

❌ **错**。VLM(Vision-Language Model)是"读图模型",而 Midjourney 是"生图模型"。

✅ **正确**:Midjourney / DALL-E / Stable Diffusion / 通义万相是**扩散模型**,跟 Transformer LLM 是两个物种。

### 16.4 误解 4:VLM 都需要超长上下文

❌ **错**。LLaVA-1.5 只有 4K 上下文,但仍是 VLM。

✅ **正确**:VLM 的上下文是被**多图、长文档、视频**逼大的,单图本身不需要超长上下文。

### 16.5 误解 5:每个数字有"正负两个维度"

❌ **错**。维度数 = 数字个数,不是数字 × 2。

✅ **正确**:4096 个数字 = 4096 个维度。每个维度的值可正可负,但"正负"不是独立维度,是同一个维度里的取值方向。

### 16.6 误解 6:Embedding 根据上下文变换

❌ **错**。Embedding 是查表得到的,**固定**——"猫"的 Embedding 永远是那串数字。

✅ **正确**:Token 在 LLM 内部的**中间状态**根据上下文逐层变换,这些变换的结果存在 KV Cache 里。

### 16.7 误解 7:Tokenizer 是个死程序

❌ **错**。Tokenizer 的规则不是手写的,是统计学习来的。

✅ **正确**:Tokenizer = "训练出来的查表程序"。规则是数据训出来的(不死),执行是纯查表(不慢)。

### 16.8 误解 8:LLM 同一问题不同回答是因为 Tokenizer 不稳定

❌ **错**。Tokenizer 永远确定,同一句话切出来的 Token 永远一样。

✅ **正确**:LLM 的"每次回答不一样"来自最后一步**采样**(temperature / top-p)。前面所有阶段都是确定的。

### 16.9 误解 9:hidden_size 一定是 4096

❌ **错**。4096 是 LLaMA-7B 的宽度。不同模型不同(768 ~ 18432 都有)。

✅ **正确**:hidden_size 是模型设计时选定、训练完锁死的参数。从 Embedding 表到 80 层中间状态到 KV Cache,全部统一使用。

### 16.10 误解 10:Encoder 只是简单的前处理

❌ **错**。Vision Encoder 是 300M-6B 参数的大模型,Whisper 是 1.5B,视频 Decoder 30B+。

✅ **正确**:Encoder 和 Decoder 本身都是经过大规模训练的复杂模型——一个完整多模态系统是 7-8 个大模型组成的"乐队"。

## 附录:终极一句话总结

把这一系列讨论的核心结论压缩成几句话:

> **多模态大模型的精髓是"Encoder 分流、LLM 主体合流、Decoder 再分流"——输入端各模态翻译进来,LLM 不分彼此地处理,输出端按词表决定能输出什么。**
>
> **Encoder 不是翻译机,是嵌入机——它把图像/音频/视频嵌入到文字 Token 共享的语义空间里,成为"离 Token 很近但本身不是 Token"的软 Token。**
>
> **整个流水线分三段:Encode 翻译模态、Prefill 灌进 LLM、Decode 逐字吐字。三段的硬件瓶颈不同,工程上正在被拆开优化。**
>
> **多模态 Token 消耗是纯文本的 50-400 倍——这是被信息密度差异逼出来的,也是 Gemini 拼命做长上下文的根本动机。**
>
> **当前这套架构本质上是"语言中心主义"——和人脑的"模态专家并行"路线截然不同。能走多远、要不要走另一条路(JEPA、世界模型),是 2024-2026 年 AI 最大的开放问题。**
