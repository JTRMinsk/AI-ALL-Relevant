## 这份笔记从哪里来

从一个朴素问题出发:**"向模型传文字、图片、音频、视频之后,模型内部会发生什么?"**

经过十几轮讨论,推到一个精确表述:**"Encoder 输出的不是文字 Token,而是和文字 Token 共享同一语义空间的连续向量——离 Token 很近,但中间没有 Token。"**

这条认知链由八个核心结论串成,下面依次过一遍。

---

## 一、万物皆向量

不管输入什么模态,Transformer 内部能处理的**只有一种东西**:一串向量。

所以多模态的工程关键是:**怎么把图片/音频/视频变成"一串向量",并且让这串向量"长得像"文本 Token 经过 Embedding 之后的样子?**

```
文字  → Tokenizer + Embedding         → 一堆 4096 维向量
图片  → 切 patch → ViT → Projector   → 一堆 4096 维向量
音频  → 梅尔频谱 → Whisper Encoder    → 一堆 4096 维向量
视频  → 抽帧 → ViT×N + 时序模块       → 一堆 4096 维向量
```

这些向量被拼成一个长序列喂给 LLM。**模型从此刻开始不再区分这些向量原本是什么模态**——对它来说全是"Token"。

五个必背术语:**ViT**(图片版 Transformer)、**Patch**(图块)、**Projector**(对齐到 LLM 空间的小 MLP)、**CLIP**(图文对齐训练范式)、**Mel-Spectrogram**(把音频变成"图"的标准表示)。

---

## 二、三段式流水线:Encode / Prefill / Decode

```
Encode → Prefill → Decode
 翻译     灌入      吐字
```

- **Encode**:把"非 Token 的东西"翻译成向量,**发生在 LLM 之前**(Vision Encoder/Whisper 等独立模型)
- **Prefill**:把向量序列在 LLM 80 层里跑一遍,**每层产生 K、V → KV Cache**;输出第一个 Token(TTFT 在这里产生)
- **Decode**:逐字自回归生成,每步读 KV Cache

三阶段对照:

| 维度       | Encode     | Prefill         | Decode   |
| -------- | ---------- | --------------- | -------- |
| 谁参与      | 专用 Encoder | LLM 80 层        | LLM 80 层 |
| 是否经过 LLM | **否**      | 是               | 是        |
| 瓶颈       | 算力         | **算力**          | **带宽**   |
| 并行性      | 一次性        | 所有 Token 并行     | 一次只一个    |
| 能否缓存     | 能(同图复用)    | 能(Prompt Cache) | 不能       |

工程意义:三步独立缓存(Encoder Cache / Prompt Cache / KV Cache),三步硬件瓶颈不同(NVIDIA 新卡 Prefill 要 FLOPS、Decode 要 HBM 带宽),三步可以分到不同机器跑(PD 分离)。

## 三、Token 经济学:为什么多模态烧钱

文本是**高度压缩过**的信息载体,图片/音频/视频是原始物理信号——Encoder 没法事先知道哪些重要,只能一视同仁地都变成 Token。

**信息密度排序**:文本 >> 代码 > 表格 > 语音 > 图片 > 视频。

表达同一件事(比如"一只橘猫在键盘上睡觉"):
- 文字 ≈ 8 Token
- 图片 ≈ 1000 Token(125×)
- 10 秒语音 ≈ 500 Token(62×)
- 10 秒视频 ≈ 3000 Token(375×)

各家典型消耗:
- GPT-4o 一张图 85-1700 Token
- Whisper 约 50 Token/秒
- Gemini 视频约 17000 Token/分钟
- **1 小时视频 ≈ 100 万 Token**

**这就是 Gemini 拼命做 1M/2M 上下文的根本动机——它就是为吃视频准备的**。

连锁后果:KV Cache 爆炸(1 小时视频 KV Cache 可达 320 GB)、TTFT 暴增、API 账单线性膨胀。工业界对策:降采样、Q-Former 压缩 Token 数、预先 ASR 转文字、关键帧选择。

> 你笔记里那次 Cursor 转 118 分钟音频,走"先转文字再处理"路径,Token 消耗就比直接喂端到端语音模型省 10 倍以上——**省钱是这条路至今主流的原因**。

## 四、VLM 不等于文生图

最容易踩的坑:**Midjourney 不是 VLM**。

```
VLM(读图,图→文)             图像生成模型(生图,文→图)
───────────────              ──────────────────
GPT-4V, Claude Vision         Midjourney, DALL-E
Qwen-VL, Gemini, LLaVA        Stable Diffusion, 通义万相
        ↓                              ↓
   Transformer LLM(自回归)       Diffusion Model(反复去噪)
   上下文 4K~2M                  prompt 撑死 50-256 Token
```

**扩散模型根本不是 Token 那一套**——它从一张纯噪声图开始,反复去噪几十次得到清晰图。**没有"上下文窗口"的概念,prompt 通常被截断到 75-256 Token**(SD 1.5 是硬 75,Midjourney v6 约 60-80,FLUX 256)。

这就是为什么写超长 Midjourney prompt 没用——**后半截它根本读不进去**。

VLM 的上下文是被**多图、长文档、视频**逼大的,单图本身不需要超长上下文(LLaVA-1.5 只有 4K)。

**你 ACA 题 15 的认知归位**:通义千问(Qwen)= VLM 家族,通义万相(Wanx)= 扩散模型家族。Midjourney 对标的是万相,不是 Qwen-VL。万相画不好"夕阳无限好"的准确文字,**因为扩散模型把文字当成"模糊的视觉概念"画**,不擅长精确符号。

## 五、反思:LLM 多模态不像人脑

这是一个戳到当前 AI 架构最深局限的洞察。

**LLM 的做法 = 语言中心主义**:所有模态翻译到类语言空间,LLM 主体统一处理。

**人脑的做法 = 模态专家并行**:视觉皮层、听觉皮层、体感皮层各自独立处理,高层联合皮层做概念整合;**语言区只是众多模块之一**,不是中央处理器。

**三个核心差异**:

1. **架构方向相反**:LLM 是"先翻译再思考";人脑是"并行处理后整合"。聋哑人没有语言但能正常看图、识别情感、解决空间问题——证明思维不必经过语言
2. **人脑有心象,LLM 没有**:你能在脑海里"看见"一只橘猫并旋转它;LLM 没有这种"内在视觉表征",必须调用独立的扩散模型才能生图
3. **人脑具身,LLM 离身**:"苹果"在你脑里 = 视觉/嗅觉/体感/运动皮层的分布式激活;在 LLM 里 = 一个 4096 维向量,没有重量、没有温度

**为什么 LLM 走了反人脑的路**:历史包袱——先有了 Transformer 文本模型,后来需要做多模态,**最省事的方案就是把别的模态翻译成文本能处理的格式**。所以语言被放在了中心,这跟人脑演化史正好相反(先有视觉听觉,后有语言)。

**正在尝试更像人脑的几个方向**:原生多
模态(GPT-4o)、模态专属 MoE 专家(DeepSeek-V3)、JEPA(LeCun 主张不预测 Token 而预测抽象表征)、世界模型(李飞飞 World Labs、V-JEPA)、SNN 脉冲神经网络。

**一个开放问题**:"像人脑"和"有效"是同一件事吗?飞机不像鸟但飞得更高——也许 AI 不需要像大脑就能实现智能。**这是 2024-2026 年 AI 最大的路线之争**。

## 六、Encoder 和 Decoder 本身就是大模型

**常见误解**:Encoder 是个"前处理工具"。**事实**:

- Vision Encoder(ViT-L/14)≈ 300M ~ **6B(InternViT)** 参数
- Audio Encoder(Whisper Large)≈ 1.5B 参数
- 视频 Decoder(Sora 估计)≈ **30B+** 参数

**InternViT-6B 单独就比 Qwen-3B 还大**。

**Encoder 的"文学功底"**:看一张猫图,Encoder 要同时编码低层(纹理、光照)、中层(动物、键盘)、高层(橘猫、慵懒情绪、程序员家居场景)、空间关系(猫在键盘上方、俯视视角)——所有这些塞进 256 个 4096 维向量。**一张图 = 1M 个数字,比 8 Token 描述多 32 倍信息量**。

**训练成本**:CLIP 4 亿对图文 $10M+;Whisper Large 训了 **77 年**的音频($10M+);EVA-CLIP-18B $100M+。

**完整画像**:一个多模态系统 = Encoder 大模型群(5-10B)+ LLM 主体(70B-1T)+ Decoder 大模型群(10-50B)= **总计 100B-1T+**,是"七八个大模型组成的乐队"。

**三个反直觉事实**:
- 60%+ 的多模态幻觉来自 Encoder 端(不是 LLM 的锅)
- Encoder 限制整个系统的天花板——Encoder 没看清,LLM 再大也救不了
- Encoder 训练数据质量(图文配对)比 LLM 训练数据更难搞,LAION-5B 的整理本身就是 PhD 级工程

## 七、软 Token:精髓所在

**Encoder 输出不是"文字 Token"**——这是最容易踩的坑。

| 维度 | 文字 Token | Encoder 输出向量 |
|---|---|---|
| 形态 | 整数 ID | 4096 维浮点向量 |
| 在词表里 | ✅ 在 | ❌ 不在 |
| 能反查回字符串 | ✅ 能 | ❌ 不能 |
| 业内叫法 | "硬 Token" | "软 Token"/Visual Embedding |

**几何含义**:Encoder 把图像"嵌入"到 LLM 的 4096 维语义空间,**让它落在相关文字 Token 的附近**。CLIP 训练就在做这件事——让"猫图"的向量靠近"猫"这个字的 Embedding。

**最深刻的判断**:"离 Token 很近,但中间没有 Token"。

```
❌ 错误理解:图 → Encoder → 文字描述 → Tokenizer → 进 LLM
✅ 正确理解:图 → Encoder → 向量(直接在 Embedding 空间)→ 进 LLM
                                       ↑
                              跳过了"变成文字"这一步
```

**跳过 Token 的工程意义**:人类语言是有损压缩,"一只橘猫趴在键盘上"10 个 Token 丢掉了猫毛纹理、键盘品牌、光线角度、构图风格等大量信息。Encoder 输出的 256 个 4096 维向量保留了**远多于文字描述能承载的信息量**——包括人类没词汇形容的视觉模式。

**另一个易混点**:Encoder 输出 **不等于** KV Cache。

```
图 → Encoder → 输入级向量(等同于"Embedding 查表后的状态")
                  ↓ 拼进 LLM 输入序列,进入 LLM Layer 1
                  ↓ Self-Attention + FFN,产生 K₁, V₁ → KV Cache 第 1 层
                  ↓ 重复 80 次,KV Cache 完整生成
```

**Encoder 输出是 KV Cache 的"远房原料",中间还差 80 层 LLM 计算**。

**两条路径**:

- **路径 A(主流,软 Token)**:连续向量,GPT-4V、Claude、Qwen-VL 都走这条
- **路径 B(前沿,硬 Token)**:用 **VQ-VAE** 把图像离散化成视觉词表里的整数 ID,Chameleon、Emu3 走这条——**图像真的被翻译成"视觉文字"**,只不过人类看不懂

**输出端两大流派**:
- **流派 A**:多模态输入,**只输出文字**(95% 的当前 VLM)
- **流派 B**:**原生多模态输出**(GPT-4o 原生模式、Gemini 2.5 Native、Chameleon)——词表里同时有文字 Token、图像 Token、音频 Token

## 八、数学具象:Token / Embedding / KV Cache / ViT

### Token = 一个整数

```
"猫" → Token ID: 28392 → INT32(4 字节)
```

Token ID 本身**完全没有语义**,只是词表里的索引位置。数据库里存的"对话历史" = 一长串整数。

**Tokenizer = 训练出来的 BPE 查表程序**:统计学习的合并规则 + 固定词表(几 MB 大小),纯 CPU 跑、毫秒级、**永远确定**(同一句话切出来的 Token 永远一样)。LLM 的"每次回答不一样"来自最后一步**采样**,跟 Tokenizer 无关。

### Embedding = 4096 个浮点数

字面意义上就是这样:

```
"猫" 的 Embedding(4096 维):
[0.0234, -0.1827, 0.4521, ..., -0.3401, 0.2789]
                4096 个数字,共 8 KB(FP16)
```

**几何含义**:4096 维空间里的一个**固定位置**。所有 15 万个 Token 在这个高维空间里散布,**相近的概念点靠得近**,这就是"语义"的物理形式。

**纠正**:维度数 = 数字个数(4096),不是"每个数字有正负两个维度"。

**经典向量算术**:`向量("国王") - 向量("男人") + 向量("女人") ≈ 向量("女王")`——RAG 的"检索"本质上就是这个空间里的几何最近邻。

**Embedding 表大小**:15 万 × 4096 × 2 字节 ≈ 1.2 GB(LLM 权重的一部分,固定)。

### hidden_size 不固定

4096 只是 LLaMA-7B 的"宽度",其他模型不同:BERT 768、LLaMA-70B 8192、GPT-3 12288。**整个 LLM 内部所有的中间向量都是同一宽度**——从输入到第 80 层输出。

加宽代价是**平方级**(每层权重 hidden² × layers),这就是为什么不能无脑加宽。

### KV Cache 是 Embedding 的 160 倍

**关键区分**:

```
1 个 Token 的输入 Embedding:1 个 4096 维向量(8 KB),固定
1 个 Token 在 KV Cache 里:  80 层 × (K+V) = 160 个向量(1.3 MB),上下文相关
```

类比:Embedding 像"身份证号"(永远不变),KV Cache 像"在不同场合的角色"(同事/父亲/队长——上下文相关)。

**Embedding 本身固定**(查表得到),变的是**模型内部的中间状态**——这些中间状态随上下文逐层加深理解,每层的 K、V 存进 KV Cache。

### ViT + Projector

**ViT = "图片版 Transformer"**,跟你笔记里学的 LLM Transformer 几乎同款,只是输入从 Token 换成 Patch:

```
图(224×224)→ 切 16×16 = 256 个 patch → 每个投影成 1024 维向量
→ 24 层 Self-Attention + FFN(让 patch 互相看、看懂全图)
→ 输出 256 个 1024 维向量
```

**ViT 内部如何"看懂"**:第 1 层每个 patch 只看邻居(纹理),第 6 层看到更远(组成猫脸),第 12 层看到全图(完整理解)。

**Projector = 2 层 MLP 小翻译官**,把 ViT 输出(1024 维)对齐到 LLM 输入空间(4096 维):

```python
Projector = Linear(1024→4096) → GELU → Linear(4096→4096)
约 2000 万参数(20M)
```

**多模态训练的核心秘密**:训练 LLaVA 时,ViT 冻结、LLM 冻结,**只训练这个 20M 的小 Projector**——这就是 LLaVA 用几小时 8×A100 就能给 LLaMA 装上"眼睛"的原因。

### 数据类型命名规则

```
FP32 = Float Point + 32 bit = 4 字节  ← 训练
FP16 = 2 字节                       ← 推理
BF16 = 2 字节(指数位多、精度位少)    ← 训练防溢出
INT8 = 1 字节                       ← 量化
INT4 = 0.5 字节                     ← 极致量化(你笔记里的 Q4)
```

规则:**FP=浮点 / INT=整数,后面数字是 bit 数,÷8 是字节数**。位数 = 精度 = 显存代价,一损俱损一荣俱荣。

## 速查:关键术语对照

**"向量化"是伞形术语**(umbrella term),罩住 Tokenization(分词)、Embedding(嵌入)、Encoding(编码)、Representation(表征)、Featurization(特征化)。口语用"向量化"完全合适,技术文档建议用更精确的词。

**Token / Embedding / KV Cache 三角**:

| 概念 | 是什么 | 单 Token 数量 | 占用空间 | 上下文相关 |
|---|---|---|---|---|
| Token ID | 整数 | 1 个数 | 4 字节 | ❌ |
| Embedding | 浮点向量 | 1 个 4096 维 | 8 KB | ❌(查表) |
| KV Cache | 浮点向量集合 | 160 个 4096 维 | 1.3 MB | ✅ |

放大关系:ID → Embedding 放大 **2000 倍**,Embedding → KV Cache 再放大 **160 倍**。

**软 Token vs 硬 Token**:

| | 软 Token(主流) | 硬 Token(VQ-VAE) |
|---|---|---|
| 形态 | 连续浮点向量 | 离散整数 ID |
| 在词表 | ❌ | ✅(视觉词表) |
| 能反查 | ❌ | 部分能 |
| 代表 | GPT-4V、Claude、Qwen-VL | Chameleon、Emu3 |

## 十个常见误解一图清

| ❌ 误解 | ✅ 正确 |
|---|---|
| Encoder 把图片变成文字 Token | 变成"和 Token 共享语义空间的连续向量",不在词表 |
| Encoder 直接产生 KV Cache | Encoder 输出 ≈ Embedding 状态,KV Cache 是 LLM 自己 80 层算出来的 |
| Midjourney 是 VLM | Midjourney 是扩散模型,跟 VLM 是两个物种 |
| VLM 都需要超长上下文 | 单图本身不需要,长上下文是被多图/长 PDF/视频逼出来的 |
| 每个数字有"正负两个维度" | 4096 个数字 = 4096 维,正负是同一维度的取值方向 |
| Embedding 根据上下文变 | Embedding 固定(查表得到),变的是 LLM 内部中间状态 |
| Tokenizer 是手写的死程序 | 是统计学习出来的 BPE 规则 + 词表,纯查表执行 |
| LLM 同问题不同答 = Tokenizer 不稳定 | Tokenizer 永远确定,不确定性来自最后一步采样 |
| hidden_size 一定是 4096 | 因模型而异:768 / 4096 / 8192 / 12288 都有 |
| Encoder 只是简单前处理 | Encoder 本身就是几亿到几十亿参数的大模型 |

## 八条核心口诀

> **1. 万语归宗**:文字、图、音、视频最终都翻译成 LLM 听得懂的向量序列,然后一视同仁地处理。
>
> **2. 三段流水线**:Encode 翻译外语、Prefill 看完全文、Decode 逐字开口。
>
> **3. Token 经济学**:文本是稀饭,图片是肉,视频是整头牛。
>
> **4. VLM ≠ 文生图**:VLM 看图(Transformer),Midjourney 生图(Diffusion),两个物种。
>
> **5. 不像人脑**:LLM 是"翻译公司"(都翻成同一语言);人脑是"大型医院"(各科室并行,会诊整合)。
>
> **6. Encoder 是大模型**:多模态系统是七八个大模型组成的乐队,不是一个模型加几个前处理。
>
> **7. 软 Token 精髓**:Encoder 不是翻译机,是嵌入机——离 Token 很近,但中间没有 Token。
>
> **8. 数学具象**:Token 是整数,Embedding 是 4096 个浮点数(高维空间一个点),KV Cache 是它走过 80 层的 160 份足迹。

---

## 终极一句话总结

> **多模态大模型的精髓是"Encoder 分流、LLM 主体合流、Decoder 再分流"——输入端各模态翻译进来,LLM 不分彼此地处理,输出端按词表决定能输出什么。**
>
> **Encoder 不是翻译机,是嵌入机——它把图像/音频/视频嵌入到文字 Token 共享的语义空间里,成为"离 Token 很近但本身不是 Token"的软 Token。**
>
> **整个流水线分三段:Encode 翻译模态、Prefill 灌进 LLM、Decode 逐字吐字。三段的硬件瓶颈不同,工程上正在被拆开优化。**
>
> **多模态 Token 消耗是纯文本的 50-400 倍——这是被信息密度差异逼出来的,也是 Gemini 拼命做长上下文的根本动机。**
>
> **当前这套架构本质上是"语言中心主义"——和人脑的"模态专家并行"路线截然不同。能走多远、要不要走另一条路(JEPA、世界模型),是 2024-2026 年 AI 最大的开放问题。**
