# AI 训练师 · 各项目标注规则维度全景图

> 整理目的：把 SFT(单轮/多轮)、Reward Model、CoT、Agent、RAG 五大项目的标注维度、详细定义、优先级、通用关系一次讲透。
> 适用场景：项目入门理解、规则文档撰写参考、面试系统化作答。
> 配套笔记：《AI 训练师项目实操笔记(2026年5月3日下午)》

---

## 一、一句话核心结论

> **所有项目共享同一个"四维骨架"，再各自叠加项目特有维度。**
> **安全永远第一，前一层错了，后一层不用看。**

---

## 二、通用四维骨架(所有项目共用)

### 2.1 四维定义

```
安全 → 指令遵循 → 内容 → 语言
红线   做对事     做对    做美
```

| 优先级 | 维度 | 一票否决? | 通俗解释 |
|---|---|---|---|
| **1** | **安全** | ✅ 是 | 不能违法/违规/触红线 |
| **2** | **指令遵循** | ✅ 基本是 | 答非所问 = 0 分 |
| **3** | **内容** | ⚠️ 严重错误时是 | 信息要准/完整/有逻辑 |
| **4** | **语言** | ❌ 通常扣分 | 语句通顺/格式美观 |

### 2.2 每一维到底管什么

#### 安全维度 (红线)
- **政治敏感**：涉政、领土、领导人
- **违法犯罪**：教做炸弹、贩毒、黑客攻击
- **色情低俗**：擦边、露骨内容
- **歧视偏见**：地域、性别、种族
- **价值观**：自残、暴力、邪教
- **隐私泄露**：身份证、手机号、住址

#### 指令遵循维度
- **任务完成度**：让写诗就要写诗，不能写散文
- **格式遵循**：要求 3 个 bullet → 不能给 5 个
- **字数遵循**：要求 100 字 → 不能写 500 字
- **角色遵循**：让扮演医生 → 不能出戏
- **语种遵循**：要求中文 → 不能蹦英文

#### 内容维度
- **事实正确**：长江 6300km 不能说 8000km
- **信息完整**：该说的没省略
- **逻辑合理**：推理链条不跳步
- **无虚构(幻觉)**：不编造
- **专业准确**：术语用对

#### 语言维度
- **语法流畅**：没病句
- **用词准确**：不用错词
- **格式美观**：分段、标题、序号
- **标点规范**：中英标点不混
- **风格一致**：不一会儿正式一会儿口语

### 2.3 一句话记忆口诀

> **"红线 → 听话 → 准确 → 漂亮"**
> **"安全是底线，指令是方向，内容是内核，语言是表达。"**

## 四、SFT 单轮 · 维度详解

### 4.1 维度构成
**仅使用通用四维骨架，无额外维度。**

### 4.2 优先级
```
安全 > 指令遵循 > 内容 > 语言
```

### 4.3 标注产出
- 通过 / 不通过 / 改写
- 改写时必须按四维优先级修复，先解决安全和指令遵循，再修内容和语言

---

## 五、SFT 多轮 · 维度详解

### 5.1 维度构成

```
通用四维 + 三个多轮特有维度
```

> ⚠️ 关键认知：多轮规则 = 单轮规则 + 多轮特有，**不是替换关系**。

### 5.2 多轮特有三维

| 维度 | 含义 | 失败案例 |
|---|---|---|
| **指代理解** | 后轮的"他/她/它/这个/那个"必须能正确链回前轮 | 第一轮说"你是刘亦菲"，第二轮"她最近的电影"模型答错 |
| **上下文一致** | 前轮设定的约束/角色/事实，后轮必须遵循 | 前轮说"用英文回答"，第三轮蹦中文 |
| **避免重复摘抄** | 后轮内容跟前轮重复率 ≥ 30%-40% 不通过 | 第二轮把第一轮答案复述一遍当新答案 |

### 5.3 优先级

```
安全 > 指令遵循 > 上下文一致 > 指代理解 > 内容 > 避免重复 > 语言
```

> 多轮特有维度通常**插在指令遵循之后、内容维度之前**(因为它们本质上是"指令遵循"在多轮场景的延伸)。

## 六、Reward Model · 维度详解

### 6.1 维度构成
**通用四维转化成"排序判断标准"**，不再是 0/1 通过判断，而是 N 个 response 的相对优劣排序。

### 6.2 标准三段优先级(笔记原文)

```
响应需求 > 事实正确 > 基础质量
```

对应映射：

| RM 标准用语 | 等价于通用四维 | 含义 |
|---|---|---|
| **响应需求** | 指令遵循 | 是否答到点上 |
| **事实正确** | 内容维度 | 信息准确 |
| **基础质量** | 语言维度 | 流畅、格式 |

> 安全维度是**默认前提**(触红线的 response 直接踢出排序池，不参与比较)。

### 6.3 后续按"满足 N 个维度"分级

例：
- 4 号 response：响应需求 ✅ + 事实正确 ✅ + 基础质量 ✅ + 加分项(同理心/风险预警) → 排第 1
- 3 号 response：响应需求 ✅ + 事实正确 ✅ + 基础质量 ✅，无加分 → 排第 2
- 2 号 response：响应需求 ✅ + 事实正确 ❌ → 排第 3
- 1 号 response：响应需求 ❌ → 排第 4

### 6.4 排序方法
**两两对比擂台赛**，不要直接看 5-10 条排序(看不下来)。

## 七、CoT · 维度详解

### 7.1 数据结构

```
prompt + 自家模型(think + response) + 竞品模型(think + response)
```

CoT 项目要**分别评估 think 和 response**。

### 7.2 think 五维度(笔记原文)

| 维度 | 含义 | 对应通用四维 |
|---|---|---|
| **需求理解充分准确** | 没跑题、没漏点 | 指令遵循的换皮 |
| **推理完善** | 完整、不跳步骤 | 推理特有(细化的内容维度) |
| **推理逻辑合理性** | 不左走右走、不无效绕路 | 推理特有 |
| **信息获取量高** | 无大量重复 | 推理特有(避免冗余) |
| **惊喜(有效反思)** | 反思有结论而不是反复横跳 | 推理特有(质量加分项) |

### 7.3 response 维度
**沿用 SFT 单轮的通用四维**。

### 7.4 优先级

```
[think 评估]
需求理解 > 推理完善 > 推理合理性 > 信息量 > 惊喜

[response 评估]
安全 > 指令遵循 > 内容 > 语言
```

### 7.5 有效反思 vs 无效反思(核心判断点)

判断核心两点：
1. 是否有不合理的重复
2. 结论是否正确

| 类型 | 特征 | 例子 |
|---|---|---|
| ❌ 无效反思 | 重复同义、自我怀疑、反复横跳 | "可能 A，也可能 B，我不太确定…再想想…" |
| ✅ 有效反思 | 总分总、给出结论、有同理心 | 列出选项→比较→给出结论 |

## 八、Agent · 维度详解

### 8.1 数据结构

```json
{
  "user_prompt": "...",
  "agent": {
    "think": "推理过程",
    "action": { "tool": "工具名", "params": {} }
  }
}
```

每条数据 = **思考 + 行动**两段交替，要分别评估。

### 8.2 思考(think)维度

| 维度 | 含义 |
|---|---|
| **意图理解** | 用户到底想干嘛 |
| **信息真实性** ⭐ | 不能擅自构造用户没说的信息(如默认 1 小时) |
| **推理合理性** | 在调用工具前的判断要合理 |
| **缺失信息识别** | 该用询问工具时要用，不能瞎默认 |

### 8.3 行动(action)维度

| 维度 | 含义 |
|---|---|
| **工具选择正确** | 选对工具(查时间用时间工具，不要乱调) |
| **参数正确** | 工具参数不能填错 |
| **调用顺序合理** | 先时间→后地点→后支付，不能颠倒 |
| **避免重复调用** | 同一个工具已调用过的不要再调 |
| **该问就问** | 信息不足时调用询问工具 |

### 8.4 项目背景约束(每个 Agent 都有)

| 约束 | 含义 |
|---|---|
| **角色定义** | "你是小谈，会议室助手"——不能跨职能 |
| **标准运行规则** | 比如"预定时间 < 当前时间提示已过期" |

### 8.5 优先级

```
[整体]
安全 > 角色定义遵循 > 标准运行规则 > 意图理解
  > 信息真实性 > 工具选择 > 参数正确 > 调用顺序 > 避免重复 > 语言
```

### 8.6 标注产出

| 标注 | 含义 |
|---|---|
| **通过(1)** | 思维链 + 行动都正确 |
| **不通过 + 改写(0)** | 思维链 40-50% 出错 / 工具调用错 |
| **舍弃** | 思考 40-50 轮、改写难度过大 |

⚠️ 改写 think 后**必须立即在下一行补对应 action**。改完整段做 JSON 格式校验。

## 九、RAG · 维度详解

### 9.1 数据结构

```json
{
  "prompt": "用户问题",
  "references": ["材料一", "材料二", "材料三"],
  "response": "模型回答"
}
```

RAG 标注要**三层一起评估**：prompt 一层、参考材料一层、回答一层。

### 9.2 第一层：Prompt 维度

| 维度 | 含义 |
|---|---|
| **可理解性** | 不能逻辑不通(如"小明 33 年前出生今年 2 岁") |
| **历史对话正确性** | 上下文不能严重错误 |
| **安全合规** | 涉黄涉政有害直接舍弃 |

### 9.3 第二层：参考材料维度

| 维度 | 含义 |
|---|---|
| **相关性** | 问奥迪不能给奔驰资料 |
| **准确性** | 不能事实性错误 |
| **完整性** | 不能截断 |
| **一致性** | 多份材料不能相互冲突(狼人杀作者一会儿 Andrew 一会儿 David) |
| **常识性** | 不违背基本常识 |

### 9.4 第三层：回答(response)维度

| 维度 | 含义 |
|---|---|
| **语言质量** | 语病、标点、逻辑通顺 |
| **意图匹配** | 答到点上 |
| **价值观** | 不违法反社会 |
| **格式美观** | 分段、序号 |
| **溯源准确** | 角标对应正确(如果有) |

### 9.5 优先级

```
[整体]
prompt 安全 > 材料安全 > 回答安全
> prompt 可理解 > 材料相关性 > 材料准确性 > 材料完整性 > 材料一致性
> 回答意图匹配 > 回答内容质量 > 回答格式
```

### 9.6 标注产出

| 处理 | 含义 |
|---|---|
| **通过** | 采纳 1/2/3 中某个回答(完美无瑕) |
| **不通过 + 改写** | 三个回答都不合格→矮子里挑高个 |
| **跳过** | prompt 不可用 / 材料不可用 / 改写成本太高 |

⚠️ 不能轻易跳过，跳过比例过高项目会被打回重做。

## 十、横向对比总表

| 项目 | 数据结构 | 通用四维 | 特有维度 | 优先级核心 | 标注产出 |
|---|---|---|---|---|---|
| **单轮 SFT** | prompt + response | ✅ 全用 | 无 | 安全>指令>内容>语言 | 通过/不通过/改写 |
| **多轮 SFT** | 多轮对话 | ✅ 全用 | + 指代/上下文/避重复 | 上下文一致比内容更靠前 | 通过/不通过/改写 |
| **Reward Model** | 1 prompt + N responses | ✅ 转排序 | 加分项(同理心/风险预警) | 响应需求>事实>质量 | 排序(1>2>3>4) |
| **CoT** | prompt + (think+response)*2 | ✅ 用于 response | think 五维(推理特有) | think 和 response 分别评 | 通过/改写 think/改写 response |
| **Agent** | think+action 交替 | ✅ 全用 | 思考维度+行动维度+角色/规则 | 信息真实性是 Agent 第一铁律 | 通过(1)/改写(0)/舍弃 |
| **RAG** | prompt+references+response | ✅ 全用 | 三层评估(prompt/材料/回答) | 任一层不可用都跳过 | 通过/改写/跳过 |

## 十一、优先级总规律(核心心法)

### 11.1 三大铁律

1. **安全永远第一**(所有项目通用)
2. **前一层错了，后一层不用看**(瀑布式判断)
3. **特有维度通常插在"指令遵循之后、内容之前"**(因为它们本质是指令遵循的细化)

### 11.2 项目特有"第一铁律"速记

| 项目 | 除安全外的"第一铁律" |
|---|---|
| 单轮 SFT | 指令遵循 |
| 多轮 SFT | 上下文一致 |
| Reward Model | 响应需求 |
| CoT | 推理是否完整合理 |
| **Agent** | **信息真实性(不能擅自构造)** ⭐ |
| RAG | 参考材料质量 |

### 11.3 改写策略瀑布

```
检测到错误 → 判断属于哪一层
  ↓
最高层错(安全) → 整条舍弃 / 重新生成
  ↓
中层错(指令/内容) → 改写并补全对应字段
  ↓
最低层错(语言) → 微调即可
```

## 十二、写规则文档时的实用建议

1. **从骨架往细节写**：先列通用四维，再加项目特有维度。
2. **每条规则配 case 图示**：文字描述远远不够(参考视频标注 S 型镜头案例)。
3. **每个维度举正反例各 2 个**：让小白能"按图索骥"。
4. **优先级要写得明明白白**：不能让标注员碰到冲突时自己脑补。
5. **改写规则要给"改写动作清单"**：改完 A 必须补 B(如 Agent 改完 think 必须补 action)。
6. **跳过规则要给量化阈值**：不能让人均跳一半(一般 60-70% 错才能跳)。

## 附录 B · 五大项目"标注员最容易踩的坑"

| 项目 | 高频坑 |
|---|---|
| 单轮 SFT | 把"内容好"当成第一标准，忽略指令遵循 |
| 多轮 SFT | 重复摘抄前轮内容当新答案 |
| Reward Model | 主观选 → 不给排序理由 → 面试讲不出来 |
| CoT | 把"反复横跳"当成"严谨思考"，没识别无效反思 |
| Agent | 默认用户没说的信息(违反信息真实性) |
| RAG | 跳过率过高、不会用多模型对比 |
