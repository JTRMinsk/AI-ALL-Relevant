## 一、开场抽问 · 规则文档撰写关键原则

### 1.1 保下限,不追上限

标注同学水平参差不齐(有的拉爆,有的非常好),所以规则文档:
- 要让"什么都不清楚的小白一看就懂"
- 不能让标注员重复来问"这是什么意思"
- 影响他效率 = 影响项目交付

老师反复强调一句:**写文档时把自己当小白**,不是为了文档美观,是为了落地性。

### 1.2 视频标注的真实踩坑案例

老师之前做视频标注:
- 规则是"每帧只要有变化就要选标签"
- 切镜头 OK(画面明显切换很清晰)
- 但 **S 型移动镜头**(上移 → 偏左摇 → 又右摇)→ 没摄影经验的同学懵了
- 本来该选 10 个标签,最后只选了 4 个
- 排查原因要么自己理解错,要么文档 case 画得不清楚

> 启示:复杂规则必须配 case 图示,文字描述远远不够。

### 1.3 单轮规则维度优先级(必背)

```
安全维度 → 指令遵循 → 内容维度 → 语言维度
```

被问"项目规则维度有哪些"时按这个顺序展开讲。

### 1.4 多轮 vs 单轮的关键差异

| 维度        | 多轮特有                             |
| --------- | -------------------------------- |
| **指代理解**  | 第一轮说"你是刘亦菲",后面用"她/他"模型必须知道 = 刘亦菲 |
| **上下文一致** | 上面给了约束,下面要遵循,不能模糊或答非所问           |
| **重复摘抄**  | 后面轮次跟前面 30-40% 内容重复 → 不通过        |

> 多轮规则 = 单轮规则 + 多轮特有规则,不是替换关系。

## 二、Reward Model 项目深度补充

> 早上已经讲过基本概念,下午老师又补了几个细节。

### 2.1 数据结构回顾

```
1 个 prompt → N 个不同模型生成的 response → 三人盲标排序
```

### 2.2 排序方法:两两对比

5-10 条数据**直接看排序根本看不下来**(字太多,看到第 3 条就忘了第 1 条)。

**正确做法:擂台赛**
- R1 vs R2 → 胜者出列
- R3 vs R4 → 胜者出列
- 胜者继续 PK,直到选出"从空到拉"的完整顺序

### 2.3 三人盲标:为什么必须是 3?

| 人数 | 问题 |
|---|---|
| 1 人 | 主观性太强 |
| 2 人 | 意见不合就打架 |
| **3 人** | **最平衡,降低主观性** |
| 5 人 | 浪费人力 |

### 2.4 不一致怎么处理

| 情况 | 处理 |
|---|---|
| 3 人不一致 | 重标,标到一致为止 |
| 一直不达标 | 找专家 / 丢项目群 @ 老师答疑 |
| **关键铁律** | **留痕!"是他告诉我的" = 锅不在我** |

⚠️ 不要在不熟悉的领域瞎答。

### 2.5 规则的优先级排序

前三位**固定**:
```
响应需求 > 事实正确 > 基础质量
```

后面的按"满足 N 个维度"分级排序 → 提升效率。

## 三、CoT(思维链)项目

### 3.1 引子:为什么需要 CoT

#### Strawberry 几个 R 的坑
早期 DeepSeek / 千问不开联网、不开推理时:
- 问"strawberry 有几个 R" → 模型答 2 个
- 原因:**分词把连续的 RR 当作一个 token**
- 这就是经典的"卡板"

#### 9.11 vs 9.9 哪个大
- 模型会拆成 "9.11" → 9 和 11,"9.9" → 9 和 9
- 然后比较 11 和 9 → 得出 9.11 大
- 模型其实不蠢,**是分词出问题**

### 3.2 慢思考 vs 快思考

| 类型 | 特点 | 例子 |
|---|---|---|
| **快思考** | 肌肉记忆,直接答 | "你今年几岁?" |
| **慢思考** | 一步步逻辑推理 | "187 × 345 = ?" |

CoT 就是让模型模仿人类做慢思考。

### 3.3 CoT 是什么

- **C**hain **O**f **T**hought 思维链
- 在问答之间插入中间推理步骤
- 模仿人类解决复杂问题时的思考过程
- ⭐ **不需要改变模型底层参数,用 prompt 就能实现**

### 3.4 CoT 三种实现方式对比

| 方式            | 实现                      | 优势     | 劣势        |
| ------------- | ----------------------- | ------ | --------- |
| **Prompt 工程** | query 后加"请一步步思考"        | 灵活、低成本 | 没经过训练,效果差 |
| **SFT**       | 投喂大量带思维链的高质量数据          | 效果强    | 成本高,需大量标注 |
| **强化学习**      | 训练 Reward Model 学习思维链规律 | 效果最强   | 训练复杂      |

### 3.5 CoT 历史时间线(吹牛素材)

| 时间 | 事件 |
|---|---|
| **2022 年 1 月** | 谷歌团队最早提出 CoT(只是论文,没产品落地) |
| **2024 年 9 月** | OpenAI 发布 o1 → **第一个落地的产品**(化学物理博士生水平) |
| | ⚠️ 但 OpenAI **没公开技术**(小气) |
| **2025 年 1 月** | DeepSeek R1 发布 → **国产之光** |
| | 公开 CoT 技术 + 让用户能看到思维链过程 |

> **面试吹牛话术**:"我们公司 24 年 12 月就用了 CoT,在 DeepSeek 公开之前就国产之光了。"
> 老师原话:"面试官也不知道真假。"

### 3.6 CoT 优势

- **提升答案准确率**(尤其复杂任务)
- **增加用户信任感**:就算最后错了,看到思考过程也觉得"起码他思考了"
  - 老师比喻:像求人办事,看到对方在打电话/找关系/试一下,你心就放下一半
- **便于纠错改进**:错在第几步可以定位,后续可以针对性改写

### 3.7 CoT 劣势

- **依赖高质量数据**(数据烂 → 学不到位)
- **消耗大量 token**(整个思考过程 20-30 行都算上下文,都算钱)
  - 老师吐槽:"花更多钱才能用我的好技术"
- **适用范围受限**:简单任务(西红柿炒鸡蛋)用 CoT 就是浪费

> 现在大模型都内嵌 CoT,**给用户开关选择**(Deep Thinking 开/关)
> 重要任务才开,日常对话不开。

### 3.8 CoT 三种 Prompt 模式

#### 零样本(Zero-shot)
```
"请你一步步思考再回答这个问题"
"请详细介绍解题思路"
```
直接在 query 后加约束句。

#### 少样本(Few-shot)
```
Q1: happy 中有几个 P?
思考:HAPPY → H,A,P,P,Y → 数 P 的个数 = 2
A1: 2 个

Q2: success 中有几个 S?
[模型参考上面格式回答]
```

#### 自动(Auto-CoT)
让模型通过自身能力完成推理,有点像强化学习的雏形。

```

    1. 给示例让 prompt 按示例生成
    2. 收集其他模型的优质回答 → 人工标注改写

  ↓
RL-2:第二轮强化学习(Pro → Max)
  ↓
最终 R1 模型
```

- ✅ 两个 SFT 阶段(筛选数据,不改写)

## 五、CoT 项目标注流程实操

### 5.1 数据结构

```
prompt + 自家模型(think + response) + 竞品模型(think + response)
```

### 5.2 标注 5 步法

| 步骤 | 动作 |
|---|---|
| 1 | 判断 prompt 是否需要舍弃 |
| 2 | 结合 prompt 判断目标模型 think 质量 |
| 3 | 改写目标模型 think(可参考竞品) |
| 4 | 结合 prompt + think + 竞品 response 判断目标 response 质量 |
| 5 | 改写 response |

#### 哪些 prompt 直接舍弃?
- 文创类(诗歌创作)→ 没推理过程
- 专业知识看不懂的
- 无法确认答案的
- 安全类敏感的

### 5.3 改写小诀窍

如果竞品 think/response **比自家好 80% 以上**:
```
Ctrl+A → Ctrl+C → Ctrl+V
直接拿过来用,合理合规
```

### 5.4 think 质量评估的 5 个维度

| 维度 | 含义 |
|---|---|
| **需求理解充分准确** | 指令遵循的换皮 |
| **推理完善** | 完整,没跳步骤 |
| **推理逻辑合理性** | 没有左走右走的无效思考 |
| **信息获取量高** | 无大量重复 |
| **惊喜** | 有效反思 vs 无效反思 |

### 5.5 有效反思 vs 无效反思

**判断核心两点**:
1. 是否有不合理的重复
2. 结论是否正确

**例子对比**:

❌ **无效反思**:
> "中国普洱茶高点茶...中国普洱茶高点茶..."
> (重复 3-4 遍同一个意思,消耗 token 但没新信息)

✅ **有效反思**:
> 有总分总结构,最后给出简洁结论
> 有同理心(被甩了的安抚而非"挺好的")

## 六、CoT 课堂实战:鱼缸玻璃问题

**题目**:长 1.3m × 宽 0.5m × 高 0.7m 无盖鱼缸需要多少平方分米玻璃?

**实操过程**:

### Step 1:判断 prompt
✅ prompt 没问题,通过。

### Step 2:对比两个 think
- 两个 think 都有问题:**重复 + 自我否定**("可能两种方法都对,我可能这样,可能那样")
- 选第一个相对好的择优

### Step 3:改写 think
错误特征:
- 大量重复
- 表达性冗余
- 验证太多遍(已得到 317 还要再算两遍)
- 自我怀疑句子("我觉得", "应该没错吧")

改写策略:
- 删掉验证 2 遍以上的部分
- 只保留到 317 平方分米的结论
- 或者用另一种简洁推理

### Step 4-5:对比 response 并改写
错误特征:
- response 用了 `**` 当标题(Markdown 错误,应该用 `#`)
- 长高宽前应该用有序列表,不该用横杠 `-`

改写后:
```markdown
## 解题过程
### 步骤一:计算各面面积
1. 长 × 宽 = ...
2. 长 × 高 = ...
...
```

### 5 步法的最终输出表格字段

老师让大家在表格里标:
- 优秀的 think 选择(一/二)
- think 改写的原因(大量重复、表达冗余等)
- 优质的 response 选择
- response 改写的原因(格式错误、标题语法等)

## 八、Agent 项目

### 8.1 Agent 是什么

> 大模型 + 工具调用 = Agent
> 一句话:**野生小秘书**,整合规划、记忆、工具调用等能力的下一代智能系统。

定位转变:**从"回答问题"变成"解决问题"**。

### 8.2 Agent 三大核心组件

```
Agent = 大脑(大语言模型) + 三个能力
         ├── 规划 Planning
         ├── 记忆 Memory  
         └── 工具 Tools
```

### 8.3 规划 Planning 三步

| 步骤 | 含义 |
|---|---|
| **任务分解** | Cursor 的 Todo List 模式(完成一步打一勾) |
| **思维链(CoT)** | 推理过程 |
| **自我反思** | 评估过往内容是否正确,自我纠错 |

进阶:**ReAct 框架** = 思考 → 行动 → 观察 → 执行 闭环

### 8.4 记忆 Memory:长期 + 短期

| 类型 | 含义 | 例子 |
|---|---|---|
| **短期记忆** | 上下文 | 这一轮对话内的信息 |
| **长期记忆** | 持久化的用户偏好 / 知识库 | 点星巴克自动选你之前点过的食材 / 你说过"我喜欢极简风格",下次装修建议自动倾向极简 |

### 8.5 工具 Tools

你手机里所有 APP 都是工具。

**订机票流程举例**:
```
时间工具(填日期) 
  → 地址工具(出发地/目的地)
  → 信息工具(身份证)
  → 支付工具(微信/支付宝)
```

Agent 帮你串起这些调用。

### 8.6 训练师在 Agent 里负责什么

| 部分 | 训练师介入? |
|---|---|
| 规划 Planning | ✅ 训练师做(思考逻辑、思维链、工具调用顺序) |
| 记忆 Memory | ❌ 算法做(向量数据库) |
| 工具 Tools | ✅ 训练师做(工具调用是否正确) |

### 8.7 Agent 数据结构(会议室助手案例)

```json
{
  "user_prompt": "下次这个时候有项目汇报,帮我看会议室空着没",
  "agent": {
    "think": "用户没给具体时间...需要先调时间工具",
    "action": { "tool": "调取时间", "params": {...} }
  }
}
```

每条数据 = **思考 + 行动**两段交替。

### 8.8 Agent 项目背景里的两个固定字段

#### 角色定义
> "你是小谈,会议室助手"

每个 Agent 都是**专项的、单一的**:
- 让会议室助手做旅游 → 不行
- 让会议室助手做西红柿炒鸡蛋 → 不行
- 每个 Agent 一个职能

#### 标准运行规则
比如会议室助手的两条规则:
1. **预定时间提醒**:用户预定时间 < 当前时间 → 提示"已过期,无法预定"
2. **避免重复调用**:已调用过的工具(如时间工具)直接复用,不重复调用

## 九、Agent 课堂实战:会议室预定改写

### 9.1 经典错误

用户说:"下次这个时候做项目汇报,帮我看会议室"

Agent 思考(错误版):
> "用户没指定会议时长,**我将默认设置为 1 小时**" ❌

⚠️ 这违反了 Agent 规则文档里的"信息真实性" —— 信息只能来自行为日志,不能擅自构造。

### 9.2 正确流程

| 步骤 | 行动 |
|---|---|
| 1 | 调取当前时间工具 → 4月1号 9点 |
| 2 | 推算下周时间 → 4月8号 |
| 3 | **调用询问工具问用户:"你需要预定多久?"** |
| 4 | 用户回:"1 小时" |
| 5 | 调取空闲会议室工具 → 拿到列表 |
| 6 | **再次询问用户**:"有 101/103/105 等空闲,你要哪个?" |
| 7 | 用户:"101" |
| 8 | 调用预定工具完成 |

⚠️ **核心原则**:不能擅自做主默认任何用户没说的信息,必须用询问工具问回去。

### 9.3 Agent 标注规则

| 标注 | 含义 |
|---|---|
| **通过(1)** | 思维链 + 行动都正确 |
| **不通过 + 改写(0)** | 思维链 40-50% 出错 / 工具调用错 |
| **舍弃** | 思考 40-50 轮、改写难度过大 |

⚠️ 不要动不动就跳过。一般规则是错 60-70% 以上才能跳过,否则人均跳一半,数据量交付不够要重做。

### 9.4 改写 Prompt 时的细节

**改写后必须立即在下一行补充对应的行动**:
```
改写后 think:"我应该询问用户的会议时长"
↓
新增一行 action:调用询问工具,询问"张敏,您预定的会议室使用时长是多久?"
```

### 9.5 用户 prompt 模糊的处理

老师举例:"我要从目前的城市去上海玩三天两晚"
- 模糊点:**没说目前是哪个城市**
- 处理:加一列"改写后 query"或"意图澄清"
- 改写要保持上下文逻辑通顺

### 9.6 JSON 格式检查

改完之后必须做 JSON 格式验证:
1. 复制改后的代码段
2. 粘贴到在线 JSON 验证器
3. **绿色 = 没问题,红色 = 有错**(标红会告诉你哪个位置错)
4. 比如少一个逗号、多一个引号都会被发现

## 十、RAG(检索增强生成)项目

### 10.1 RAG 是什么

> **R**etrieval **A**ugmented **G**eneration —— 给大模型外挂专门的知识库

让模型"查资料",查出来的资料更准、更新、更贴合用户需求。

### 10.2 两种 RAG

| 类型         | 数据来源  | 用途               |
| ---------- | ----- | ---------------- |
| **在线 RAG** | 联网搜索  | 时效性强(今天的新闻)      |
| **离线 RAG** | 本地知识库 | 私有化数据(车企售后/医疗指南) |

### 10.3 为什么要做 RAG?(四大原因)

#### 原因 1:部分解决幻觉
幻觉来源回顾:
- 训练数据错误
- **训练数据缺失** ← RAG 解决这部分
- Token 预测出错

#### 原因 2:专业领域数据
- 广汽、上汽、奔驰各家销售政策都不同
- 通用模型查不到这些私有数据
- 必须本地部署 RAG 知识库

#### 原因 3:时效性问题
- 模型有训练截止时间(R1 截止 2024 年 10 月)
- 今天的新闻它查不到
- 在线 RAG 解决

#### 原因 4:可解释性 / 溯源
- 开了联网后,回答带角标
- 点角标 → 跳转到原网页
- 可以验证是不是百度贴吧 / 三无网站 / 赌博广告
- 来源是知网 / 官网 / 法条 → 可信度高
- **本质上模型是黑盒,RAG 让我们能溯源**

### 10.4 RAG 完整流程(必懂)

```
准备阶段(离线):
公司文档(Word/PDF/Excel/PPT) 
  ↓
切分 chunks(按段落/语义/章节/字数)
  ↓
Embedding 模型转成向量(数组形式)
  ↓
存入向量数据库

查询阶段(用户提问):
用户 query 
  ↓ 转成向量
在向量数据库里找最相似的 N 个 chunk(top-k)
  ↓ 召回
query + chunks 拼成"增强 prompt"
  ↓
喂给大模型生成最终回答
```

### 10.5 切分(Chunking)的坑

文档 1 万字怎么切?

| 切分方式 | 说明 |
|---|---|
| 按段落 | 文档常用 |
| 按语义 | 保持上下文一致 |
| 按章节 | 长文档常用 |
| 按字数(每 500/1000) | ⚠️ **可能把一个完整故事切断** |

切错 → 召回时拿不全 → 答案不准。

### 10.6 Embedding 模型干什么

把人类语言**转成模型能看懂的数组**:
- 苹果 → [0.1, 2.1, 3.1, 4.05]
- 香蕉 → [5.6, 1.2, 0.3, 2.8]
- 距离越近 = 越相似

> 老师比喻:就像描述苹果有什么特征,把所有特征用数字表示成一个高维空间的点。新苹果出现 → 找到距离最近的点 → 它就是苹果。

### 10.7 Top-K 是什么

| 设置 | 召回数量 |
|---|---|
| top-k=3 | 召回最相关的 3 个 chunk |
| top-k=10 | 召回 10 个 |

这是检索阶段的关键参数,由算法/运营定。

### 10.8 RAG 数据结构

```json
{
  "prompt": "美国独立日为何要使用唐朝开国大年主题防爆胎",
  "references": [
    "材料一:狼人杀作者是 Andrew",
    "材料二:狼人杀作者是 David",
    "材料三:..."
  ],
  "response": "..."
}
```

### 10.9 RAG 数据问题排查(三个维度)

#### 维度 1:Prompt 有问题
- 难以理解(逻辑不通)
- 历史对话上下文严重错误
- 涉黄涉政有害

老师课堂例子:
> "小明在 33 年前出生,今年 2 岁。小王的爸爸比小王大..."
> → 难以理解,跳过

#### 维度 2:参考材料有问题
- **不相关**:问奥迪给你奔驰资料
- **不准确**:事实性错误
- **不全面**:截断了
- **材料相互冲突**:狼人杀作者材料一说 Andrew,材料二说 David
- **常识性错误**

#### 维度 3:回答质量
- 语病、标点错误、逻辑不通
- 意图理解错
- 价值观问题(违法反社会)
- 格式不美观(没分段、没序号)

### 10.10 RAG 标注方案

| 处理 | 含义 |
|---|---|
| **通过** | 采纳 1/2/3 中某个回答(完美无瑕) |
| **不通过 + 改写** | 三个回答都不合格 → 矮子里挑高个 |
| **跳过** | 对话不可用 / 材料不可用 / 改写成本太高 |

⚠️ 老师强调:**不能轻易跳过**。
> 一共就 100 条,大家平摊下来一人才 50 条。一半跳过 = 交付量不够 = 重做。
> 一般规则是错 60-70% 以上才能跳过。

### 10.11 标注策略小技巧

#### 多模型生成对比
让其他模型(GPT、Claude、豆包)生成同 query+材料的回答 → 哪个最优用哪个。

#### 改写策略
- **三个回答融合**:把三个里对的部分拼起来
- **里面找对的**:1000 字里有 600 字对,把对的部分留下
- **完全自己写**:难度高、人少做、不推荐

### 10.12 课堂插曲:RAG 同时调用在线+离线?

有同学提了个好问题:同时调用两个数据库会不会冲突?

**老师答案**:
- 可以同时调
- 模型自己组合 6 个 chunk(3 个在线 + 3 个离线)
- 一起喂给大模型,模型自己挑最相关的(向量距离最近的)
- 不需要用户手动选

### 10.13 训练师在 RAG 里负责什么

| 阶段 | 训练师做什么 |
|---|---|
| 数据准备 | 看怎么切分(策略由算法/运营定) |
| 构建高质量数据集 | 把 100 字的冗余精简到 20 字 |
| 生成阶段 | 评估最终生成质量 |

### 10.14 ⚠️ 面试雷区

老师强调:**千万别说"RAG 是我搭建的"**。

这只是最基础流程,深处的检索策略 / Embedding 选型 / 向量数据库 / 召回算法非常复杂。

✅ **正确说法**:"我做过 RAG 项目"(参与了切分/数据/生成评估部分)

### 10.15 RAG + Agent 一般组合用

完整链路:
```
用户 query 
  ↓
意图识别(Agent 路由)
  ↓
路由分发("我吃饭"往左,"我游泳"往右)
  ↓
进入对应 RAG 知识库(售后/政策/产品)
  ↓
模型生成回答
```

### 12.2 各站做不出来的解决方法

同学痛点:复制了好看网站发给 Claude,但生成不出来。

**老师解释**:
- Claude 没办法识别截图
- 必须把**实际代码**复制给 IDE / Cursor / Trae
- 网页 → F12 开发者模式 → 把动效代码扒出来 → 喂给 AI

**操作流程**:
1. 找到喜欢的动效(网上搜)
2. 浏览器开发者模式 → 复制代码
3. 让 Claude 把动效作为**背景层**(z-index 低)
4. 文字内容作为**上层图层**(z-index 高)
5. 这样动效不挡字,字也有动感背景
