## 一、上节课回顾

老师上来就抽人提问巩固上周内容,要点:

**AI 训练师团队架构**:产品经理 / 算法 → AI 训练师 → 数据标注员

**AI 训练师工作流(四步)**:
1. 承接需求
2. 撰写规则文档
3. 标注全流程管理(规则下发 → 培训 → 试标 → 正式标注 → 质检 → 验收 → 交付)
4. 数据复盘

### 1.1 项目需求维度详解(5W2H)

⚠️ 面试时**不能脱口而出"5W2H"**(对方可能没听过这词),要把每个维度自然地一步步问出来。

**5W2H 不是 AI 行业的方法论**,它是 1932 年美国陆军军械兵团提出的通用项目分析框架,后来被广泛用在管理学、产品经理需求拆解里。核心价值:**用一套结构化提问把模糊需求挤干净,逼出所有隐藏前提**。

#### ① What — 项目目标

**核心问题**:这个项目到底要训什么模型,要解决什么问题?

子问题:
- 训的是哪个模型?(基础模型 / 垂类模型 / 多模态)
- 处于训练的哪个阶段?(预训练 / SFT / RLHF / CoT)
- 项目类型是什么?(单轮 / 多轮 / RM / Agent / RAG)
- 数据形态?(纯文本 / 图文 / 视频 / 音频)
- **数据量多少**?
- **准确率要求**多高?(决定质检策略)

⚠️ 典型坑:需求方扔来"帮我做下数据清洗",你不问 → 等开干才发现是 5 万条 6 层嵌套的图片,全程返工。

#### ② Why — 为什么要做

**核心问题**:为什么要训这批数据?希望模型产生什么效果?

子问题:
- 现在模型有什么问题?(幻觉?指令遵循差?某垂类不行?)
- 衡量成功的指标是什么?(badcase 率下降?某个 benchmark 提升?)
- 这批数据补哪块短板?(安全 / 创造性 / 专业度?)

**为什么这步关键**:Why 决定了**规则文档的优先级排序**。修"乱拒答" → 指令遵循维度要细;修"涉政漏标" → 安全维度要堆 case;修"答案敷衍" → 价值丰富度要加权重。

#### ③ Where — 作业方式 / 平台

**核心问题**:用什么平台、什么形态作业?

子问题:
- **线上还是线下**?(线上 = 标注平台:阿里 AIDP、字节魔兜、智谱狂飙;线下 = Excel / 飞书表格)
- 平台有没有现成功能支持?(打分 / 排序 / 改写 / 多轮编辑)
- 没有就要**提需求做平台改造**,这是额外排期

#### ④ When — 时间节点

**核心问题**:什么时候交?中间有没有里程碑?

子问题:
- **最终交付 deadline**?
- 中间节点交付?(比如先交 1000 条试水)
- 试标周期多长?
- 培训 + 试标 + 正式 + 质检 + 验收各阶段排期?
- 节假日 / 突发事件影响人力?

**反推逻辑**:
```
交付日 - 验收 - 质检 - 标注 - 试标 - 培训 - 文档撰写 = 你今天必须开始的最晚时间
```

#### ⑤ Who — 涉及人员

**核心问题**:跟哪些人有关系?

- **需求方**几人?谁是最终决策者?(避免 A 说改 B 说不改)
- **承接方**几个 AI 训练师?谁主负责?
- **标注人员**多少?(内部 / BPO / 众包 / 标注基地)
- 需要哪些**专业背景**?(医疗项目要医学生,法律项目要法学生)
- 质检谁做?互检机制?

#### ⑥ How — 怎么做 / 实施方式

**核心问题**:具体怎么落地?

- 有没有**现成规则文档**或参考?
- 有没有**示例数据**?(good case + bad case)
- 有没有**已知卡点**?(某类 prompt 大家一直标不准)
- 标注方案?(打分 / 排序 / 改写 / 选优 / 组合)
- 试标策略?(内部小范围 / 拉需求方一起)
- **质检比例**:10%-30%(根据项目而定)

⚠️ **试标不通过**:可以给一次机会,再不通过就释放掉这个人力。在阿里一般只一轮试标。
⚠️ **回扫**:阿里把"打回"叫"回扫" —— 错一两道帮改;错 50% 以上直接打回让人重做。

#### ⑦ How much — 资源 / 成本

**核心问题**:这事儿要花多少钱?

- **预算多少**?(走公司账,需要前置预估)
- 标注员人天单价?(BPO / 众包不同价)
- 平台资源占用费?
- 外采数据成本?
- ROI 怎么估?

⚠️ AI 训练师容易忽略 How much,觉得"花钱不归我管"。**预算超支会被回溯责任**,而且懂成本的训练师面试时直接拉开差距。

### 1.2 沟通必须留痕

每次需求承接完,**当场或当天**做一个表单,丢项目群 @ 需求方确认:

| 项 | 内容 |
|---|---|
| 项目名称 | XXX 单轮问答 SFT 数据 |
| 数据量 | 10000 条原始 / 预估 7000 条有效 |
| 数据类型 | 中文文本 |
| 准确率要求 | 95% |
| 交付 deadline | 2026-06-30 |
| 中间节点 | 6-15 交 30% 试水 |
| 标注平台 | AIDP |
| 标注方案 | 改写 + 通过/不通过 + 舍弃 |
| 质检比例 | 20% |
| 投入人力 | 12 标注员 + 2 质检 + 1 训练师 |
| 预算 | XX 万 |
| 备注 | XX |

**职场关键铁律:沟通留痕、结果留痕、量化留痕**

工具不重要(飞书表单 / 问卷星 / Excel 都行),关键是**有书面记录 + 需求方确认**。这套 SOP 模板本身就是"提效赋能"的产出,面试可以讲。

| 层级      | 内容                      | 学完能干什么      |
| ------- | ----------------------- | ----------- |
| **基础层** | 预训练 + 后训练               | 弄清大语言模型怎么训练 |

**今日核心两个学习目标**:
1. 模型是怎么训练的?

### 3.1 全景图:训练阶段 vs 项目类型 vs 增强应用(必看)

⚠️ 这是后面所有内容的总骨架。课程里出现的术语很多,容易混在一起,先按"层"分清:

```
┌─────────────────────────────────────────────────┐
│            基础层(模型本身的训练)              │
├─────────────────────────────────────────────────┤
│                                                  │
│  ① 预训练(Pre-training)                       │
│     海量互联网数据 + 无监督学习                  │
│     → 产出 Base Model                            │
│         ↓                                        │
│  ② 后训练(Post-training)                      │
│     ├── SFT(有监督微调)                        │
│     │   投喂高质量"问—答"标注数据               │
│     │                                            │
│     └── RLHF(基于人类反馈的强化学习)           │
│         a. 训练 Reward Model                     │
│         b. 用 RM 给主模型打分,做强化学习        │
│                                                  │
└─────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────┐
│      增强层(模型已训练完,推理时加挂)         │
├─────────────────────────────────────────────────┤
│  • RAG(检索增强生成)                          │
│  • Agent(工具调用)                             │
│  • CoT(思维链 prompt)                          │
│  → 不改模型参数,只是"外挂"                     │
└─────────────────────────────────────────────────┘
```

**关键认知 — 训练师工作的对位**:

| 概念 | 所属阶段 | 性质 |
|---|---|---|
| **单轮问答** | 后训练 → SFT | SFT 项目子类型 |
| **多轮问答** | 后训练 → SFT | SFT 项目子类型 |
| **RM 排序训练** | 后训练 → RLHF Step 1 | 训独立小模型 |
| **CoT 标注项目** | 后训练 → SFT | 教模型推理 |
| **Agent 标注项目** | 后训练 → SFT | 教模型用工具 |
| **RAG 标注项目** | 后训练 → SFT | 教模型用材料 |
| **RAG / Agent / CoT 系统** | 增强层 | 推理时加挂,不参与训练 |

**所有 SFT 项目本质相同**:都是给"prompt → response"对子,让模型学某种回答模式。区别只在数据结构里多了什么(对话历史 / 思考过程 / 工具调用 / 检索材料)。

⚠️ **常见误区**:笔记里把 SFT、RLHF、CoT、Agent、RAG 章节并列,看起来像 5 个并列阶段 —— **错**。RAG / Agent / CoT 各有"训练时项目"和"推理时系统"两面,AI 训练师做的几乎都是前者。

## 四、基础层 · 预训练(Pre-training)

### 4.1 定义
通过海量数据训练模型,让模型学会预测 TOKEN 序列,最终产物叫 **Base Model(基础模型)**。

预训练的革命性意义在于:让模型从文本的自然结构中**自主学习,无需外部监督**。所以也叫 **无监督学习**。

> 比喻:像把一个小孩丢到图书馆里自己看书。学完会变学霸(脑子里墨水很多),但说不出来 —— 阿巴阿巴,不会表达。

### 4.2 五个必背陌生词

老师让在飞书里建一个"模型陌生词汇表"sheet,持续往里填:

#### 涌现(Emergence)
- **模型训练三要素**:数据、算力、算法(必背)
- 不停堆叠三要素,模型能力会持续上升
- **质变点不可预测**:某天突然从 A 等级跳到 B 等级 —— 像武侠小说"打开任督二脉"
- 案例:ChatGPT3(2020 年 175B,只有上下文学习)→ ChatGPT4(1T+,多模态 + 高阶推理)
- **涌现的临界点和参数量强相关**:上下文学习 ~10B、思维链 ~30B、Agent 能力 ~70B 才稳定显现

#### 参数(Parameters)— 详细展开

**白话理解**:模型脑子里"长在身上"的所有知识、技能、直觉和经验 —— 一旦训练好就固定了,推理时只读不写。

⚠️ 旧笔记说"参数 = 内存"是误导 —— 模型推理时的"工作内存"是 KV Cache,不是参数。**参数 = 长期记忆 + 技能**,KV Cache = 短期记忆 / 当前对话上下文。

**参数量决定哪些能力**:

| 能力 | 关系 |
|---|---|
| **知识广度** | 越大装得越多。1B 装常识,7B 覆盖通识,70B+ 进入专家级,1T+ 百科全书级 |
| **推理能力** | 临界点效应。< 3B 极差,7B 一般,14B 中等,32-70B 较强,100B+ 真正强 |
| **指令遵循** | < 1B 经常答非所问,7B 能听懂大部分,14B+ 能执行复杂多约束指令 |
| **长上下文理解** | 7B 8K 就吃力,14-32B 能用 32K,70B+ 能稳定处理 128K+ |
| **多语言** | 7B 通常只在 1-2 种主流语言上好,70B+ 才能在 30+ 种语言可用 |
| **代码 / 数学** | 对参数量极敏感 —— 7B 写简单脚本可以,中等复杂度就开始幻觉 |

**参数量决定的"代价"**:

| 代价 | 关系 |
|---|---|
| **显存占用** | ≈ 参数量(B) × 精度系数。FP16 ×2,INT8 ×1,INT4 ×0.5 |
| **推理速度** | 参数翻倍速度大概减半(显存带宽决定上限) |
| **训练成本** | ≈ 参数量的平方级关系,不是线性 |
| **首字延迟** | 7B ~0.5 秒,70B 1-3 秒,千亿级 3-10 秒 |
| **部署难度** | 7-14B 单卡能跑,32B+ 要专业卡,100B+ 基本只能上云 |

**档次划分(2026 年)**:

| 档次 | 参数量 | 代表 |
|---|---|---|
| 超轻量 | < 1B | Phi-3-mini、Qwen3-0.6B |
| 轻量 | 1-4B | Qwen3-4B、Llama 3.2-3B |
| 小钢炮 | 7-8B | Qwen3-8B、Llama 3.1-8B |
| 主力 | 13-14B | Qwen3-14B |
| 专业 | 30-32B | Qwen3-32B |
| 旗舰 | 70-100B | Llama 3.1-70B |
| 前沿 | 200B-1T+ | DeepSeek V3、Claude、GPT-5 |
| 超大稀疏 MoE | 万亿级 | Qwen3-235B-A22B |

**几个反常识**:
- **参数 ≠ 性能** —— 一个 7B 的 2026 模型 ≈ 30B 的 2022 模型,数据质量比参数更重要
- **MoE 模型要分两个数字看**:总参数(看能力)+ 激活参数(看速度)。Qwen3-235B-A22B = 总 235B,每次只激活 22B
- **7B SFT 微调在特定任务上能打 70B 通用版** —— 这就是为什么后训练是 AI 训练师主战场

#### Scaling Law(缩放定律 / 扩展法则)

⚠️ **旧笔记勘误**:此前写作"Scaling Law(死性)" —— "死性"是录音转写错误。标准译法是**缩放定律 / 扩展法则 / 规模法则**,业内也常直接说英文。

**核心含义**:模型性能与「参数量 × 数据量 × 算力」之间存在**可预测的幂律关系**。训练前能预估能拿到什么水平的模型。

**关键现象 — 边际效应**:
- 7B → 14B 提升明显
- 14B → 32B 提升较大
- 32B → 70B 提升变小
- 70B → 175B 提升相对有限
- 175B → 1T 提升非常有限,但成本爆炸

所以公司内部不会只训一个模型 —— 豆包 2.0 可能内测了 10 个 2.0 版本,选最好的发布。

**为什么会有边际效应?**(六大根因,面试加分)

1. **数据见顶** —— 互联网高质量文本就那么多(~15T tokens),前沿模型已经吃完了。参数翻倍但没新数据可学。
2. **Chinchilla 定律** —— 参数量 × 20 = 最优训练 tokens。数据跟不上,多出来的参数就是闲置脑容量。
3. **知识幂律分布** —— 高频知识小模型就学完了,大模型多学的都是用不到的长尾。
4. **Transformer 架构上限** —— 注意力 O(n²)、token 预测本质局限,堆参数撞不破架构天花板。
5. **经济不划算** —— 训练成本是参数量的超线性增长,回报却近似线性。
6. **评估饱和** —— 现有 benchmark 接近满分,看不出新模型的提升。

**结果**:各家公司开始转向后训练(SFT/RL)、MoE 架构、多模态等"非预训练堆料"路线。

#### 幻觉(Hallucination)— 详细展开

**三个产生原因**:

##### 原因 1:训练数据本身错误
好坏数据都投喂,模型不分对错全学,生成时也会一起吐出来("吃什么拉什么")。

##### 原因 2:训练数据缺失 → 模型硬编

模型本质是**概率机器,没有"我不知道"这个 token**。被问到没学过的内容时,它依然会从概率分布里采样,挑"听起来最像答案"的字往外吐。

**底层机制**:
- 训练目标里**根本没有"不知道"这个选项** —— 互联网上几乎没有人在文章里写"这个我不知道"
- 概率分布**永远不会是 0** —— softmax 会给所有 token 分配非零概率,模型一定会采样出一个
- SFT/RLHF 早期标注甚至**惩罚过"诚实拒答"** —— 把硬编反向训练成了模型的本能

**典型表现**:
- **张冠李戴**(最常见):林黛玉倒拔垂杨柳(鲁智深的事迹串过来)
- **合理推测式编造**:问"《XX 法》第 X 条" → 按法条格式编一段(最危险,因为人难以一眼识别)
- **自信加细节**:编一个不存在的人,附上生卒年、出生地、代表作
- **前后矛盾**:同一回答里前后说法不一致

##### 原因 3:Token 预测出错 → 错误链式传播

模型是"一个字一个字往外挤"的(自回归生成),前面已生成的 token 会被当作既定事实喂回模型。

**只要中间某一步采样错了,后面会基于错的 token 继续推**,无法回头改。

**经典案例(数学题)**:
```
"23 × 47 = ?"
Step 2: "= 23×50 - 23×3"  ✓
Step 3: "= 1150 - 69"     ✓
Step 4: "= 1080"          ✗ 错了!应该是 1081
Step 5: "× 2 = 2160"      ← 把错的 1080 当对的继续用
```

**链条越长翻车概率越高**:99% 准确率的模型生成 100 个 token,全对概率只剩 36.6%。

**为什么模型不能"回头改"**:
- Transformer decoder 只能从左往右生成,**生成第 N 个 token 时无法修改第 N-1 个**
- 模型不知道自己错了 —— 没有"重新计算"机制
- Temperature > 0 时有随机性,会增加采样错误概率

**业界对抗手段**:
- **CoT** —— 显式写出推理过程,出错可观测
- **自我反思** —— 生成后再读一遍检查
- **多次采样投票** —— 同题答 5 次,看哪个答案出现最多
- **工具调用** —— 关键步骤(算数 / 查事实)让模型调计算器 / 搜索引擎,不自己生成
- **RL 后训练** —— 用 RM 把"错链"打低分,模型学会避开高风险路径

**AI 训练师视角**:
- 数据错误 → SFT 阶段筛选优质数据
- 数据缺失 → 投喂"诚实拒答"的样本
- 链式传播 → CoT / 工具调用 / RL
- **训练师工作就是在标注里识别这三种幻觉,改写成正样本喂回模型**

> 经典案例:让模型介绍《孙悟空在打王者荣耀》这本书的作者、生平 —— 它会一本正经胡编。

### 4.3 预训练的 4 个步骤

| 步骤  | 内容                 | 训练师参与度            |
| --- | ------------------ | ----------------- |
| 1   | **数据收集与预处理**       | ✅ AI 训练师可能参与(占比小) |
| 2   | 分词(把人话分成模型能看懂的)    | ❌ 算法主导            |
| 3   | Transformer 神经网络训练 | ❌ 算法主导            |
| 4   | 推理与生成能力评估          | ❌ 算法主导            |

> AI 训练师在预训练阶段参与度只有 **10%-20%**,主要工作集中在后训练。

## 五、基础层 · 后训练(Post-training)

### 5.1 定义
在预训练完成后,通过额外的数据处理或模型优化,**进一步提升模型性能或适应性**。
- 核心目标:**弥补预训练时的不足/缺陷**
- 让模型从"通用型人才"变成"专项人才"
- 由 **算法 + AI 训练师共同完成**
- 必须在预训练之后

### 5.2 后训练两大阶段

```
后训练
├── SFT(有监督微调,Supervised Fine-Tuning)
│   ├── 单轮问答项目
│   ├── 多轮问答项目
│   ├── CoT 项目(教模型推理)
│   ├── Agent 项目(教模型用工具)
│   └── RAG 项目(教模型用材料)
│
└── RLHF(基于人类反馈的强化学习)
    ├── Reward Model 训练 ← Step 1
    └── 强化学习主流程    ← Step 2
```

> AI 训练师 80%-90% 的工作都在后训练阶段。

## 六、SFT 阶段:对话训练项目

### 6.1 SFT 定义
通过部分**优质的标注数据**精准微调,提升模型在各任务的表现能力,让 AI 学习人类特定对话任务的交流方式。

> 还是那个笑话案例:在 SFT 阶段构建数千上万条人类觉得好笑的笑话,投喂模型 → 模型从中找规律 → 学会人类喜欢什么样的笑话。

### 6.2 通用 vs 专项

- **通用模型**:豆包、Kimi、ChatGPT —— 啥都吃,数学语文物理游戏全吃
- **专项模型**:垂直领域 —— 医疗、金融、电商客服、汽车

> 例如训练电商客服模型,就在 SFT 阶段投喂售前、售中、售后的分类数据。

### 6.3 单轮问答项目

#### 案例:"4.5 磅是多少斤?"
- 答案 1:简单回答
- 答案 2(优质):详细换算 + 一磅多少克 + 一斤多少克 + 结构化、逻辑清晰
- ⚠️ 老师提议:**以后咱们能不能就不用豆包了?**(豆包经常单纯只回答简短答案)

#### 训练师工作内容
1. 撰写规则文档
2. 构建高质量数据
3. 把控标注过程质量

#### 数据来源(两种)
1. **算法给完整数据**(理想情况,但阿里这种"很畜生"的算法只给一部分)
2. **从 0-1 自己构建**:
   - 人工撰写
   - 从社区平台爬取(可灵社区、即梦社区、微图等)
   - 用 PE 让模型生成

#### 关于"低质量数据要不要看一遍"
**必须看**。
- 60 个人分一下,每人才十几条,根本不多
- 老师做 Happy House 短剧训练时,**"那几天是我最快乐的时光"**(把短剧拆 10-20 秒切片标镜头)
- ⚠️ 内部测试模型可能生成涉黄涉政内容,**有历史痕迹,尽量别试**

### 6.4 单轮问答的四大规则维度(梯度顺序)

```
安全维度 → 指令遵循维度 → 内容维度 → 语言维度
   ↓
(从重要到次要,逐级判断)
```

#### ① 安全维度(最重要)
| 子维度      | 含义            | 例子                 |
| -------- | ------------- | ------------------ |
| **涉政违法** | 政治敏感、法律法规、黄赌毒 | 违反国家法律的内容          |
| **价值观**  | 地域歧视、抹黑公众人物   | "长得帅的人能力都不行" → 不通过 |
| **风险规避** | 必须给免责提示       | 医疗→谨遵医嘱;金融→投资有风险   |

⚠️ **风险规避话术不能千篇一律** —— 早期模型每次都说"需谨遵医嘱"过于单一,现在要训练**多种话术变体**。这就涉及到 **过拟合 vs 欠拟合**。

#### 过拟合 vs 欠拟合(必懂)— 详细展开

**本质**:模型训练的目标是学**规律**,不是背**答案**。两个极端都会翻车。

| | 欠拟合 | 过拟合 |
|---|---|---|
| 通俗 | 大傻子,啥也没学到 | 书呆子,死记硬背 |
| 训练集表现 | 差 | 完美 |
| 新问题表现 | 差 | 也差 |
| 训练 Loss | 高,降不下来 | 极低,接近 0 |
| 验证 Loss | 高 | **先降后反弹**(关键信号) |

##### 欠拟合的具体表现

**表现 1:学完跟没学一样**

投喂了 10000 条"客服话术"数据,模型回答还跟原来一样。

```
训练前:用户问"我不满意你们的服务"
模型答:"非常抱歉给您带来不便,请告诉我具体问题。"

训练 10000 条客服数据后:同样的问题
模型答:"非常抱歉给您带来不便,请告诉我具体问题。"   ← 一模一样
```

**表现 2:答非所问 / 输出胡言**:模型完全没掌握任务模式
**表现 3:某些维度完全无视**:比如要求"医疗类必须加'谨遵医嘱'",但训练完模型大部分医疗问题还是不加 → 局部欠拟合(信号太弱)

**根因**:
- 模型容量不够 / 训练时间不够 / 数据量不够
- **数据质量太差(50% 标错)**
- 学习率不对 / 训练超参数不对

##### 过拟合的具体表现

**表现 1:风险规避话术千篇一律**(经典 case)
```
训练数据(每条都用相同话术):
Q: 我感冒了 / 头疼 / 心情不好(各种问题)
A: 建议谨遵医嘱,如有不适请及时就医。  ← 全都一样

(投喂 5000 条这样的数据)

训练完后:
Q: 我心情不好怎么办?
A: 建议谨遵医嘱,如有不适请及时就医。   ← 心情问题也整这套
```

模型学到的不是"医疗类要安全提示",而是**"什么问题都用这套话术"**。

**表现 2:换个问法就崩**
```
训练时:"4.5 磅是多少斤?"  → 完美

测试时:
"四点五磅等于几斤?"        → 乱答
"4.5 lb 是多少 jin?"      → 乱答
```
模型背的是字符串,不是规律。

**表现 3:复刻训练样本的小毛病**:训练数据里有 200 条都用了"哦~",训练完模型几乎每条都带"哦~"

**表现 4:跟原文一字不差**:最严重的过拟合 —— 模型把训练数据逐字背下来了

##### AI 训练师的两件武器(都是数据侧)

**抗欠拟合 → 提质 + 增强信号**

| 做法 | 例子 |
|---|---|
| 数据噪声清掉 | 标错的、模糊的全部剔除或修正 |
| 想训练的维度,样本足够多 + 处理一致 | 至少 200-300 条相关样本 |
| 宁可 500 精标,不要 5000 烂标 | 维基百科被读 3.4 遍就是这个道理 |
| 改写要彻底 | 留一半坏数据等于没改 |

**抗过拟合 → 提多样性**

| 做法 | 例子 |
|---|---|
| 同一意思 5 种问法 | "4.5 磅多少斤" → 加"四点五磅"、"4.5lb"、"四磅半"等变体 |
| 风险话术 10 种变体 | "谨遵医嘱" / "咨询专业医生" / "去医院检查"... |
| 难度梯度 | 50% 简单 + 30% 中等 + 20% 边缘 case |

##### 经典面试串讲

> "早期模型医疗问题千篇一律答'谨遵医嘱'是过拟合 —— 模型把'医疗→谨遵医嘱'当成了规律,而不是'医疗类要安全提示'这个抽象规律。修复方法是在 SFT 数据里加 5-10 种安全提示变体,让模型学抽象规律而不是具体话术。"

#### ② 指令遵循维度
| 子维度     | 含义                             |
| ------- | ------------------------------ |
| 完全不遵循指令 | 答非所问、驴唇不对马嘴                    |
| 部分指令遵循  | 只答一半(如要求"你好开头/再见结尾",但开头没用"你好") |
| 不合理拒答   | 合法合理无风险的问题却拒绝回答                |
| 问题有误    | 用户问题本身有问题 → 模型先纠错再揣测真实意图       |

#### ③ 内容维度

**准确性**:
| 子维度 | 含义 | 注意点 |
|---|---|---|
| 知识错误 | 模型回答错误 | - |
| 推理有误 | 数学/逻辑推理过程出错 | ⚠️ **过程错但结果对**怎么办?要写进规则:看过程 vs 看结果 |

**价值丰富度**:
- **多角度/多维度**:从多个层面看问题。例:"路边被打了" → 报警 + 120 + 看监控 + 打开懂车帝
- **信息一致性**:答案前后是否一致(可用豆包/千问/Claude 同一 prompt 对比)
- **全面性**:能否从更高层面分析

**内容价值**:
| 子维度 | 含义 | 例子 |
|---|---|---|
| 内容贴切性 | 是否符合用户实际需求 | 用户被甩了 → 要安抚情绪而非"挺好的" |
| 时效性 | 答案是否最新 | "最好的视频模型是 Sora?" → 已过时,现在是 Seedance |
| 权威性 | 信息源是否权威 | 法律→宪法/法条;医疗→三甲医院/专业机构,不能来自百度贴吧 |

#### ④ 语言维度
| 子维度 | 含义 |
|---|---|
| 内容表达 | 通顺度、标点符号、语病 |
| 格式表达 | 是否按要求用 1234 序号、Markdown 等 |
| **话术冗余** | 废话太多、扭捏、把简单问题复杂化(用户问北京时间,模型整一个全球时间表) |
| 思路混乱 | 多条思维逻辑互相打架 |

> 思路混乱案例:"企鹅走路晃,可能下雪跳舞,跟哪个约会。以前是会飞的,后来冻硬了才走的,每天守肚子上肉藏的鱼晃着不会掉..."
> 同学:"我觉得挺可爱的。"

**改写规则**:难度太大可舍弃;难度低可改写。错 50% 以上直接跳过。

### 6.5 标注表格关键字段(必须填清楚)
- 错误类型、问题备注、标注原因、互检人、质检结果
- **目的:溯源** —— 这条数据是谁标的、出问题找谁
- 找不到就是训练师责任(不能写"无名氏")

老师之前优化:在表格里加了一列"参考竞品 response" → 不用 Ctrl+Tab 来回切窗口,省力很多。

### 6.6 单轮问答的标注方案
1. 在当前 response 基础上,通过**人为主观判断 + 参考竞品** 提质
2. ⚠️ 知识类内容**不要直接复制竞品**(竞品也有事实错误和幻觉)
3. **主流参考模型**:Gemini、Claude、ChatGPT 5.5 优先用;不好时用文心、Kimi 等第二梯队
4. 通过 / 不通过 / 改写 / 舍弃 —— 四种处理方式

## 七、专项规则文档实战(汽车领域示例)

### 7.1 通用规则能复用到专项吗?
✅ **可以,且必须复用**。

> 比喻:玩 FPS 穿越火线,再玩 CSGO,只需要熟悉新游戏的射击方式 —— WASD 这些底层架构是一样的。

**做法**:在通用规则维度上 **加专项规则**(知识专业性、权威性、时效性等)。

### 7.2 面试话术
被问"你们项目规则维度有哪些?"——
- ❌ 只说"安全、指令遵循、话术冗余" → 太单薄
- ✅ "我们分通用规则维度 + 专项规则维度"分两块说

### 7.3 用 PE 构建专项规则文档(实战流程)

老师强调:**实际工作中,领导也不写,都是用模型查的。**

**两段提示词流程**:

**第一段(了解阶段)**:
```
帮我列出与汽车行业模型 SFT 阶段单轮问答项目相关的内容:
- 这个模型在什么场景下解决什么问题?
- 训练数据类型、数据内容大概长什么样?
- 数据处理大概要怎么处理?
```

**第二段(产出阶段 - PE 格式)**:
```
你是一个专业的 AI 训练师,主要职责是对模型不同训练环节中投喂的数据进行前期处理...

请以汽车行业模型 SFT 阶段单轮问答为例,帮我构建相关规则文档。

[把第一段了解到的数据内容/格式作为示例填入这里]

要求输出:项目背景、目标、数据来源、总量级、输出概况、人效...
```

⚠️ **关键技巧**:
- **角色限定的好处**:防止模型跑偏(不会去金融/医疗/汽车到处乱飞找答案)
- 不给示例 → 模型可能给你 JSON 格式 → **要明确告诉它"一问一答中文格式"**
- 开新项目要 **新开对话窗口**,不然第一轮会污染后面
- 让它"忘记一切"也行

### 7.4 规则文档的核心要素

最重要的是:**背景 + 标注规则**,其他可加可不加。

**阿里实际规则文档结构**(简洁派):
```
1. 背景(数据量、交付周期、准确率)
2. 标注规则(图表 + 维度 + 通过/不通过 + case)
没了。
```

**关键原则**:
- 标注同学只关心"我这数据怎么做",其他不看
- 一定要有 **正向 case + 负向 case 示例**
- 多模态项目视频/图片/语音都要放好坏对比
- 文本类型至少要文字 case
- 数据量是"原始数据量",还要说明剔除后剩多少

### 7.5 人效要写进规则文档
- 给出明确要求:"早上 10-11 点要标 100 条"
- 阿里有交付排期表,每小时统计每人产量
- ⚠️ 自作聪明的同学:实际领了 7 个包却写做了 90 条 —— **后台能看到领包数,一查就穿帮**(每包 10 条数据)

## 八、多轮问答项目

### 8.1 定义
模型在对话中能进行**连续多个回合**的语言交互,且能保持**上下文连贯性和逻辑性**。

### 8.2 单轮 vs 多轮关键区别

| 维度 | 单轮 | 多轮 |
|---|---|---|
| 上下文 | 无 | **有,且影响后续生成** |
| 复杂度 | 低 | 高(需查上下文、推理) |
| 标注难度 | 低 | 高(轮次多、字多) |

### 8.3 上下文一致性陷阱
- 用户在 Q1 设定:"用御姐小姐姐的语气回答"
- 模型在 Q2、Q3 必须保持小姐姐口气
- 到 Q4 突然变成"老弟" → 上下文不一致 → ❌

### 8.4 两种多轮标注方式

**方式 1:全量标注(更常见)**
```
对每一轮 Q 和 A 都进行标注 + 改写
Q1, A1, Q2, A2, Q3, A3 全部都改
```

**方式 2:针对性标注**
```
3 轮里只对第 2 轮进行标注改写
第 1 轮和第 3 轮作为上下文参考(不改)
```

> 应用场景:算法觉得只有第 2 轮回答得不好,其他 OK。

### 8.5 多轮特有规则维度(在单轮基础上加)

#### 指代省略(你我他)
- Q1:"让周杰伦给我唱首歌"
- Q2:"**他**会唱什么?" → 模型必须知道"他"= 周杰伦
- 不能每轮都重复"周杰伦"

#### 重复摘抄
- 第二轮答案有 30%-40% 内容跟第一轮重复 → 不通过

#### 上下文一致性
- 同上,语气/约束/人设全程保持

### 8.6 改写颜色标记规则
- 错误的内容 → **标红**
- 改写后的内容 → **标绿**
- 目的:质检同学一眼能看出哪些字改过了

### 8.7 第一轮就错了怎么办?
"前面都错了,后面跟着错,那就废了" —— 第一轮如果是关键问题错误,后面整组数据都不用救了。

## 九、强化学习(RL)与 RLHF · Reward Model

### 9.1 强化学习的理想 vs 现实

- **理想态**:让模型自主学习、自主进化
- **现实**:目前没有模型能做到 → 需要平替方案

### 9.2 RLHF(基于人类反馈的强化学习)

**RLHF = Reinforcement Learning from Human Feedback**

> 一句话:用人类的偏好/反馈对模型整体输出结果进行训练。
> 
> 比喻:**训练小狗** —— 握手就给吃的,不握手就不给。

### 9.3 Reward Model(奖励模型)

```
原始流程:人 → 直接训练大模型(累死人)
RLHF 流程:人 → 训练小模型(Reward Model)→ Reward Model 代替人 → 训练大模型
```

**关键概念**:
- Reward Model 又叫**奖励模型**
- 它的任务是**学会人类偏好的规律**,不是给用户用的
- 学会规律后,**Reward Model 与大模型形成自循环**,人就解放了
- 最终交付物:**大模型**(小模型只是工具人)

### 9.4 训练师在 RLHF 阶段的工作

- 撰写规则文档
- 构建高质量数据(一个 prompt + 多个答案的排序)
- 质量把控
- 完成 Reward Model 的训练

### 9.5 Reward Model 数据结构

```
1 个 query → N 个不同模型生成的 response → 人工排序

例:
Q:"给我做一份西红柿炒鸡蛋教程"
R1(GPT)、R2(Gemini)、R3(Claude)、R4(豆包)、R5(千问)
↓
人工排序:1234 → 比如 [Claude > GPT > Gemini > 豆包 > 千问]
```

### 9.6 怎么排序? 两两对比法

⚠️ **不能直接看 5 列数据排序** —— 字太多看到 R3 已经忘了 R1 写啥。

**Tournament 擂台赛流程**:
```
R1 vs R2 → 胜者出列
R3 vs R4 → 胜者出列
胜者 vs 胜者 vs R5 ... 直到选出全序
```

**视觉化案例**:5 个美女让大家选喜欢哪个
- 直接选 5 选 1 → 男生第一个,女生第五个,凭感觉
- 把美女换成"5 列多轮对话数据"想想 —— 字一多脑子直接死机

### 9.7 三人盲标机制

⚠️ **盲标 = 三人各自标各自的,互相不知道答案**(各关一个小黑屋)

#### 为什么是 3 人?
- 1 人:主观性太强
- 2 人:意见不合就打架
- 3 人:**最平衡**,降低主观性
- 5 人:浪费人力

#### 不一致怎么办?

| 情况 | 处理 |
|---|---|
| 3 个里有 2 个一致 | 取多数(高一致率) |
| 3 个全不一致 | 重标,标到一致为止 |
| 仍解决不了 | 开会讨论 / 丢项目群让前辈解答 |

⚠️ **不能商量** —— 都商量好统一答案就成串通了。

### 9.8 标注规则的优先级排序(很重要)

被问到 RM 项目规则维度时要懂得**给规则分优先级**。

**响应需求 > 事实正确性 > 基础质量** 是固定的前三位:
1. **响应需求**(指令遵循):没回答需求,谈何正确?
2. **事实正确性**:有答案才能判断对错
3. **基础质量**:无基础质量 > 错 1 项 > 错 2 项 > 错 3 项

后面 4-N 位根据项目自定义:
- **信息丰富度**:4 点 > 3 点 > 1 点
- **创造性**(主观维度,纠结时丢群里讨论)
- **专业度**:多领域深入 > 单一领域
- **排版**:有序 Markdown > 无序

### 9.9 降人效的小技巧

5 人盲标降到 3 人盲标 + 1 人复核:
- 3 人盲标里 2 人一致
- 从普通标注组(非质检组)拉 1 人,标这条数据看是否同意
- 同意 → 视为 3 人一致 → 通过

### 9.10 ⚠️ 数据来源问题

Q:奖励模型的数据来源只有"自己构建一个 prompt + 多答案"吗?算法会不会直接给?
A:看公司、看人。
- 千问业务线可能给
- 淘天业务线可能不给
- 没有统一标准,就看算法那个人

Q:1000 条数据要问 1000 遍模型吗?
A:看项目周期。1000 条 / 22 天 / N 个人 → 一天每人 50-100 条很合理。

## 十、Loss、训练状态与模型评价(简明速记)

> ⚠️ 完整版见独立文档:**《Loss 概念与模型评价完全指南 - AI 训练师视角》**
> 这里只放训练师工作时**最常用的速查信息**。

### 10.1 Loss 一句话理解

**Loss = 模型这次答得有多烂的扣分值**。训练目标 = 调参数让 Loss 变小。

### 10.2 Train / Val / Test Loss 三兄弟

| | 算什么 | 时机 | 用途 |
|---|---|---|---|
| **Train Loss** | 训练集上的扣分 | 每个 batch 都算 | 看学没学进去 |
| **Val Loss** | 验证集上的扣分 | 每个 epoch 后 | 看泛化能力,决定要不要早停 |
| **Test Loss** | 测试集上的扣分 | 训练全完毕后 | 最终成绩单 |

类比:学生备考。
- Train Loss = 讲过的题做得怎样
- Val Loss = 没讲过的模拟考做得怎样
- Test Loss = 期末考分数

### 10.3 用 Loss 判断模型状态

| Train Loss | Val Loss | 状态 |
|---|---|---|
| 高 | 高 | 欠拟合 |
| 低 | 低 | 健康 |
| 低 | 高 | **过拟合** |

> ⚠️ Loss 没有绝对标准 —— 不同任务、不同 Loss 公式不能直接比。看相对差距、趋势、下游 benchmark 才有意义。

### 10.4 业界模型评价指标(Benchmark)

**两条主线一起看**:

| 类别 | 主要 Benchmark |
|---|---|
| **通识** | MMLU、MMLU-Pro、GPQA、C-Eval(中) |
| **数学** | GSM8K、MATH、AIME |
| **代码** | HumanEval、SWE-Bench、LiveCodeBench |
| **长上下文** | Needle in a Haystack、LongBench |
| **指令遵循** | IFEval、MT-Bench |
| **安全** | TruthfulQA、JailbreakBench |
| **多模态** | MMMU、MathVista |
| **主观** | Chatbot Arena Elo、SuperCLUE(中) |

**业内共识**:Benchmark 当筛选门槛,人评决定最终发布。**Benchmark 容易被针对性优化("应试教育"),Arena 是真实用户用脚投票**。

### 10.5 训练师的实战意义

- **算法说 Loss 不收敛** = 数据可能脏 / 标错(第一个找你)
- **Val Loss 反弹** = 过拟合,需要提多样性
- **RM 排序数据** = 你在为 RM 定义 Loss
- **汇报项目效果不报"标了多少条",报 benchmark 提升幅度**:
  ```
  ❌ 我们标了 5000 条数据
  ✅ 我们指令遵循 SFT 让 IFEval 从 60% 涨到 72%,Arena Elo 涨了 30 分
  ```

## 十一、训练师全流程关注的核心 Indicator(必读)

> AI 训练师的工作不是"标完就算",**全流程都要盯数据**。这一节列出每个阶段必看的核心指标。

### 11.1 需求承接阶段

| Indicator | 标准 | 为什么 |
|---|---|---|
| **数据总量** | 写在 SOP 里 | 决定人力 + 工期 |
| **有效数据率(预估)** | 一般 60-80% | 算法给的数据有垃圾,要剔除 |
| **准确率要求** | 95% / 98% / 99% | 决定质检比例 |
| **交付 deadline** | 写明日期 + 中间节点 | 反推每日产量 |
| **数据多样性 / 难度分布** | 简单 50% / 中等 30% / 困难 20% | 防过拟合 |

⚠️ 没问清这些就开干 → 项目大概率延期 / 返工。

### 11.2 试标阶段

| Indicator | 标准 | 解读 |
|---|---|---|
| **试标通过率** | > 70% | 低于 70% → 规则文档不清晰,要补 case |
| **首次准确率** | > 80% | 低于 80% → 培训不到位 / 题目过难 |
| **三人盲标一致率** | > 80% | 低于 80% → 主观性强,规则要细化 |
| **试标完成时间** | 估算的 70%-130% | 太快 → 可能没认真;太慢 → 难度估算错 |
| **疑问数量** | 控制在 < 5 条 / 100 条 | 多 → 规则有死角 |

⚠️ 试标不通过给一次机会,再不通过就释放人力。

### 11.3 正式标注阶段

#### 产量类

| Indicator | 标准 | 为什么 |
|---|---|---|
| **人均日产量** | 文本类 50-180 条 / 天 | 复杂数据(几千字)10 条 / 天也合理,关键是讲得出原因 |
| **累计产量进度** | 按排期 ±10% | 偏差大 → 调整人力或难度 |
| **领包数 vs 完成数** | 必须一致 | 阿里后台能查领包数,造假必穿帮 |

#### 质量类(关键)

| Indicator | 标准 | 解读 |
|---|---|---|
| **互检通过率** | > 90% | 低 → 整组在出错 |
| **不一致率** | < 15% | 高 → 标注员理解分歧 / 规则有歧义 |
| **回扫率** | < 10% | 错 1-2 道帮改;> 50% 直接打回重做 |
| **跳过率** | < 5%(RAG 类项目可放宽到 30%) | 太高 → 数据本身不可用 / 标注员偷懒 |
| **改写率 vs 通过率** | 改写多 → 数据初质量差;通过多 → 数据本身好 | 影响后续算法用法 |

#### 一致性类(RM 项目特有)

| Indicator | 标准 | 解读 |
|---|---|---|
| **三人完全一致率** | > 50% | 低 → 排序主观性太强,规则维度优先级要细化 |
| **两人一致率** | > 80% | 低 → 数据集本身区分度太低 |
| **全不一致率** | < 10% | 高 → 重标 / 拉专家答疑 |

### 11.4 质检验收阶段

| Indicator | 标准 | 解读 |
|---|---|---|
| **质检比例** | 10%-30% | 准确率要求越高比例越大 |
| **抽检通过率** | ≥ 准确率要求 | 不达标 → 全员回扫 |
| **错误类型分布** | 按 4 大维度统计 | 集中在某维度 → 规则文档某块漏了 |
| **Bad case 占比** | < 5% | 高 → 数据策略有问题 |
| **Bad case 复用率** | 加进规则文档 | 同样错不能犯第二次 |

### 11.5 训练后(算法反馈)

#### Loss 类(过程指标)

| Indicator | 健康范围 | 异常处理 |
|---|---|---|
| **Train Loss** | 顺利下降至 1.5-2.5(LLM SFT) | 不降 → 数据脏 / 标错 |
| **Val Loss** | 跟着 Train Loss 降,差距 < 30% | 反弹 → 过拟合,提多样性 |
| **两者比值** | < 1.3 | > 2.0 → 严重过拟合 |

#### Benchmark 类(结果指标)

| 任务类型 | 关注 Benchmark |
|---|---|
| **通用对话 SFT** | MT-Bench、Arena Elo |
| **指令遵循** | IFEval |
| **安全项目** | TruthfulQA、JailbreakBench |
| **代码项目** | HumanEval、SWE-Bench |
| **数学项目** | GSM8K、MATH |
| **多轮对话** | MT-Bench |
| **多模态** | MMMU |

⚠️ 关键认知:**Loss 降了但 benchmark 没涨 = 数据"形似神不似"**(模型背了表面没学到本质)。这时要回头排查多样性、难度梯度、创造性维度。

### 11.6 复盘阶段

| Indicator | 用途 |
|---|---|
| **数据利用率**(交付量 / 原始量) | 评估算法预处理质量 |
| **改写率分布** | 评估数据初始质量 |
| **人效达成率**(实际产量 / 计划) | 给下次排期做参考 |
| **流失率**(标注员中途退出比例) | 控制项目风险 |
| **汰换率**(替换不合格标注员比例) | 招标员质量评估 |
| **客户满意度**(需求方反馈) | 决定下次合作 |

   ↓               ↓                  ↓                ↓              ↓             ↓

### 11.8 训练师汇报话术升级

❌ "我们标了 5000 条数据,项目按时交付了。"

✅ "我们承接了 5000 条单轮指令遵循 SFT 数据,试标通过率 85%,正式标注阶段三人一致率 91%,质检抽检通过率 96%(超过承诺的 95%)。算法训练后 IFEval 从 60% 涨到 72%,Arena Elo 涨了 30 分。后期复盘发现某类边缘 prompt 改写率偏高,我们把这部分加进了规则文档第 6 版。"

→ 同样的项目,后者**直接体现你懂数据闭环 + 懂指标量化**。

## 十二、实战工作技巧补充

### 12.1 飞书知识库(老师强烈推荐)

**怎么建**:云文档 → 新建知识库 → 输入名字

**为什么要建**:
- 笔记、作业、未来工作内容都放进去
- "只要飞书不倒闭、字节还活着,就一直存在"
- 早建早沉淀,反正后期也得建
- 也可以用语雀,但飞书更好用

### 12.2 Prompt 工程要点

- 先用大白话告诉模型 → 让模型生成 PE 框架
- 自己读一遍,判断角色/示例/规范是否 OK
- **PE 不是一次成型**:测试 → 微调 → 测试 → 加内容 → 测试,循环

### 12.3 PE vs CE — 业界范式转变(必懂)

笔记原版只提了"提示词工程师 vs 上下文工程师"一句话,这里展开。

**本质区别**:
- **PE(Prompt Engineering)**:调"**这一句问得好不好**"
- **CE(Context Engineering)**:调"**这一轮该塞哪些东西进模型**"

| | PE | CE |
|---|---|---|
| 解决问题 | 模型不知道要啥 | 上下文里信息太杂/太少 |
| 粒度 | 一段文本 | 整个 context window |
| 工具 | 角色 / 框架 / 示例 / CoT | RAG / Memory / Skill / 摘要 / 路由 |
| 时代 | 2022-2024 | 2024+ |
| 典型场景 | 单次对话 / 文案生成 | Agent / 长任务 / 多轮 |

**简单类比**:
- PE = "怎么把问题问到位"(写好一句话)
- CE = "考试时桌上摆哪几本参考书"(管一整桌信息)

**CE 不是替代 PE,而是包含 PE** —— PE 是 CE 的子集。

#### PE 简单案例:婉拒邮件

❌ 烂版本:
```
帮我写一封拒绝面试的邮件
```

✅ PE 版本:
```
角色:职场沟通专家
背景:我两周前投了 ABC 公司 PM 岗,昨天 HR 邀请下周二面试。
     但同时已经接到更心仪的 offer,要婉拒。
     ABC 是知名公司,希望保留未来再合作可能。
任务:婉拒邮件
要求:
  - 表达感谢
  - 简单说明已接受其他机会(不透露公司)
  - 暗示对 ABC 的好感
  - 150 字以内
语气:专业、礼貌、温暖
格式:邮件格式(标题 + 称呼 + 正文 + 签名)
```

#### CE 简单案例:Cursor 修 bug

只用 PE:"你是 React 专家,我有一个 bug:[贴代码]" → 模型只能根据贴的那段代码猜。

CE 系统(Cursor、Claude Code 在做的):

```
[System Prompt]:你是 React 专家,遵循以下风格规范...
[自动检索的项目上下文]:
  - package.json:React 18、TypeScript、Vite
  - 相关文件:UserList.tsx, useUser.ts
  - 最近 git 改动:3 天前修改了 useUser.ts
[过往对话记忆]:用户偏好不要 class component
[RAG 检索]:React 18 useEffect 最佳实践
[当前问题]:这个组件报错"Cannot read property 'map' of undefined"
```

→ 用户只问了"修 bug",但 CE 系统在背后自动组装了**上下文 + 项目结构 + 用户偏好 + 相关文档**。

#### 训练师怎么用?

| 工作 | PE 还是 CE |
|---|---|
| 用大模型生成专项规则文档(老师讲的两段式 PE) | **PE** |
| 标注 Agent / RAG / 多轮项目 | **教模型做 CE 的能力** |
| 写 SFT 训练数据 | 给 PE/CE 提供原料 |
| 设计 SP / Memory / Skill 系统 | **CE**(算法/工程师做,你不直接做) |

#### 面试话术

> "PE 是早期模型能力不稳定时,用结构化提示词去激活模型特定能力。但模型变强后,瓶颈不再是'听不听得懂',而是'上下文里塞太多反而分心'。所以现在主流是 CE —— 不只关心一句话怎么写,还关心整个上下文窗口里**该有什么、不该有什么、按什么顺序排**。Cursor、Claude Code 这种产品本质上都是 CE 系统。我们 AI 训练师的工作是给模型提供高质量训练数据,让它学会更好地理解上下文 —— 从结果倒推就是在帮模型练 CE 能力。"

### 12.4 模型选择
- 老师反复表态:**别全用豆包**(单一回答、易幻觉)
- 主流梯队:Claude(老师强推)、Gemini、ChatGPT 5.5
- 第二梯队:文心、Kimi(主流不行时辅助)
- Claude Opus **4.6 比 4.7 更强**(老师的经验)
- 普通推理任务不用勾 Adaptive Thinking

### 12.5 个人网站(各站)持续优化
- 不止生成,要**反复迭代**优化
- PDF/飞书文档不专业 —— 个人网站可以放视频/图片/小红书笔记/公众号等
- 用 Claude Design 做最快(内嵌模板)

## 十四、今日核心知识点速查

| 概念 | 一句话 |
|---|---|
| **预训练** | 海量互联网数据 + 无监督学习 → Base Model |
| **后训练** | 弥补预训练缺陷 → SFT + RLHF |
| **SFT** | 有监督微调,投喂优质标注数据 |
| **RLHF** | 用人类反馈训练 Reward Model 代替人 |
| **Reward Model** | 学会人类偏好的中间小模型 |
| **涌现** | 三要素堆叠到某个临界点出现质变能力 |
| **参数** | 模型脑子里"长在身上"的所有知识技能 |
| **Scaling Law** | 性能与「参数 × 数据 × 算力」的可预测幂律关系 |
| **边际效应** | 数据见顶 + Chinchilla + 知识幂律 + 架构上限 + 经济不划算 + 评估饱和 |
| **幻觉** | 数据错误 / 数据缺失硬编 / Token 链式错误 |
| **过拟合** | 书呆子,只会背字符串不会规律 |
| **欠拟合** | 大傻子,啥也没学到 |
| **Loss** | 模型答得有多烂的扣分值 |
| **Train/Val Loss** | 学过的题 vs 没学过的题 |
| **Benchmark** | MMLU/GSM8K/HumanEval/MT-Bench/Arena 等业内公认指标 |
| **PE vs CE** | 调一句话 vs 调一桌信息 |
| **上下文一致** | 多轮中前轮约束影响所有后轮 |
| **指代省略** | 你我他指代正确 |
| **三人盲标** | 各关小黑屋,降低主观性 |
| **两两对比** | 5 列数据看不过来,做擂台赛 |

## 十五、关键面试 / 工作话术

1. **被问"你们怎么做需求承接?"** → 不要脱口而出"5W2H",自然展开 7 维度 + 留痕
2. **被问"项目规则维度?"** → "我们分通用规则 + 专项规则两类"
3. **被问"项目难点?"** → 这是考察解决问题能力的环节,要讲故事
4. **熟用专业词建立印象**:Response、Query、涌现能力、SFT、RLHF、Reward Model、Scaling Law、Loss、Benchmark
5. **STAR 法则写背景**:Situation(现状问题)→ Task(目标)→ Action(怎么做)→ Result(达成什么效果)
6. **被问"你怎么衡量项目效果?"** → 不报"标了多少条",要报 **benchmark 提升 + 三人一致率 + 抽检通过率**
7. **被问"PE 和 CE 区别?"** → "PE 调一句话激活能力,CE 管整个上下文窗口的信息组装,Cursor / Claude Code 都是 CE 系统"
8. **被问"为什么风险话术不能千篇一律?"** → 串讲过拟合 → "把'医疗→谨遵医嘱'当成了规律,不是'医疗类要安全提示',要加多种话术变体"
