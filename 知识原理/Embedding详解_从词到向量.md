## 一、Embedding 是什么

### 一句话定义

> **Embedding 是把"词的意思"压缩进一个数字数组的方式。**

比如"苹果"这个词，经过 Embedding 后变成：

```
"苹果" → [0.21, 0.43, -0.44, 0.87, -0.12, 0.33, ...]
```

这个数组可能有 4096 个数字（具体取决于模型大小），每个数字是一个浮点数。

---

### 为什么叫"向量"

数学上，一组有序的数字就叫**向量**。

```
2D 向量（二维空间的坐标）：[3, 5]
3D 向量（三维空间的坐标）：[3, 5, 2]
4096D 向量（4096 维空间的坐标）：[0.21, 0.43, -0.44, ..., 0.87]
```

Embedding 就是一个高维空间里的坐标。

---

### 这些数字是什么意思

**单独看每一个数字，没有人能解释它是什么意思。**

但整体看这个向量，它编码了这个词的"语义位置"——和其他词的相似度、关系、上下文。

把它想成：模型给每个词造了一张"语义身份证"，身份证上的每一格数字你看不懂，但模型能从整张身份证里"认出"这个词，以及它和其他词的关系。

---

## 二、为什么需要 Embedding

### 计算机只能处理数字

计算机不能直接理解文字。"苹果"对计算机来说就是一串字符——它不知道苹果是水果、能吃、是圆的。

最简单的数字化方式是**One-hot 编码**：

假设词表有 5 个词：

```
苹果 = [1, 0, 0, 0, 0]
香蕉 = [0, 1, 0, 0, 0]
狗   = [0, 0, 1, 0, 0]
猫   = [0, 0, 0, 1, 0]
汽车 = [0, 0, 0, 0, 1]
```

**One-hot 的致命问题：**

苹果和香蕉的向量距离，和苹果和汽车的向量距离——**一模一样**。

```
苹果 vs 香蕉：[1,0,0,0,0] vs [0,1,0,0,0] → 距离 = √2
苹果 vs 汽车：[1,0,0,0,0] vs [0,0,0,0,1] → 距离 = √2
```

向量里没有任何语义信息，不知道苹果和香蕉都是水果、比苹果和汽车更相似。

---

### Embedding 解决了这个问题

Embedding 让**语义相近的词，坐标相近**：

```
           高维空间示意（降维到2D方便画图）

                 苹果 ●
                      ● 香蕉
                 橙子 ●

                              ● 狗
                          ● 猫
                        ● 鸟

     汽车 ●
              ● 摩托车
         ● 自行车
```

- 苹果、香蕉、橙子聚在一起（都是水果）
- 狗、猫、鸟聚在一起（都是动物）
- 汽车、摩托车、自行车聚在一起（都是交通工具）

模型通过这种"语义聚集"来理解词与词之间的关系。

## 三、Embedding 是怎么训练出来的

### 核心原理：上下文相似的词，意思相近

语言学家 Firth 在 1957 年说过一句话：

> **"你可以通过一个词的伴侣来了解它。"**

翻译成现代说法：**出现在相似上下文里的词，意思相近。**

- "我吃了一个**苹果**" / "我吃了一个**香蕉**" → 苹果和香蕉可以互换 → 它们的 Embedding 要靠近
- "**狗**在叫" / "**猫**在叫" → 狗和猫可以互换 → 它们的 Embedding 要靠近

---

### 训练过程（Word2Vec 的直觉）

早期的 Word2Vec 模型用了一个简单的训练任务：

**任务：给定上下文词，预测中间那个词**

```
训练样本：
"我 ___ 了一个苹果"  →  正确答案：吃
"我 ___ 了一个香蕉"  →  正确答案：吃
"狗 ___ 了"          →  正确答案：叫
```

模型一开始给所有词随机分配坐标：

```
"苹果"：[0.1, -0.3, 0.7, ...]   ← 随机，没意义
"香蕉"：[0.9, 0.2, -0.4, ...]   ← 随机，没意义
```

训练过程中，如果"苹果"和"香蕉"在类似上下文里反复出现，**它们的坐标会被一步步推近**。

训练完成后：

```
"苹果"：[0.21, 0.43, -0.44, ...]   ← 有语义了
"香蕉"：[0.23, 0.41, -0.46, ...]   ← 和苹果很近
```

---

### 现代大模型的 Embedding

现代大模型（GPT、Qwen、Claude）的 Embedding 不是单独训练的，而是和整个模型**一起端到端训练**的。

在海量文本（几万亿 token）的预训练过程中，Embedding 矩阵的每一行（每个词的向量）都在不断被优化，直到能最好地支持模型做"预测下一个 token"的任务。

---

## 四、向量空间里的语义几何

### 向量加减法有语义意义

这是 Embedding 最神奇的地方：

```
向量("国王") - 向量("男性") + 向量("女性") ≈ 向量("女王")
```

用图来理解：

```
        女性
         ↑
女王 ←───┤
         │  （这个偏移量代表"性别"）
         │
国王 ←───┘
         ↓
        男性
```

"国王"到"女王"的偏移方向，和"男性"到"女性"的偏移方向**一致**。

这说明 Embedding 空间里真的存在某种"语义方向"：
- 某些方向代表"性别"
- 某些方向代表"单复数"
- 某些方向代表"时态"

---

### 相似度计算：余弦相似度

判断两个词的语义相似度，用**余弦相似度**：

```
余弦相似度 = 两个向量夹角的余弦值
         = 方向越接近，值越接近 1
         = 方向越相反，值越接近 -1
```

直觉理解：

```
苹果 vs 香蕉  →  余弦相似度 0.89（很相似）
苹果 vs 汽车  →  余弦相似度 0.12（不相似）
苹果 vs 烂苹果 → 余弦相似度 0.95（非常相似）
苹果 vs 橙子  →  余弦相似度 0.82（相似）
```

**RAG（检索增强生成 Retrieval-Augmented Generation）里的"向量检索"，就是用这个原理**：把用户的问题变成向量，在知识库的向量里找余弦相似度最高的几个。

## 五、Embedding 和 Token 的关系

很多人会混淆这两个概念，这里明确区分。

### Token 是什么

Token 是**分词器切分后的最小单元**，本质是一个**整数 ID**。

```
"我吃了一个苹果" 
    ↓ 分词器
["我", "吃", "了", "一个", "苹果"]
    ↓ 映射为 ID
[101, 2345, 342, 1256, 3721]
```

| 概念 | 本质 | 例子 |
|------|------|------|
| Token | 整数 ID | 3721 |
| Embedding | 浮点数向量 | [0.21, 0.43, -0.44, ...] |

---

### 从 Token 到 Embedding：查表

模型有一张巨大的 **Embedding 查找表**（Embedding Matrix）：

```
Embedding Matrix（部分示意）：

token ID 0    → [0.12, -0.34, 0.56, ...]
token ID 1    → [-0.23, 0.45, -0.12, ...]
...
token ID 3721 → [0.21, 0.43, -0.44, ...]  ← 苹果
...
token ID 50256→ [0.87, -0.91, 0.33, ...]
```

词表有多少个 token，这张表就有多少行。每行是一个 4096 维的向量。

**查表这一步没有任何计算，就是"根据 ID 找对应那一行"。**

---

### 一个具体的数字

以 Qwen2.5-7B 为例：

```
词表大小：约 152,000 个 token
每个 token 的 Embedding 维度：4096
Embedding Matrix 总大小：152,000 × 4096 = 约 6.2 亿个浮点数 ≈ 约 1.2 GB
```

这张表是模型参数的一部分，存在 GPU 显存里。

## 六、Embedding 在模型里的位置

### 整体流程中的位置

```
文本输入："小明喜欢她"
    ↓
【分词器】
    ↓
Token 序列：["小明", "喜欢", "她"]
    ↓
Token ID 序列：[2341, 8912, 512]
    ↓
【Embedding 查表】  ← Embedding 在这里
    ↓
向量序列：
  小明 → [0.31, 0.52, -0.21, ..., 0.44]
  喜欢 → [-0.12, 0.83, 0.67, ..., -0.33]
  她   → [0.77, -0.41, 0.29, ..., 0.61]
    ↓
【进入模型各层（共 32 层）】
    ↓
【输出下一个 token 的概率分布】
```

Embedding 是**语言进入数学世界的入口**，是模型计算的起点。

---

### 位置编码（Positional Encoding）

有一个重要问题：**"小明喜欢她"和"她喜欢小明"的词一样，但意思完全不同。**

Embedding 查表只管"这个词是什么"，不管"这个词在第几个位置"。

所以查表完之后，还要加上**位置编码**：

```
小明的最终向量 = Embedding("小明") + PositionalEncoding(位置1)
喜欢的最终向量 = Embedding("喜欢") + PositionalEncoding(位置2)
她的最终向量   = Embedding("她")   + PositionalEncoding(位置3)
```

位置编码也是一个向量，把"我在第几个位置"这个信息编码进去。这样模型才能区分词序。

---

## 七、从 Embedding 到 Q/K/V

这是 Embedding 之后紧接着发生的事情，也是理解注意力机制的关键。

### Embedding 只是"原材料"

进入每一层后，每个 token 的向量会被乘以**三个不同的权重矩阵**，分别产生 Q、K、V：

```
token向量（来自Embedding）
    ↓
    ├── × W_Q（权重矩阵Q） → Q向量（Query，查询）
    ├── × W_K（权重矩阵K） → K向量（Key，键）
    └── × W_V（权重矩阵V） → V向量（Value，值）
```

W_Q、W_K、W_V 是训练出来的固定参数，不同层有不同的权重矩阵。

---

### Q/K/V 各自的命运

| 向量 | 用途 | 最终命运 |
|------|------|---------|
| **Q（Query）** | 用来"问"——"我想关注谁？" | 与所有K点积算完分数后消失 |
| **K（Key）** | 用来"被问"——"我有什么特征？" | **缓存在 KV Cache 里** |
| **V（Value）** | 真正的内容——"找到我，拿走这个" | **缓存在 KV Cache 里**，加权求和后流向下一层 |

---

### 注意力计算的完整过程

以"她"这个 token 为例，它想知道自己指代谁：

```
第1步：计算注意力分数
Q_她 · K_小明 = 0.92  （点积结果）
Q_她 · K_喜欢 = 0.31
Q_她 · K_她   = 0.11
        ↓ softmax（变成概率，加起来=1）
[0.70, 0.20, 0.10]    （注意力权重）

第2步：加权求和 V
0.70 × V_小明
+ 0.20 × V_喜欢
+ 0.10 × V_她
= "她"的新向量（融入了"小明"的语义）

第3步：这个新向量流向下一层
```

每过一层，每个 token 的向量就更新一次，融入更多上下文信息。32 层之后，"她"的向量已经"知道"自己指代小明，并融合了整句话的语境。

---

### 为什么缓存 K 和 V，不缓存 Q

生成下一个新 token 时：

- **Q** 是新 token 自己的，每次现算，没法提前知道
- **K** 和 **V** 是历史 token 的，算过一次就不会变——所以缓存起来

这就是 **KV Cache** 的本质：用空间换时间，避免每次生成都重算历史 token 的 K 和 V。

---

## 八、Embedding 的局限：它是静态的

### 同一个词，永远同一个 Embedding

Embedding 查表这一步有一个重大局限：

```
"我吃了一个苹果"  →  苹果的Embedding：[0.21, 0.43, -0.44, ...]
"苹果公司发布了新手机" →  苹果的Embedding：[0.21, 0.43, -0.44, ...]
```

**无论苹果是水果还是公司，查出来的向量一模一样。**

这就是为什么需要模型的**多层注意力机制**——通过 Q/K/V 的运算，不断融入上下文，让向量越来越"懂得语境"。

到了模型的最后几层，"苹果（水果）"和"苹果（公司）"的向量**已经完全不同**了，因为注意力机制让它们融入了各自不同的上下文。

---

### 上下文 Embedding（Contextual Embedding）

BERT、GPT 这类模型产生的，就是**有上下文信息的向量**：

```
查表阶段（静态）：
  "苹果"（水果）→ [0.21, 0.43, -0.44, ...]
  "苹果"（公司）→ [0.21, 0.43, -0.44, ...]  ← 一样

经过多层注意力后（动态）：
  "苹果"（水果）→ [0.87, -0.12, 0.34, ...]  ← 不一样了
  "苹果"（公司）→ [0.23, 0.76, -0.55, ...]  ← 不一样了
```

RAG 里用来做"语义检索"的，通常就是这种**上下文 Embedding**——把整段文字编码成一个有语义的向量，用于相似度匹配。

## 九、完整流程总结

```
文本："小明喜欢她"
        ↓
【1. 分词器】
  → Token: ["小明", "喜欢", "她"]
  → Token ID: [2341, 8912, 512]
        ↓
【2. Embedding 查表】（静态，无上下文）
  → 小明: [0.31, 0.52, -0.21, ...]
  → 喜欢: [-0.12, 0.83, 0.67, ...]
  → 她:   [0.77, -0.41, 0.29, ...]
        ↓
【3. 加位置编码】
  → 各自加入"我在第N个位置"的信息
        ↓
┌─────────────────────────────────┐
│  【4. 第 1 层：注意力 + FFN】    │
│   每个向量 × W_Q → Q             │
│   每个向量 × W_K → K （存KV Cache）│
│   每个向量 × W_V → V （存KV Cache）│
│   Q·K → 注意力权重               │
│   权重 × V → 新向量（有了上下文）  │
└─────────────────────────────────┘
        ↓
┌─────────────────────────────────┐
│  【5. 第 2 层】同样的过程         │
│     但权重矩阵不同，融入更深语义   │
└─────────────────────────────────┘
        ↓
      ...（共 32 层）...
        ↓
【6. 最后一层输出】
  → "她"的向量现在已经包含了整句话的语境
  → 用这个向量预测下一个最可能的 token
        ↓
【7. 输出】
  → 下一个词："笑了" / "哭了" / "离开了" ...
```

## 十、术语速查

| 术语 | 英文 | 一句话解释 |
|------|------|-----------|
| **Embedding** | Embedding | 把词变成向量的方式，语义相近的词向量相近 |
| **Embedding Matrix** | Embedding Matrix | 存所有词向量的大表，token ID 对应一行 |
| **Token** | Token | 分词后的最小单元，本质是整数 ID |
| **Token ID** | Token ID | 词在词表里的编号 |
| **词表** | Vocabulary | 模型认识的所有 token 的集合 |
| **向量** | Vector | 一组有序的数字，代表高维空间里的坐标 |
| **维度** | Dimension | 向量的长度，如 4096 维 |
| **余弦相似度** | Cosine Similarity | 衡量两个向量方向是否接近，用于语义相似度计算 |
| **位置编码** | Positional Encoding | 把词的位置信息加入向量 |
| **上下文 Embedding** | Contextual Embedding | 经过注意力机制后融入上下文的向量 |
| **Q/K/V** | Query / Key / Value | 注意力机制里的三个角色，由 Embedding 乘权重矩阵产生 |
| **KV Cache** | KV Cache | 缓存历史 token 的 K 和 V，避免重复计算 |
| **Word2Vec** | Word2Vec | 早期的词向量训练方法，奠定了 Embedding 的基础 |
| **RAG** | Retrieval-Augmented Generation | 检索增强生成，利用向量相似度检索知识库 |

---

## 一句话终极总结

> **Embedding 是语言进入数学世界的入口。**
> **它把"词的意思"压缩成一串数字，让模型能做语义运算。**
> **但它本身是静态的——真正的"理解"是后续多层注意力机制一步步累积出来的。**
