### 程鹏 — 多模态图片美学SFT + 视频标注

**项目**：
- 多模态模型SFT阶段提升图片理解和美学生成
- 需求方给5万条数据
- 7个跳过规则 + 8个标注维度（主体类型、景别、构图、风格、光影、色调、情感氛围、整体描述250-350字）
- 数据清洗用自动化脚本（Cloud Code + Cursor）
- 两轮试标：第一轮40条发现漏洞，第二轮50条验证
- 卡帕一致性0.68

**犀利追问**：
> "原始数据8万还是5万？清洗你们负责的？"
> "自动化脚本怎么写的？Prompt分几个架构？有约束有示例吗？"（答：项目背景+角色定位+思考行动+自检）
> "为什么是8个维度？只给3个你选什么？"（答：主体类型、构图、色调）
> "卡帕一致性是什么？你用的多少？"（答：0.68，较好一致）
> **"你说的都是套话——给我一个具体场景！"**
> 冲突案例：构图维度标注员只打中心构图被质检打回 → 规则没写清楚构图可选两个按主导排序

## 第四场：复盘总结课（18:43，约37分钟）

### 一、项目准备三大铁律

**铁律1：规则文档必须自己写，AI不算**
> "自己去标，自己去构建。AI生成也不是你的。"

展示往期学长范本：风格矢量坐标图（传统↔现代×极简↔极繁）、纹理混淆表（真木纹vs假贴图）、光影自采图、饱和度分割图——全是一手做的，不是模型生成的。

**铁律2：人效自己算**
> "别问我60条行不行、100条行不行——自己算！"

公式：**人效×人数×周期=数据量**。三个对上就没人能质疑。特殊情况（长caption几千字半小时一条）才几百条，普通图片5-20万条。

**铁律3：数据实打实自己标**
> "数据有质疑就是因为你没真正标过。"

规则细的话标3条就行，但必须涵盖所有问题标签。标的过程计人效再推算落地。

---

### 二、面试=讲故事

> "前期→中期→遇到问题→给方案→最终成果。这就是迪士尼动画的结构——所有好故事都有冲突和解决方案。"

- 80%面试官问"项目中遇到什么问题怎么解决"→ 核心看**解决问题能力**
- 项目讲解：讲清项目本身 + 解决问题能力 + 人员管理案例 + 展示优势
- "你做了这个项目=你来我这也能做"

---

### 三、七大考察点

| 类别 | 常见问题 | 考什么 |
|------|---------|--------|
| 自我介绍 | 信息→公司→项目→职责→优势 | 第一印象 |
| 项目经验 | 全流程、规则、落地、管理 | 能不能干活 |
| 解决问题 | "遇到什么问题怎么解决？" | 通用能力 |
| 个人 | 离职原因、优缺点、转行原因 | 稳定性+抗压 |
| 前瞻性 | 用过什么模型？工具对比？AGI看法？ | 真热爱这行吗 |
| 场景题 | 紧急需求？多任务并行？从零到一？ | 逻辑思维 |
| 反问 | 你问面试官 | 意愿度 |

---

### 四、评测项目三核心

1. **评测集**：真真正正构建，打分值，发现数据常见问题
2. **评测方案**：规则方案（1-5分各代表什么怎么确定）+ 人员作业方案（如何去除主观性）
3. **评测报告**：胜出率、分值占比、场景平均分、Good/Bad Case、给算法/需求方的有效建议

---

### 五、面试技巧10条

1. **回答前先想2-3秒**——不要着急，想清楚结构再说
2. **用STAR/总分总/前中后**——每句话体现一个能力
3. **讲多了赶紧拉回来**——面试官可能只听最后一句话
4. **面试=相亲**——每句话暗含一个优点，表达"我愿意来"
5. **不要冷脸、不要话太少**——冷场是最大忌
6. **微笑面对**——"人生在外全靠演技"
7. **反问问业务方向/团队/发展**——体现意愿度
8. **不要问加班、周末上班**
9. **❌禁止提老师名字或"钱万出来的"**
10. "MBTI职场最受欢迎的是J人——有规划的人"

---

### 六、项目周期表述技巧

> "别说一个项目5天/22天——把周期去掉，改说持续性的。"

正确说法："我们项目是根据算法/产品需求来驱动的。算法训完发现人像能力不行→给新需求→还是纹身图但专项提升构图和风格→训模型→评测→发现问题→回来交替训练→周期性持续。"

## 常见错误与踩坑

### 🔴 致命级

| 错误 | 后果 | 正确 |
|------|------|------|
| 规则文档靠AI生成 | 一追问就穿帮 | 自己写/自己标/自己验证 |
| 人效前后矛盾 | 心里一算就对不上 | 实打实标一下，公式验证 |
| "保密/没了解到" | 显得没参与核心 | 至少知道模型名/方向 |
| 没案例 | 像在编造 | 每个维度配一个真实案例 |
| 张口套话 | 面试官打断追问 | 准备2-3个真实冲突故事 |
| 开放题第一反应拒绝需求 | 暴露能力零 | 先分析→方案→极限 |
| 项目周期极不合理 | 一眼假 | 改说持续性项目 |
| 说管理但讲不出案例 | 直接PASS | STAR故事讲清楚 |
| 分不清纹身图/图生文 | 基本概念错 | 搞清模型类型 |

### 🟡 高风险

- 口语太重 → 抓不到重点
- 讲话随便 → 不像做这行的
- 聊自动化讲不清实现 → 挖坑
- 回答没结构 → 显得思维乱
- 追问开始绕 → 越绕越被动
- 冷场话少 → 面试就凉
- 反问提问禁忌 → 意愿度低

### 🟢 易忽略

- 数据量/人数/人效/周期必须互相验证
- Bad Case分类要有框架
- 质检率的理由要说清
- 试标不是走形式
- 自我介绍1分钟
- 项目经历不写具体周期

## 核心技巧

### 1. 结构化表达模板

**总分总**："关于这个问题，我从X个方面回答。第一...第二...总结..."

**STAR**："在XX项目中，我遇到XX。方案是XX。结果是XX。"

**前中后**："前期做了XX，中期做了XX，后期做了XX。最有挑战的是..."

### 2. 紧急需求题黄金流程

```
Step 1: 确认需求（数据形式？质量？规则复杂度？）
Step 2: 预估人效（自己标一条花多久）
Step 3: 盘点资源（多少人？供应商？）
Step 4: 算极限（最多人同做，最快几天）
Step 5: 主动报方案（我们3天交付，OK？）
```

### 3. "卡点"回答模板

准备2-3个真实场景，每个包含：
- 背景（项目、维度）
- 冲突（谁和谁、什么问题）
- 行动（分析→处理→更新文档）
- 结果（沉淀成规范）

> ❌ "我们遇到过构图问题，后来解决了"
> ✅ "标注员只打中心构图被质检打回。我去看发现规则没说清楚——构图可选两个按主导排序。我更新文档+全体培训，之后再没出现。"

### 4. 知识面必备

面试前能随口说：
- 3个生图模型名字+优缺点+场景
- 3个大模型+各自擅长
- 评测vs标注自己的理解
- 对AI行业一个个人观点

### 核心速算公式

```
数据总量 = 标注人数 × 人均日效 × 有效作业天数
质检人数 = 标注人数 ÷ 质检配比（常见5:1~7:1）
日均质检量 = 标注人数 × 人均日效 × 抽检率
```
