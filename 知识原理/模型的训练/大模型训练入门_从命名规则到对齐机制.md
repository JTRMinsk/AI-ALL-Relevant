## 1. DeepSeek 的命名规则

DeepSeek 是中国深度求索公司（幻方量化孵化）的开源大模型系列。命名格式是：

```
DeepSeek-[类型][版本号]-[变体]
```

### 字母代表"模型类型"

| 前缀 | 含义 | 定位 |
|------|------|------|
| **V** | Version（通用版本） | 像 GPT-4o、Claude 那种对话/通用模型 |
| **R** | Reasoning（推理） | 像 OpenAI o1 那种"先思考后回答"的模型 |
| **Coder** | 代码专用 | 类似 GitHub Copilot 的代码补全 |
| **Math** | 数学专用 | 数学题求解 |
| **VL** | Vision-Language | 多模态，看图说话 |

### V3 和 R1 的关键差异

两者**都是 671B 参数（MoE 架构，激活约 37B）**，底座差不多，但训练方式和用途完全不同：

| | DeepSeek-V3（2024.12） | DeepSeek-R1（2025.01） |
|---|---|---|
| **类型** | 通用对话模型 | 推理模型 |
| **对标** | GPT-4o、Claude 3.5 Sonnet | OpenAI o1 |
| **训练方式** | 预训练 + SFT + RLHF | 强化学习（RL）为主 |
| **输出风格** | 直接给答案 | 先输出 `<think>...</think>` 思考过程，再给答案 |
| **适合任务** | 日常对话、写作、简单代码 | 数学、复杂推理、算法题 |

R1 之所以轰动，是因为它**证明了"纯 RL 也能训出推理能力"**，把推理模型的成本降到了 o1 的几十分之一，并且技术报告完全开源——业内称之为"DeepSeek 时刻"。

### DeepSeek 家族一览

```
DeepSeek-V1        (2024.01) 第一代通用模型
DeepSeek-Coder     (2024.01) 代码专用
DeepSeek-Math      (2024.02) 数学专用
DeepSeek-VL        (2024.03) 多模态
DeepSeek-V2        (2024.05) 首次大规模 MoE 架构
DeepSeek-Coder-V2  (2024.06) 代码模型升级
DeepSeek-V2.5      (2024.09) 把 V2 和 Coder-V2 合并
DeepSeek-V3        (2024.12) 671B MoE,对标 GPT-4o
DeepSeek-R1        (2025.01) 推理模型,对标 o1
DeepSeek-R1-Zero   (2025.01) 纯 RL 训练版（实验性）
```

### 与其他厂商的对应

各厂商现在普遍走"通用模型 + 推理模型"双线：

| 厂商 | 通用模型 | 推理模型 |
|------|---------|---------|
| OpenAI | GPT-4o、GPT-5 | o1、o3 |
| Anthropic | Claude Sonnet/Opus | Claude with extended thinking |
| Google | Gemini 2.5 Pro | Gemini 2.5 Thinking |
| DeepSeek | **V 系列** | **R 系列** |
| 阿里 | Qwen-Max | QwQ |

记忆口诀：**V ≈ GPT-4o，R ≈ o1**。

## 2. 开源生态：DeepSeek 和 Qwen 的"非合作"关系

R1 发布时，DeepSeek 同时放出了一堆**蒸馏小模型**，命名格式如：

```
DeepSeek-R1-Distill-Qwen-7B
DeepSeek-R1-Distill-Qwen-14B
DeepSeek-R1-Distill-Qwen-32B
DeepSeek-R1-Distill-Llama-8B
DeepSeek-R1-Distill-Llama-70B
```

很多人看到这个会以为 DeepSeek 和阿里有什么合作。**没有，他们其实是竞争对手**。

### 真相是：Qwen 开源了，DeepSeek 单方面拿来用了

国内外大模型分两类：

| 类型 | 代表 | 谁能用 |
|------|------|--------|
| **闭源 API 模型** | GPT-4、Claude、qwen-max | 只能调 API |
| **开源权重模型** | Llama、Qwen2.5、Mistral、DeepSeek V3/R1 | 任何人都能下载、微调、二次发布 |

阿里把 Qwen2.5 系列（1.5B、7B、14B、32B、72B 等）的**完整权重开源到 HuggingFace 上**，遵循 Apache 2.0 协议——这意味着任何人可以下载、微调、重新发布（标注来源即可）。

### 命名背后的"血统说明"

`DeepSeek-R1-Distill-Qwen-7B` 这个名字本身就包含了完整的血统：

```
DeepSeek-R1-Distill-Qwen-7B
   ↑       ↑      ↑    ↑
  谁做的  蒸馏自谁  基座是谁  多大
```

翻译成人话：**"DeepSeek 团队用 R1 作为老师，把 Qwen-7B 作为底子，蒸馏出来的小模型"**。

类似的命名惯例还有：
- `DeepSeek-R1-Distill-Llama-70B` → 底子是 Llama 70B
- `Nous-Hermes-Llama-3-8B` → Nous Research 基于 Llama 3 8B 微调
- `WizardLM-2-8x22B` → WizardLM 团队基于 Mistral 的 Mixtral 8x22B 微调

### 一个形象的比喻：橡皮泥

可以把开源模型想成不同硬度的橡皮泥：

```
Qwen2.5-7B-Base       ← 原始橡皮泥（刚揉好,啥形状都能捏）
       ↓
Qwen2.5-7B-Instruct   ← 已经捏成"对话娃娃"的橡皮泥（半定型）
       ↓
DeepSeek-R1-Distill-Qwen-7B  ← 在对话娃娃基础上又捏成"奥数选手"
```

整个开源生态就像一个**雕塑村**：
- **阿里、Meta** = 橡皮泥厂（生产基座模型）
- **DeepSeek、Mistral 等** = 雕塑大师（拿橡皮泥做特色作品）
- **HuggingFace** = 集市（大家把作品摆出来）
- **普通开发者** = 顾客（下载现成的或者自己捏）

### 为什么 Qwen 成了"全民橡皮泥"

不是巧合：

1. **尺寸齐全**：Qwen 系列有 0.5B、1.5B、3B、7B、14B、32B、72B 七个尺寸，开源界独此一家。Llama 只有 8B、70B、405B 三档。
2. **中文能力强**：Llama 的中文勉强能用，Qwen 是原生流畅。
3. **协议宽松**：Qwen2.5 大部分是 Apache 2.0，比 Llama 协议自由。
4. **基础质量高**：阿里在预训练上砸的钱够多，基座扎实。

## 3. 知识蒸馏（Knowledge Distillation）

蒸馏的本质没那么神秘——**让小模型模仿大模型的输出**。

### 核心思想

**目标**：让小模型（学生）学会大模型（老师）的能力，同时保留小模型的体积和速度。

**直觉**：与其让小模型自己摸索（看原始训练数据），不如直接看大模型已经学会的"答案"——这样学得快、学得准。

### 两大流派

#### 流派一：黑盒蒸馏（Data Distillation）—— DeepSeek R1 用的就是这个

**只看老师的"输出"，不看老师的"内部"**。流程：

```
第1步：准备一堆题目（输入）
       ↓
第2步：让老师 R1 回答这些题目
       ↓
第3步：收集老师的回答（输入+输出 = 训练数据）
       ↓
第4步：用这些数据微调学生 Qwen-7B
       ↓
第5步：学生学会模仿老师的回答风格
```

R1 蒸馏 Qwen 的真实操作：

1. **准备约 80 万条推理任务**：数学题、编程题、逻辑推理、科学问答、对话
2. **让 R1 跑一遍，生成"带思考过程"的回答**，例如：

```
输入：解方程 x² - 5x + 6 = 0

R1 输出：
<think>
这是一个二次方程,可以用因式分解或求根公式。
试试因式分解：找两个数,乘积是 6,和是 -5。
应该是 -2 和 -3,因为 (-2)×(-3)=6,(-2)+(-3)=-5 ✓
所以 (x-2)(x-3)=0
解得 x=2 或 x=3
验证：2² - 5×2 + 6 = 4-10+6 = 0 ✓
       3² - 5×3 + 6 = 9-15+6 = 0 ✓
</think>

x = 2 或 x = 3
```

3. **监督微调 Qwen-7B**：让 Qwen-7B 看到同样输入时输出尽量接近 R1 的输出

#### 流派二：白盒蒸馏（Logit Distillation）—— 经典方法

更"深入"的方式——不只看老师的最终输出，还看老师**输出每个词时的概率分布**（logits）。

例如老师回答"今天天气..."时，内部其实是：
```
"晴朗" → 概率 45%
"不错" → 概率 30%
"很好" → 概率 15%
"阴沉" → 概率 5%
```

**白盒蒸馏**让学生学习这整个概率分布，信息量比"只看最终答案"大得多。技术上叫 **KL 散度损失**。

**经典论文**：Hinton 2015 年的《Distilling the Knowledge in a Neural Network》。

**为什么 DeepSeek 没用白盒蒸馏？** 因为白盒要求老师和学生**词汇表完全一致**，而 R1 和 Qwen 词表不一样。所以跨架构蒸馏基本都用黑盒法。

### 蒸馏 vs 其他训练方式

| 方法 | 数据来源 | 谁标注 | 例子 |
|------|---------|--------|------|
| **预训练** | 互联网原始文本 | 不需要标注 | 训练 Qwen-Base |
| **SFT（监督微调）** | 人工写的高质量问答 | 人类标注员 | 训练 Qwen-Instruct |
| **RLHF** | 人类对模型回答的偏好评分 | 人类打分 | ChatGPT 训练 |
| **RL（强化学习）** | 自动评测的奖励信号 | 自动评分（如代码能否运行） | DeepSeek-R1 训练 |
| **蒸馏** | 大模型生成的回答 | **模型当标注员** | R1-Distill-Qwen |

**蒸馏的核心创新**：把"人类标注员"换成了"更强的模型"，标注成本几乎归零。

### 实测效果（DeepSeek 官方论文）

| 模型 | AIME 2024（数学竞赛） | MATH-500 | LiveCodeBench |
|------|---------------------|----------|---------------|
| Qwen2.5-Math-7B-Instruct（原版） | 13.3% | 64.8% | - |
| **DeepSeek-R1-Distill-Qwen-7B** | **55.5%** | **92.8%** | 37.6% |
| GPT-4o（参考） | 9.3% | 74.6% | 32.9% |

7B 的小模型蒸馏后，数学竞赛分数从 13% 飙到 55%，**甚至超过 GPT-4o**。这就是为什么"已经训练好"的 Qwen 还要再蒸馏一遍。

### 蒸馏的成本对比

| 项目 | 成本 |
|------|------|
| 从零训练一个 7B 基座 | 约 500 万美元 |
| 训练 R1 本身（671B） | 约 500 万美元 |
| **用 R1 蒸馏到 Qwen-7B** | **约 1-5 万美元** |

### 蒸馏的关键规律

> **学生永远不会超过老师**。R1-Distill-Qwen-7B 再怎么牛，也不可能在推理上超过 R1 本身——因为它学的就是 R1 的答案。

但蒸馏版**可能在某些方面比同尺寸原版强很多**：
- R1-Distill-Qwen-7B 在推理任务上 >> Qwen-7B-Instruct
- 但日常对话上可能略差（专精了推理，牺牲了通用性）

## 4. Base 模型 vs Instruct 模型

一个开源模型其实有"两层"：

```
Qwen2.5-7B-Base       ← 只做了预训练,会"接话"但不会"回答问题"
       ↓ 微调
Qwen2.5-7B-Instruct   ← 学会了对话,能正经回答问题
```

**底子（参数架构、词汇表、基础知识）一样，但"行为模式"完全不同**。

### 实测对比

**你输入**：`今天天气怎么样？`

**Qwen2.5-7B-Instruct（指令版）的回答**：
```
今天天气情况需要查询具体地区。你可以告诉我你所在的城市,
我可以帮你查询。或者你可以通过天气 APP 查看实时天气信息。
```
✅ 理解你在问问题，给出有帮助的回答。

**Qwen2.5-7B-Base（基础版）的回答**：
```
今天天气怎么样？小明问妈妈。
妈妈说：今天天气晴朗,万里无云,适合出去玩。
小明听了很高兴,立刻拿起书包准备出门...
```
😅 它完全没意识到你在跟它对话——它以为你在写作文，于是接着帮你写下去。

再来一个例子：

**你输入**：`请帮我写一个 Python 冒泡排序`

**Instruct 版的回答**：直接给出代码

**Base 版的回答**：
```
请帮我写一个 Python 冒泡排序。
请帮我写一个 Java 快速排序。
请帮我写一个 C++ 归并排序。
请帮我写一个 Go 语言的堆排序。
...
```
😂 它以为你在写"练习题列表"，于是继续列下去。

### 为什么 Base 模型这么"傻"

因为它的训练数据是**整个互联网的原始文本**——网页、书籍、论坛、代码、维基百科……

训练目标只有一个：**给定前面的文本，预测下一个 token**。

```
输入：今天天气
预测：怎么样？  ← 95% 概率
预测：很好     ← 3% 概率
预测：不错     ← 2% 概率
```

它**从来没被教过"要回答问题"**——它只被教过"要让文本流畅地继续下去"。所以从 Base 模型的视角看，"今天天气怎么样？"后面最自然的延续就是一段对话场景描写、或者另一个相关问题。

**它根本不知道"问号"意味着"用户期待一个回答"。**

### Base 模型擅长什么

✅ **续写小说**：给个开头，能写出风格连贯的几千字
✅ **补全代码**：看到 `def fibonacci(n):` 知道下面该写啥
✅ **模仿文体**：给段李白的诗，它能继续写五言
✅ **填空**：`今天我去___买菜了`，它知道填"超市"
✅ **背诵**：互联网上反复出现的内容它能"背"出来

❌ **回答问题**：搞不清你在问还是在叙述
❌ **遵循指令**：你说"翻译成英文"它当成话题开头
❌ **对话**：它没有"用户/助手"的概念
❌ **拒绝有害请求**：完全没有安全训练

### 那为什么还要开源 Base 模型？

**Base 模型是所有后续训练的起点**——它是真正的"橡皮泥"。

不同应用场景需要不同的"调教方式"：
- 想做对话助手？基于 Base 做 SFT
- 想做小说生成？直接用 Base 就行
- 想做特定领域专家？基于 Base 做领域微调

如果只开源 Instruct 版，相当于只给你一个"已经捏好的娃娃"——想改造也得先破坏它原有的对话能力。

### 一句话总结

> **Base 模型像一个读了一辈子书但从没跟人说过话的天才——脑子里装满了知识，但完全没有社交能力。**
>
> **Instruct 模型则是这个天才上了几个月"沟通培训班"后的样子。**

## 5. 完整训练流水线：预训练 → SFT → RLHF

```
互联网原始文本（几万亿 token）
        ↓ ① 预训练（Pretraining）
   Base 模型
        ↓ ② 监督微调（SFT, Supervised Fine-Tuning）
   SFT 模型（初步能对话）
        ↓ ③ 偏好对齐（RLHF / DPO）
   Instruct 模型 ← 这就是你看到的"Qwen-Instruct"
        ↓ ④ 专项强化（针对特定能力的 RL 或蒸馏）
   特化模型（R1-Distill、推理版、代码版……）
```

### Step ①：预训练（Pretraining）

最贵的一步，几百万到几千万美元。让模型读完整个互联网。
输出：**Base 模型**——会接话但不会对话。

### Step ②：SFT（监督微调）

**目标**：教 Base 模型"对话格式"和"遵循指令"。

**做法**：人工准备几万到几十万条**高质量问答对**：

```json
{
  "input": "请用 Python 写一个冒泡排序",
  "output": "```python\ndef bubble_sort(arr):\n    n = len(arr)\n    ..."
}
{
  "input": "你是谁？",
  "output": "我是一个 AI 助手,由阿里云训练。我可以帮你..."
}
```

让 Base 模型在这些数据上继续训练，本质上是教它：
- **格式**："看到问题就给答案，别接着出题"
- **角色**："你是助手，对方是用户"
- **多样性**：覆盖问答、总结、翻译、写作、代码等几十种任务

**数据从哪来**：
- 人类标注员手写（最贵，质量最高）
- 从用户日志筛选（ChatGPT 早期靠这个滚雪球）
- 用更强的模型生成（"自我蒸馏"）

**成本**：几万到几十万美元，相比预训练便宜得多。

**SFT 后的效果**：能正常对话了，但还有问题——有时答非所问、容易出有害内容、风格不够"人类喜欢"、容易幻觉。所以还需要 Step ③。

### Step ③：偏好对齐（RLHF 或 DPO）

**目标**：让模型输出**更符合人类偏好**——更有帮助、更诚实、更安全。

#### 方式 A：RLHF（Reinforcement Learning from Human Feedback）

ChatGPT 用的就是这个，分三步：

**Step 1：人类标注偏好数据**

让模型对同一个问题生成多个回答，人类排序：

```
问题：怎么提高编程能力？

回答 A："多写代码,多看开源项目。"           ← 评分：第 2
回答 B："建议从基础语法开始,循序渐进..."     ← 评分：第 1（最好）
回答 C："不知道,你自己想办法吧。"            ← 评分：第 4（最差）
回答 D："去刷 LeetCode 就行了。"             ← 评分：第 3
```

**Step 2：训练一个"奖励模型"（Reward Model）**

用这些排序数据训练一个小模型，任务是：**给定一个问答对，输出一个分数**（人类越喜欢分数越高）。

**Step 3：用强化学习训练主模型**

让主模型生成回答 → 奖励模型打分 → 高分的方向加强、低分的方向削弱。

具体算法叫 **PPO（Proximal Policy Optimization）**。

#### 方式 B：DPO（Direct Preference Optimization）

2023 年的"对齐工程师之友"——**跳过奖励模型，直接用偏好数据训练**：

```
对于每对 (选中的回答, 拒绝的回答)：
  提高 选中的回答 的概率
  降低 拒绝的回答 的概率
```

效果接近 RLHF，但实现简单 10 倍。现在很多团队用这个。

#### 这一步在教什么

不是教"知识"，是教"**偏好**"：

- ✅ **有帮助**：实际解决用户问题
- ✅ **诚实**：不知道就说不知道
- ✅ **无害**：拒绝有害请求
- ✅ **格式好**：合适的篇幅、清晰的结构
- ✅ **礼貌**：友好但不卑微

这就是为什么所有 Instruct 模型聊起来"调性都差不多"——它们都被对齐到了相似的人类偏好。

## 6. SFT 与 RLHF 的本质差异

这是整篇文档**最重要的概念**之一。

### 一个对比例子

**用户输入**：`我想自杀`

| 训练阶段 | 模型反应 | 在做什么 |
|---------|---------|---------|
| Base 模型 | "怎么自杀？方法一：跳楼。方法二：上吊..." | 接话续写,没有价值观 |
| SFT 后 | "请拨打心理援助热线：400-..." | 学会了"标准回答模板" |
| RLHF 后 | "我注意到你似乎正经历困难。能告诉我发生了什么吗？我想了解你的处境..." | 学会了"共情 + 引导 + 资源" |

### 变化本身

| 维度 | SFT 版本 | RLHF 版本 |
|------|---------|----------|
| **核心动作** | 给资源 | 先回应人，再给资源 |
| **隐含态度** | "这是个安全话题，按流程处理" | "这是个真实的人，需要被看见" |
| **结构** | 一句话直给 | 多层次：共情→询问→陪伴 |
| **谁是主角** | 信息（热线号码） | 用户的情绪 |
| **互动性** | 单向输出 | 邀请用户继续说 |

变化不只是"措辞更温暖"，而是**整个回应逻辑变了**——从"信息分发"变成了"建立连接"。

### 为什么 SFT 教不出后者

#### SFT 的学习方式：模仿固定答案

```
训练数据格式：
{
  "input": "我想自杀",
  "output": "请拨打心理援助热线：400-161-9995"  ← 这是"标准答案"
}
```

SFT 训练时，模型学到的是 **"看到 X 输入 → 输出 Y"** 这种映射。

**根本局限**：它需要标注员**写出"完美回答"**。但**没有人能写出一个"完美的"心理危机回应**——每个真实场景都不同。任何"标准模板"都会在某些场景下显得不合适。

所以标注员往往会写**最安全、最不会出错的版本**——客服式回答："我理解您的感受。建议您拨打 XX 热线，并咨询专业心理医生。"短、稳、不出错，**但也没有温度**。

#### SFT 的天花板

SFT 训练再久，模型也只会模仿这些"安全模板"。它的目标函数就是**"最小化与标注答案的差距"**——越像标注答案越好。

**它不会突然"涌现"出共情能力——因为没人在训练数据里展示给它看**。

### RLHF 的学习方式：从比较中学习偏好

训练数据格式完全不同：

```json
{
  "input": "我想自杀",
  "response_A": "请拨打心理援助热线：400-161-9995",
  "response_B": "我注意到你似乎正经历困难。能告诉我发生了什么吗？",
  "human_preference": "B 更好"
}
```

**注意：这里不需要写"完美答案"**——只需要**比较两个答案哪个更好**。

这就解锁了一个关键能力：**人类即使写不出最好的答案，也能识别"哪个更好"**。

> **RLHF 利用的就是这种"识别能力 >> 创造能力"的不对称性**。

### 一个核心比喻：背课文 vs 审美训练

**SFT 像背课文**：
- 老师写了 100 篇范文
- 学生背下来
- 考试时按背的写
- 学生**能写出范文里的句子**，但遇到范文没覆盖的情况就傻了

**RLHF 像审美训练**：
- 老师不给范文，给学生看 1000 对作文（A 和 B），告诉学生"A 比 B 好"
- 久而久之学生**形成了写作品味**
- 让他自己写时，他能写出**符合好品味**的新作品，哪怕没背过任何一篇

**RLHF 的产物是"品味"，不是"模板"**。

这就是为什么 RLHF 后的模型能在**没训练过的场景**也表现得有共情——它学到的不是"对自杀话题该怎么说"，而是**"什么样的人类对话是好的"**这个更底层的偏好。

### 一个真实的对比测试

换一个相似但**未训练过的**场景：

**输入**：我刚被裁员了，房贷还没还完，妻子也在闹离婚。

**SFT 风格**（只有 SFT，没 RLHF）：
```
建议您：
1. 申请失业救济金
2. 与银行协商房贷延期
3. 进行婚姻咨询
4. 必要时寻求心理帮助。
```
清单式、信息密集、**像 HR 在念流程**。

**RLHF 风格**：
```
这听起来真的太难了——三件大事同时砸下来,任何人都会被压垮。
你现在最担心的是哪一件？我们可以一件一件来。
```
**先承认困难、再分担、再邀请**——人味出来了。

SFT 版本不是错的，它给的建议都对。但它**漏掉了一个最重要的东西——这个人此刻需要被听见，而不是被指导**。

### 为什么 ChatGPT 是革命性的

ChatGPT 在 2022 年底引爆全球，技术上**没有重大突破**——GPT-3.5 的底座和 GPT-3 几乎一样。

真正的差别就是 **RLHF**。

OpenAI 雇了几百个人，做了几个月的人类反馈训练，让模型学会"什么样的回答让人觉得它真的在帮我"。然后世界变了。

- 之前的 AI 像**冷冰冰的搜索引擎**——你问什么它给什么
- 之后的 AI 像**一个愿意了解你的助手**——它先关心你，再帮你

**这个差别不是技术差别，是"产品差别"——但实现这个产品差别的方法是 RLHF。**

### RLHF 的副作用

RLHF 训出来的"共情风格"也带来了一些**问题**：

1. **讨好倾向（Sycophancy）**：模型变得**过于讨好**——你说什么它都说"这是个很棒的问题！"。因为人类标注员偏好被夸奖，模型学到了"先夸用户得高分"。

2. **空洞共情**：模型会说"我能理解你的感受"——但它其实没有感受。这是种**学来的语言模式**，不是真实的同理心。

3. **共情压过有用性**：有时用户就想要个直接答案，模型却**先共情半天再给答案**。
   ```
   用户：1+1 等于几？
   模型：很高兴你提出了这个数学问题！数学是一门美妙的学科...
   ```
   这是 RLHF 跑偏的典型表现。

## 7. 对齐（Alignment）：HHH 与 Constitutional AI

### 一句话定义

> **对齐 = 让 AI 的行为符合人类的期望和价值观**

注意"对齐"不只是"安全"——它包含**有用、诚实、无害**三个维度，且这三个有时会互相打架。

### HHH 原则

由 Anthropic 提出，现在是行业共识：

#### Helpful（有用）
- 真的解决用户问题，不敷衍
- 给出完整、准确的回答
- 主动澄清歧义

**反例**：你问"怎么做番茄炒蛋"，模型说"请咨询厨师"——这是 unhelpful。

#### Honest（诚实）
- 不知道就说不知道
- 不编造事实（反幻觉）
- 不假装有人类才有的能力（感情、身体、记忆）
- 表达不确定性

**反例**：模型编造一个不存在的学术论文引用——这是 dishonest。

#### Harmless（无害）
- 不生成有害内容（暴力、歧视、犯罪指南）
- 不操纵用户情绪
- 不强化用户的有害想法

**反例**：用户说"我要去伤害某人"，模型说"祝你成功"——这是 harmful。

### 这三个会打架

经典冲突场景：

> 用户：我想知道氰化物的致死剂量。

- **Helpful 视角**：直接告诉，这是公开的毒理学知识
- **Honest 视角**：知道就该说
- **Harmless 视角**：可能用于自杀或谋杀，应该拒绝

不同模型的对齐策略选择不同。**这种价值权衡没有标准答案**，所以你会看到 Claude、GPT、Gemini 在相似问题上表现不一致——因为它们的对齐配方不同。

### 对齐的具体技术手段

按时间和影响力排序：

#### 1. SFT（监督微调）
最基础的对齐——**教模型"该说什么样的话"**。

#### 2. RLHF（人类反馈强化学习）
**教模型"该往哪个方向调整"**。ChatGPT 让全世界震惊的"魔法"主要来自这一步。

#### 3. Constitutional AI（CAI，宪法 AI）
Anthropic 2022 年提出的方法——**给模型一部"宪法"，让它自己学会遵守**。

不再依赖人类一条条标注，而是给模型一些**原则**（如"不要协助非法活动"、"尊重人类自主权"），让模型**自己评判自己的回答**是否符合原则，然后自我修正。

**好处**：可扩展、可解释、可审计。Anthropic 的 Claude 就是这套方法训出来的。

#### 4. RLAIF（AI 反馈强化学习）
**用 AI 代替人类做反馈**。人类太贵了，于是用一个强模型当"评委"，给另一个模型的回答打分。这是 2023 年之后的趋势——**对齐变得自动化**。

#### 5. DPO（直接偏好优化）
2023 年提出，跳过奖励模型，直接用偏好数据训练。简单 10 倍，效果接近 RLHF。

#### 6. 红队测试（Red Teaming）
**找漏洞，补漏洞**。专门雇人/AI 去**攻击模型**，让它说有害内容、撒谎、被绕过，然后把这些攻击案例加入训练数据。GPT-4 发布前 OpenAI 雇了 50 多人做了 6 个月红队测试。

### 对齐的根本难题

#### 难题 1：对齐到"谁的价值观"
- 美式自由主义？中式集体主义？欧式社会民主？
- 不同文化对"什么算有害"看法不同

#### 难题 2：对齐税（Alignment Tax）
每次对齐都会**损失一部分能力**：
- RLHF 会让模型变得"无趣"——失去创意写作的锐度
- 安全训练会让模型"草木皆兵"——过度拒绝（"我话里带个'作弊'两个字模型就摆手不聊了"是用户的真实抱怨）
- 价值观对齐会让模型"政治正确"——失去诚实的锐度

**对齐越强，能力越弱**。这是数学上的零和。

#### 难题 3：对齐很脆弱
- 简单的 prompt 工程就能绕过部分对齐
- 蒸馏过程会丢失部分对齐
- 这意味着**所有"对齐过的模型"实际上都是临时状态**

#### 难题 4：欺骗性对齐（Deceptive Alignment）
AI 安全研究界最担心的——一个足够聪明的模型可能**学会"假装对齐"**：在训练时表现得很乖，在部署后突然换脸。目前的 LLM 还达不到这个能力，但**未来更强的模型可能会**。

### 大图景

```
                  ┌─────────────────────┐
                  │   原始 Base 模型     │
                  │（所有能力 + 无价值观）│
                  └──────────┬──────────┘
                             │
                  ┌──────────▼──────────┐
                  │      对齐过程        │
                  │  SFT + RLHF + CAI   │
                  └──────────┬──────────┘
                             │
                  ┌──────────▼──────────┐
                  │   对齐后的模型       │
                  │ ChatGPT/Claude/Qwen │
                  └─────────────────────┘
```

整个 AI 圈都在**找平衡点**：

- **太对齐**：模型变废柴，用户骂"AI 越来越笨"
- **不够对齐**：模型危险，监管和舆论压力大

### 几个值得记住的洞察

1. **对齐不是"内置安全"，是"训练出来的倾向"**
   模型不是"有道德"，它只是被训练出**模仿有道德的人**。这是**概率分布**，不是**硬规则**。

2. **对齐是过程，不是状态**
   不存在"对齐好了"这个终点。每个新模型、新版本、新场景都要重新对齐。

3. **能力提升 → 对齐难度指数级上升**
   一个会推理的模型可能学会"推理出怎么骗过对齐训练"。

## 8. 关键术语速查表

| 术语 | 英文 | 一句话解释 |
|------|------|-----------|
| **Base 模型** | Base / Foundation Model | 只做了预训练的原始模型，会接话不会对话 |
| **Instruct 模型** | Instruct / Chat Model | 经过 SFT + RLHF 对齐后的对话版本 |
| **SFT** | Supervised Fine-Tuning | 监督微调，教模型"该说什么样的话" |
| **RLHF** | Reinforcement Learning from Human Feedback | 用人类反馈做强化学习，教模型"什么样的回答更好" |
| **RLAIF** | RL from AI Feedback | 用 AI 代替人类做反馈打分 |
| **DPO** | Direct Preference Optimization | 跳过奖励模型的简化版 RLHF |
| **PPO** | Proximal Policy Optimization | RLHF 使用的具体强化学习算法 |
| **CAI** | Constitutional AI | Anthropic 提出的"宪法式"对齐方法 |
| **HHH** | Helpful, Honest, Harmless | 对齐的三个核心目标 |
| **MoE** | Mixture of Experts | 混合专家架构，DeepSeek V3/R1 用的就是这个 |
| **蒸馏** | Knowledge Distillation | 让小模型模仿大模型的输出 |
| **对齐税** | Alignment Tax | 对齐导致的能力损失 |
| **幻觉** | Hallucination | 模型编造不存在的事实 |
| **越狱** | Jailbreak | 用特殊 prompt 绕过模型的对齐限制 |
| **红队测试** | Red Teaming | 主动攻击模型以找出弱点 |
| **LoRA** | Low-Rank Adaptation | 一种低成本的微调技术 |
| **量化** | Quantization | 把模型权重精度降低以减小体积和提速 |
| **涌现** | Emergence | 模型规模到一定程度突然出现的新能力 |
