# MoE 与现代 LLM 架构创新

> 整理自与 Cursor 的讨论。本文聚焦 **MoE 的本质特性（不止 offload）** 与 **2024-2026 现代 LLM 的八大架构创新方向**。

---

## 第一部分：MoE 深度解析

## 一、稠密模型 vs MoE 的本质区别

| | 稠密模型（Dense） | MoE 模型 |
|---|------------------|---------|
| 总参数 | 全部参与计算 | 只激活一部分专家 |
| 显存需求 | **必须全部装入** | 可以"分层装" |
| 例子 | Qwen2.5-Omni-7B | DeepSeek-VL2 27B (只激活 4.5B) |

---

## 二、MoE 的 8 大特性（按重要性排）

### 1️⃣ 稀疏激活 = "大模型的速度，小模型的成本"（最核心）

**这才是 MoE 的灵魂，offload 只是副产品。**

```
稠密 70B 模型：每个 token → 激活 70B 参数 → 算 70B
MoE 671B/37B：每个 token → 激活 37B 参数 → 只算 37B
```

**结果：** DeepSeek V3 总参 671B，但每 token 计算量 ≈ 37B 稠密模型。

带来的好处：

| 维度 | 稠密 70B | MoE 671B/37B |
|------|---------|-------------|
| 知识量 | 70B 级 | **671B 级** |
| 每 token 算力 | 70B 级 | **37B 级** |
| 训练成本 | 高 | 相对低 |
| 推理速度 | 慢 | 快 |

> **一句话：MoE 把"模型容量"和"计算成本"解耦了。**

### 2️⃣ 专家分工 / 涌现专业化

**MoE 不是平均分工，而是专家会"自己学会专业化"。**

研究观察到：
- 某些专家只激活在 **代码** 上
- 某些专家只激活在 **数学公式** 上
- 某些专家只激活在 **中文** 或 **日文**
- 某些专家只激活在 **某种风格的文本**（比如学术 vs 口语）

```
处理 "def solve(): ..." 时
  → 激活 [代码专家 #3, 缩进专家 #17, Python 专家 #42]

处理 "假设 x ∈ ℝ..." 时
  → 激活 [数学专家 #8, 符号专家 #21, 形式化专家 #31]
```

这有点像**人脑功能分区**——视觉皮层、语言区、运动皮层各管各的。

**实际意义：**
- 单个专家"学得更深"
- 不需要每个参数都"什么都懂一点"
- 提升整体上限

### 3️⃣ 容量扩展 = 解锁"万亿级"知识

**稠密模型扩到万亿参数，训练 / 推理都顶不住。MoE 是唯一可行路径。**

回顾今天的"大模型天花板"：

```
稠密极限：    Llama 3 405B    （已经是工程极限）
MoE 突破：    DeepSeek V3      671B / 激活 37B
              MiMo V2.5        310B / 激活 15B
              Qwen3.5-397B    397B / 激活 17B
              DeepSeek V4-Pro  1.6T / 激活 49B  ← 万亿俱乐部
              Kimi K2          ~1T  / 激活 32B
```

**为什么必须是 MoE？**

- 万亿稠密模型 = 训练算力翻倍、推理慢一倍、显存翻倍 → 商业上不划算
- 万亿 MoE = 知识容量翻倍，但推理还是几十 B 的成本 → 性价比飞起

**所以"未来所有顶级模型都会是 MoE"已经是行业共识。**

### 4️⃣ 路由器（Router）= MoE 的灵魂

Router 是个小神经网络，负责决定每个 token 该交给哪些专家：

```
token "Python" 进来
   ↓
Router 算分: [专家1: 0.9, 专家2: 0.1, 专家3: 0.7, ..., 专家64: 0.05]
   ↓
选 Top-K（比如 Top-2）: 专家1 + 专家3
   ↓
两个专家各自处理，加权合并 → 输出
```

#### Router 设计的演化

| 时代 | 做法 | 问题 |
|------|------|------|
| Mixtral 时代 | Top-2 静态路由 + 辅助损失平衡 | 经常专家"摆烂"或"过载" |
| DeepSeekMoE | **细粒度专家** + **共享专家** | 容量更大、专业化更强 |
| DeepSeek V3 | **辅助损失自由平衡**（无需辅助 loss） | 训练更稳，质量更高 |
| Qwen3.5 | Gated DeltaNet 混合 + MoE | 长上下文 + 高效路由 |

Router 设计直接决定 MoE 的天花板，这是各家**核心机密**。

### 5️⃣ 能源效率 = 数据中心降本利器

**同等智能水平，MoE 推理用电比稠密少一大截。**

直觉：30B 稠密 vs 30B-A3B MoE 同质量
- 稠密：每 token 算 30B 浮点运算
- MoE：每 token 算 3B 浮点运算
- **能耗差 10 倍**

这就是为什么 **2025-2026 年所有大厂都全面转向 MoE** —— 不是为了用户体验，是为了**电费**。

> 一个有趣事实：DeepSeek 之所以能在 GPU 受限的情况下做出 V3/V4，**就是因为 MoE 让他们用同样算力训出更大模型**。

### 6️⃣ 训练的优势与挑战

#### 优势
- **可以"模型并行"放进多台机器**（每台放几个专家）
- **数据效率高** —— 不同专家学不同分布
- **scaling law 更平滑** —— 加专家比加参数效率更高

#### 挑战
- **负载不均** —— 有的专家被疯狂调用，有的"摸鱼"。需要辅助损失或 router 设计来平衡。
- **专家崩溃**（Expert Collapse）—— 训练初期某些专家被"饿死"，永远学不到东西
- **通信开销** —— 多机训练时专家之间要传数据，吃带宽
- **模型容量利用率低** —— 实际可能只有 60-80% 的专家被有效使用

### 7️⃣ MoE 的"隐藏代价"（很多人忽略）

#### ❗ 显存占用 = 总参数（不是激活参数）

```
你以为：30B-A3B 只要 3B 的显存
实际上：还是要装 30B 的权重在某处！
        激活的是计算，不是装载
```

**所以 MoE 在显存上没省**，省的是：
- 计算（FLOPs）
- 内存带宽（每步只读取激活专家）

这就是为什么 12GB 显卡跑 35B-A3B 必须 offload 到内存——**装不下**。

#### ❗ "MoE Tax"（经验法则）

> **MoE 的总参数 ÷ 4-6 ≈ 等效稠密参数质量**

```
30B-A3B (MoE) ≈ 7-10B 稠密的质量水平
DeepSeek V3 671B/37B ≈ 100-150B 稠密的质量
Llama 4 Scout 109B/17B ≈ 30-40B 稠密的质量
```

**也就是说 MoE 不是"白嫖"——你用更多总参数换更少计算，但质量也打折。**

#### ❗ 量化更敏感

MoE 量化比稠密更难：
- 不同专家对量化敏感度不同
- 共享层（attention）和专家层（FFN）应该用不同精度
- Q4 量化在 MoE 上的损失通常大于稠密模型

这就是为什么 ik_llama.cpp 对 MoE 有专门优化。

#### ❗ 推理批处理效率低

- 稠密模型：所有 token 共享同一组权重，批处理效率高
- MoE 模型：不同 token 路由到不同专家，**批处理变碎**，GPU 利用率低

数据中心要做大量工程优化（Expert Parallelism、Token Choice）才能跑高效。

### 8️⃣ 现代 MoE 的工程创新

2024-2026 期间的几个关键突破：

| 创新 | 出处 | 解决什么 |
|------|------|---------|
| **Fine-grained experts**（细粒度专家） | DeepSeekMoE | 把大专家拆成更多小专家，专业化更深 |
| **Shared experts**（共享专家） | DeepSeekMoE | 留几个"通才"始终激活，处理共性知识 |
| **Auxiliary-loss-free**（无辅助损失平衡） | DeepSeek V3 | 直接靠路由器偏置实现负载均衡 |
| **Expert Parallelism** | Megatron / vLLM | 把不同专家放不同 GPU |
| **Speculative Decoding for MoE** | 多家 | 加速推理 |
| **MoE 量化（per-expert quant）** | ik_llama.cpp | 不同专家用不同精度 |
| **Selective Expert Offload** | KTransformers | 热门专家在 GPU，冷门在 CPU |

## 三、MoE 的"三级资源"全景

```
┌────────────────────────────────────────┐
│  💾 硬盘（SSD）                         │
│  必须装下完整权重：30B × 量化精度        │
│  例：Qwen3.5-35B-A3B Q4 ≈ 21 GB       │
│  ❌ 这部分省不掉                        │
└────────────────────────────────────────┘
              ↓ 加载到内存
┌────────────────────────────────────────┐
│  🧠 系统内存（RAM）                     │
│  装下完整权重 或 装下"非活跃专家"        │
│  - 全装：21 GB（最稳，速度快）          │
│  - 部分装：用 mmap 按需加载              │
└────────────────────────────────────────┘
              ↓ 调度到显存
┌────────────────────────────────────────┐
│  🎮 GPU 显存（VRAM）                    │
│  必装：共享层（Attention）+ 当前激活专家  │
│  可选：常用专家缓存                      │
│  - 全装：21 GB（要 24GB 显卡）          │
│  - 共享层 only：~3-5 GB                 │
└────────────────────────────────────────┘
```

### 三种部署模式对比

| 模式 | 硬盘 | 内存 | 显存 | 速度 | 适合 |
|------|------|------|------|------|------|
| **🥇 全显存** | 21 GB | 几乎不用 | 21+ GB | ⚡ 极快（50+ tok/s） | 24GB+ 显卡 |
| **🥈 混合（offload）** | 21 GB | 15-20 GB | 8-12 GB | 🐢 慢（5-15 tok/s） | 4070 这类 |
| **🥉 极限内存** | 21 GB | 21+ GB | 4-6 GB | 🐌 极慢（1-3 tok/s） | 没好显卡时硬上 |

### 4070 12GB + 32GB RAM 跑 Qwen3.5-35B-A3B Q4 的真实情况

```
启动时：
├─ 从硬盘读 21 GB 权重
├─ 加载到 32GB 内存（占用 ~22 GB）
└─ 共享层（~5 GB）拷贝到 12GB 显存

推理时（每个 token）：
├─ Router 决定激活哪些专家
├─ 专家权重从内存通过 PCIe 传给 GPU 计算
├─ 计算完丢弃临时数据
└─ 下一个 token 重复

瓶颈：PCIe 4.0 的 32 GB/s 带宽
结果：实测 0.5-2 tok/s（慢得不能用）
```

**这就是 MoE offload 看着诱人但实际不可用的原因** —— 不是显存不够，是**总线传输跟不上计算速度**。

### 几个常见误解澄清

#### ❓ "MoE 不是只算激活的部分吗？为什么还要装全部？"

因为**你不知道下一个 token 会用哪些专家**：

```
token "Python"  →  激活专家 [3, 17, 42]
token "数学"    →  激活专家 [8, 21, 31]
token "音乐"    →  激活专家 [5, 12, 38]
```

每个 token 路由结果不同，**所以 64 个专家必须随时待命**。

#### ❓ "能不能只下载用得上的专家？"

理论上可以（叫 Expert Pruning），但：
- 你不知道你**未来**会问什么问题
- 删掉某些专家会让模型在某些任务上变蠢
- 大多数模型不公开专家功能映射

**目前没有"按需下载"的成熟方案**，硬盘空间逃不掉。

#### ❓ "硬盘有了，是不是可以从硬盘直接 mmap 跑？"

可以，但**速度灾难**：

```
SSD 4.0：~7 GB/s
DDR5 内存：~50 GB/s
PCIe 5.0：~64 GB/s
GPU HBM：~1000+ GB/s
```

从 SSD 加载比内存慢 7 倍，比显存慢 100+ 倍。**实测从 SSD 跑 MoE：0.1-0.5 tok/s，看一个字眨一次眼。**

### 智能调度的最新进展（2025-2026）

#### KTransformers / ik_llama.cpp 的玩法

```
观察：实际推理中，部分专家被频繁激活，部分很少用
策略：
  - 热门专家（前 30%）→ 常驻 GPU
  - 中等专家（中 40%）→ 内存待命
  - 冷门专家（后 30%）→ 内存待命
按需调度 + 智能缓存 + 预测路由
```

**效果**：消费级硬件跑 MoE 速度从 1 tok/s 提升到 5-10 tok/s（仍不如全显存，但勉强可用）。

#### Expert Caching

```
LRU 缓存最近用过的专家
路由器有"温度"机制，倾向重用热门专家
某些工程 trick 能减少专家切换次数
```

## 四、MoE 特性总结表

| 特性 | 是优势? | 影响 |
|------|--------|------|
| 稀疏激活（速度） | ✅ 大优势 | 推理快、训练快 |
| 容量解耦（知识） | ✅ 大优势 | 万亿参数可行 |
| 专家专业化 | ✅ 优势 | 质量提升 |
| 能源效率 | ✅ 优势 | 大厂降本 |
| Offload 友好 | ✅ 小优势 | 消费级勉强能跑 |
| 显存占用 | ❌ **没优势** | 跟总参数一致 |
| MoE Tax | ❌ 劣势 | 总参打折 4-6 倍 |
| 量化敏感度 | ❌ 劣势 | 损失更大 |
| 批处理效率 | ❌ 劣势 | 工程复杂 |
| 训练稳定性 | ⚠️ 挑战 | 需要技巧 |
| 微调难度 | ⚠️ 挑战 | 比稠密难 |

### 一图总结

```
                  MoE 资源占用本质
        ┌─────────────────────────┐
        │  容量（参数总量）         │  ←  装在哪都行，但必须装
        │  = 硬盘必备 + 内存/显存   │
        └─────────────────────────┘
        ┌─────────────────────────┐
        │  计算量（每 token FLOPs）│  ←  这才是稀疏的、被 MoE 优化的
        │  = 激活专家的算力         │
        └─────────────────────────┘

  关键洞察：
  MoE 节省的是"算力"和"带宽"
  从来没节省过"存储容量"
```

## 五、MoE vs 人脑（一个有意思的视角）

| 特性 | MoE 模型 | 人脑 |
|------|---------|------|
| 神经元总数 | 几千亿参数 | 860 亿神经元 |

## 六、给消费级用户的实操结论

### ✅ 什么时候选 MoE
- 你有**充足显存**（24GB+）→ MoE 比稠密快得多
- 你需要**广博知识**而非深度推理
- 你想用**最新一代模型**（基本都是 MoE）

### ✅ 什么时候选稠密
- 你**显存吃紧**（12GB 这种）→ 稠密更划算
- 你需要**深度推理**（数学/代码）→ 稠密+大参数更稳
- 你要**长上下文连续推理** → 稠密更稳定

### 💡 具体建议

```
12GB 显卡 → 稠密 9B（Qwen3.5-9B）依然是甜点
升级到 24GB（如 4090） → 切换到 MoE 35B-A3B
```

### 一句话心智模型

> **MoE = 一个大公司有 64 个专家部门，每次开会只叫 6 个相关的来，省时省钱但办公楼一样大。**
>
> **稠密模型 = 一个全才团队，每次都是全员上阵，反应快但养不起太多人。**
>
> **未来万亿级模型一定是 MoE，但 13B 以下小模型仍然是稠密的天下。**

# 第二部分：现代 LLM 架构的"七大流派"

MoE 只是 **"如何让模型变大"** 这一个方向。AI 架构创新远不止于此。

```
                ┌─ 1. 注意力替代派    （干掉 Attention 本身）
                ├─ 2. 注意力改良派    （让 Attention 更高效）
                ├─ 3. 稀疏激活派      （MoE 在这里）
                ├─ 4. 长期记忆派      （RAG / 状态空间）
现代 LLM 架构 ─→├─ 5. 测试时计算派    （让模型"想得更久"）
                ├─ 6. 多模态融合派    （怎么消化非文本）
                ├─ 7. 解码加速派      （怎么吐字更快）
                └─ 8. 范式革命派      （彻底换路子）
```

---

## 一、注意力替代派 —— "干掉 Attention 本身"

**问题**：Transformer 的 self-attention 是 **O(n²)** 复杂度，长上下文极贵。

### 主要架构

| 架构 | 复杂度 | 代表模型 | 现状 |
|------|-------|---------|------|
| **Mamba / SSM**（状态空间模型） | O(n) | Mamba、Mamba-2、Codestral Mamba | 已有可用模型 |
| **RWKV** | O(n) | RWKV v6 / v7 | 中文社区活跃 |
| **Hyena** | O(n log n) | StripedHyena | 较学术 |
| **Linear Attention** | O(n) | Performer、Linear Transformer | 老路线 |
| **Gated DeltaNet** | O(n) | **Qwen3.5 用的就是这个** | 已上车主流 |

### 关键洞察

```
Transformer：每个 token 都看所有过去 → 精确但慢
SSM/Mamba：  压缩过去成"状态" → 快但会"忘"
```

### 混合派（Hybrid）—— 当前主流

**纯 Mamba 长记性差，纯 Transformer 太贵 → 混合是答案。**

| 混合模型 | 配方 |
|---------|------|
| **Jamba** | Mamba + Transformer + MoE |
| **Qwen3.5** | **Gated DeltaNet + 标准 Attention 混合** |
| **Samba**（微软） | Sliding Window Attention + Mamba |
| **Zamba** | Mamba + Attention |

> **2025-2026 的新模型几乎全是混合架构**。纯 Transformer 的时代正在结束。

---

## 二、注意力改良派 —— "让 Attention 更高效"

不替代 Attention，而是优化它。这条路线**回报最高，落地最快**。

### 关键创新

| 技术 | 节省什么 | 代表 |
|------|---------|------|
| **MQA**（Multi-Query Attention） | KV cache 显存 | 老 Llama |
| **GQA**（Grouped-Query Attention） | KV cache 显存 | Llama 3、Qwen 系列 |
| **MLA**（Multi-head Latent Attention） | KV cache **大幅压缩** | **DeepSeek V2/V3/V4 杀手锏** |
| **Sliding Window Attention** | 远端不算 | Mistral、Phi |
| **Flash Attention v3** | 不是省，是"算得更快" | 几乎所有现代模型 |
| **Compressed Sparse Attention (CSA)** | 稀疏化注意力 | DeepSeek V4 |
| **DeepSeek Sparse Attention (DSA)** | 智能稀疏 | DeepSeek V4 |

### MLA 是真神器（DeepSeek 的核心壁垒）

```
普通 Attention KV cache：每个 token 几 MB
MLA 压缩后：             每个 token 几 KB
节省比例：              10-100 倍
```

**DeepSeek V4 能做到 1M 上下文且推理还便宜，主要靠 MLA。**

---

## 三、稀疏激活派（MoE）—— 见第一部分

略，前面讲过。**关键：解耦"参数容量"和"计算成本"。**

## 四、长期记忆派 —— "外挂大脑"

**问题**：模型参数装不下所有知识，怎么办？

### 方向

| 方法 | 思路 | 现状 |
|------|------|------|
| **RAG**（检索增强） | 用向量数据库外挂知识 | **生产环境标配** |
| **In-Context Learning** | 把知识塞进提示词 | 简单但贵 |
| **长上下文**（128K-10M） | 直接装下整本书 | Gemini 1.5、Qwen3.5 主推 |
| **持续学习** | 模型边用边学 | 学术阶段 |
| **Memory-augmented Networks** | 显式外挂记忆模块 | 学术阶段 |
| **Episodic Memory** | 仿人脑情景记忆 | 前沿研究 |

### 趋势：长上下文 + RAG 双路并行

```
2023：8K 上下文，靠 RAG 救场
2024：128K-1M 上下文，能装一本书
2025-2026：262K-10M 已成标配，但 RAG 仍不可替代
```

> **为什么不能只靠长上下文？** 检索精度、成本、新鲜度（实时数据）—— RAG 永远有市场。

## 五、测试时计算派 —— "让模型想得更久"

**这是 2024-2026 最大的范式转变。**

```
传统：训练时投入大量算力 → 推理时一闪而过给答案
新范式：训练适度 + 推理时让模型"思考几秒到几分钟" → 答案更靠谱
```

### 代表

| 模型 | 思路 |
|------|------|
| **OpenAI o1 / o3 / o4** | 把"思维链"内化到模型 |
| **DeepSeek R1** | 同上，开源版本 |
| **Qwen QwQ / Qwen3.5 Thinking** | 同上 |
| **Claude Sonnet Extended Thinking** | 可控的思考时长 |
| **AlphaGeometry** | 神经+符号搜索 |

### 关键洞察

```
扩大模型 1 倍 = 提升能力 X%
让模型多思考 1 倍 = 提升能力 Y%

研究发现：在某些任务上，Y > X
也就是说"让 7B 模型多想 10 秒" > "用 70B 模型秒答"
```

**所以 DeepSeek-R1-Distill-7B 能在数学题上吊打 Llama 3 70B。**

## 六、多模态融合派 —— "怎么消化非文本"

### 三代演化

| 代际 | 做法 | 例子 | 缺点 |
|------|------|------|------|
| **第一代：拼接** | 文本 LLM + 视觉编码器 + 适配器 | LLaVA、Qwen-VL v1 | 多模态对齐差 |
| **第二代：统一 token** | 把图像/音频也变成 token | Chameleon、Janus | 训练难 |
| **第三代：原生融合**（Early Fusion） | 训练时所有模态共同学习 | **Qwen3.5、Llama 4、MiMo V2.5、GPT-4o** | 当前主流 |

### 输入和输出的差异

| | 输入 | 输出 |
|---|------|------|
| **理解** | 文本/图像/视频/音频 | 文本 |
| **生成** | 文本 | 文本/图像/视频/音频 |

**理解端**已经"原生统一"，**生成端**仍在拼接（LLM + 扩散模型）。

> **下一个里程碑**：原生输出图像 / 视频的统一模型，目前 GPT-4o 部分实现，开源还没真正做到。

---

## 七、解码加速派 —— "怎么吐字更快"

不改架构，只改推理过程。

### 核心技术

| 技术 | 思路 | 加速 |
|------|------|------|
| **Speculative Decoding** | 小模型先猜，大模型验证 | 2-3x |
| **Multi-Token Prediction (MTP)** | 一次预测多个 token | 1.5-2x |
| **Lookahead Decoding** | 并行猜测 + 验证 | 2x |
| **Medusa / EAGLE** | 多头并行预测 | 2-3x |
| **Continuous Batching** | 不同请求混合处理 | 4-10x（吞吐量） |
| **PagedAttention** | KV cache 像虚拟内存一样分页 | 显存利用率 ↑↑ |
| **Flash Attention v3** | 算子级优化 | 2x |

### 工程趋势

**vLLM、SGLang、ExLlamaV2** 这些推理引擎本身就是"加速派"的产物。**MTP 已经被 DeepSeek V3/V4 内化进模型架构** —— 不是事后优化，而是训练时就考虑。

---

## 八、范式革命派 —— "彻底换路子"

激进派们在挑战 Transformer 本身。

### 🌊 扩散 LLM（Diffusion Language Model）

```
传统 LLM：自回归（一个 token 一个 token 蹦）
扩散 LLM：一次性生成整段，多步去噪
```

代表：
- **Mercury**（Inception Labs，2025）—— 第一个商用扩散 LLM
- **LLaDA** —— 开源扩散语言模型

**优势**：可以并行生成（理论上比 GPT 快 10 倍）、双向上下文
**劣势**：质量还差点意思

### 🧠 JEPA / 世界模型（Yann LeCun 学派）

```
不预测下一个 token，而是预测下一个"潜在状态"
更接近人类认知方式
```

代表：
- **V-JEPA**（视频世界模型）
- **DINO** 系列

**目标**：让 AI 真正"理解"物理世界，而不是"模式匹配文本"。

### ⚡ 神经形态计算 / 脉冲神经网络（SNN）

模仿大脑的脉冲发放，**理论能效是 Transformer 的 100 倍**。代表：英特尔 Loihi、IBM TrueNorth、Spiking-LLM 学术尝试。**离实用还远**。

### 🌀 Liquid Foundation Models（液态网络）

MIT 团队基于"液态时间常数"的连续时间神经网络。代表：**Liquid AI 公司**的 LFM-1B / 3B / 7B / 40B 系列（2024-2025）。**特点**：极小模型达到大模型效果，推理极省。

### 🧬 Test-Time Training（推理时训练）

模型推理时还在自我调整，每个用户 / 任务都"个性化"一下。代表：**TTT 论文（2024）**、部分 Anthropic 研究。

## 一句话总结

> **MoE 解决"如何变大"，但 LLM 进化是多线作战：注意力优化（MLA）、记忆增强（RAG / 长上下文）、测试时计算（Thinking）、原生多模态、解码加速（MTP）—— 这些方向各自独立又互相组合，构成了 2026 年的现代 LLM。**
