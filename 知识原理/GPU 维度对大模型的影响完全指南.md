## 1. 核心结论速览

**对 LLM 推理来说，GPU 维度的重要性排序：**

```
1. 显存容量    ← 决定能不能跑（绝对硬限制）
2. 显存带宽    ← 决定单用户聊天多快（速度上限）
3. 计算算力    ← 决定 prompt 处理速度 + 并发能力
4. 精度支持    ← 决定能榨出多少性能
5. 缓存大小    ← 决定带宽利用率
6. PCIe 通道  ← 多卡或 CPU 卸载时影响
7. 互联带宽    ← 多卡场景才有意义
```

**一句话总结**：跑 LLM 像把一本厚书的每一页搬到桌上读一遍。**算力是你眼睛读字的速度（很快）**，**带宽是你伸手拿书页的速度（慢，是真瓶颈）**，**显存是你桌子的大小（决定书能不能完全摊开）**。

## 3. 各维度深度解析

### 3.1 显存容量（VRAM Capacity）

**它是什么**：GPU 上专属的高速内存大小，模型权重和 KV cache 都要装在这里才能跑得快。

**对 LLM 的影响**：

| 影响项         | 说明                            |
| ----------- | ----------------------------- |
| **能不能跑该模型** | 模型必须 ≤ 显存（否则要卸载到内存，速度暴跌 10 倍） |
| **能开多大上下文** | KV cache 占显存，上下文越长占用越多        |
| **能不能并发**   | 多个请求 = 多份 KV cache            |
| **能用什么量化**  | 显存大可以用 Q8/FP16，显存小被迫用 Q4/Q3   |

**显存够不够的判断公式**：

```
模型实际占用 = 模型权重 + KV cache + 系统开销
            ≈ 模型大小 × 1.2 + 上下文长度 × 0.0001 × 模型大小
```

举例：14B 模型 Q4（9GB），开 8K 上下文：
```
9GB × 1.2 + 9GB × 0.8 = 10.8 + 7.2 ≈ 显存中至少 18GB
```
（数字仅为粗略估算，实际看模型架构）

**结论**：显存是**最硬的硬限制**。差 1GB 都跑不了，差 100GB 跟差 1GB 没区别。

---

### 3.2 显存带宽（Memory Bandwidth）

**它是什么**：每秒能从显存往计算单元搬运多少数据。

**对 LLM 的影响**：**直接决定单用户推理的速度上限**。

**核心原理**：每生成一个 token，模型要把全部权重从显存读到计算单元里走一遍。

**速度上限公式**：

```
理论最大速度 (token/s) = 显存带宽 / 模型实际占用
```

**实际计算示例**（14B Q4 模型，9GB）：

| GPU | 带宽 | 理论上限 | 实际速度 |
|-----|------|---------|---------|
| RTX 3060 | 360 GB/s | 40 tok/s | 30-35 tok/s |
| **RTX 4070** | **504 GB/s** | **56 tok/s** | **40-50 tok/s** |
| RTX 4090 | 1008 GB/s | 112 tok/s | 80-95 tok/s |
| RTX 5090 | 1792 GB/s | 200 tok/s | 150-180 tok/s |
| H100 | 3000 GB/s | 333 tok/s | 250-280 tok/s |

**关键认知**：**带宽是跑 LLM 的天花板，无论算力多强都打不破**。这就是为什么二手 3090（带宽 936GB/s）比新的 4070（504GB/s）跑 LLM 快得多。

---

### 3.3 计算算力（Compute Power）

**它是什么**：GPU 每秒能做多少次浮点运算（TFLOPS = 万亿次/秒）。

由以下因素决定：

#### 3.3.1 计算单元数量

- **CUDA 核心数**（通用工人）
  - 4070：5888 个
  - 4090：16384 个
- **Tensor 核心数**（AI 专用工人，更重要）
  - 4070：184 个第 4 代
  - 4090：512 个第 4 代
  - 5090：680 个第 5 代

> LLM 推理 90% 的工作交给 Tensor Core 做，CUDA 数仅供参考。

#### 3.3.2 频率

- 4070 Boost：2475 MHz
- 4090 Boost：2520 MHz
- 频率高 ≠ 算力高，**架构代际差异影响更大**

#### 3.3.3 架构代际

| 架构 | 代表卡 | 同核心数性能（相对） |
|------|--------|--------------------|
| Turing | RTX 20 系 | 1.0× |
| Ampere | RTX 30 系 | 1.5× |
| Ada Lovelace | RTX 40 系 | 2.0× |
| Blackwell | RTX 50 系 | 3.0× |

**对 LLM 的影响**：

| 任务 | 算力影响程度 |
|------|------------|
| **单用户聊天（短 prompt）** | ⭐ 几乎无影响（带宽是瓶颈） |
| **长 prompt 处理（首 token 延迟）** | ⭐⭐⭐⭐⭐ 决定性影响 |
| **并发请求** | ⭐⭐⭐⭐ 用户越多越重要 |
| **训练 / 微调** | ⭐⭐⭐⭐⭐ 决定性影响 |

**示例对比**（处理 5000 token 长 prompt）：

| GPU | 首 token 延迟 |
|-----|--------------|
| 4070 | 2-3 秒 |
| 4090 | 0.8-1 秒 |
| H100 | < 0.3 秒 |

### 3.4 数据精度支持

**它是什么**：GPU 原生支持哪些数据格式（FP32 / FP16 / BF16 / FP8 / FP4 / INT8 / INT4）。

**精度越低，同样硬件能跑出的算力越高**：

| 精度 | 4090 算力 | H100 算力 | 5090 算力 |
|------|----------|----------|----------|
| FP32 | 82.6 | 67 | ~100 |
| FP16/BF16 | 330 | 989 | 838 |
| **FP8** | **660** | **1979** | **1676** |
| **FP4** | 不支持 | 不支持 | **3352** |
| INT8 | 660 | 1979 | 1676 |

**对 LLM 的影响**：

- **量化模型推理**：模型用什么精度，硬件原生支持就快，不支持就要"模拟"，速度大打折扣
- **新模型用新精度**：GPT-OSS 用 MXFP4，跑在 5090 上比 4090 快一倍
- **训练精度选择**：BF16 训练已成标准，FP8 训练前沿（DeepSeek V3 就是 FP8 训的）

**架构 × 精度支持表**：

| 架构 | 代表卡 | 原生支持 |
|------|--------|---------|
| Pascal | GTX 10 系 | FP32 |
| Volta | V100 | FP32, FP16 |
| Turing | RTX 20 系 | + INT8 |
| Ampere | RTX 30 系, A100 | + BF16, INT4 |
| Ada | **RTX 40 系（你的）** | + **FP8** |
| Hopper | H100/H200 | + FP8（强化） |
| Blackwell | RTX 50 系, B200 | + **FP4** |

---

### 3.5 缓存大小（L2 Cache）

**它是什么**：显存和计算核心之间的缓冲区，越大越能减少访问显存的次数。

**Ada 架构（40 系）做了一次大跃进**：

| GPU | L2 缓存 |
|-----|--------|
| RTX 3090 | 6 MB |
| RTX 4070 | 36 MB（6 倍） |
| RTX 4090 | 72 MB（12 倍） |
| RTX 5090 | 96 MB |

**对 LLM 的影响**：

- 缓存大 = 减少访问显存次数 = **实际带宽利用率更高**
- 这就是为什么 4090 实际带宽利用率比纸面 1008 GB/s 更高
- 长上下文场景下，KV cache 复用率高，大缓存优势明显

**注意**：缓存影响是"放大器"，本身不能突破带宽上限，但能让你更接近上限。

---

### 3.6 PCIe 通道（PCIe Bandwidth）

**它是什么**：CPU 与 GPU 之间数据传输的"桥梁"宽度。

| PCIe 版本 | 全双工带宽（x16） |
|----------|------------------|
| PCIe 3.0 | 16 GB/s |
| PCIe 4.0 | 32 GB/s |
| PCIe 5.0 | 64 GB/s |

**对 LLM 的影响**：

| 场景 | PCIe 影响 |
|------|----------|
| 全 GPU 推理（模型完全在显存） | ⭐ 几乎无影响 |
| **CPU 卸载推理** | ⭐⭐⭐⭐ 是次要瓶颈 |
| **多卡推理（无 NVLink）** | ⭐⭐⭐⭐⭐ 关键瓶颈 |
| 模型加载时 | ⭐⭐⭐ 影响首次启动速度 |

**关键认知**：单卡纯 GPU 推理时，PCIe 几乎不重要。一旦做 CPU 卸载或多卡，PCIe 立刻成为限速器。

---

### 3.7 多卡互联（NVLink）

**它是什么**：NVIDIA 数据中心卡专属的高速 GPU 间互联技术，远超 PCIe。

| 互联方式 | 带宽 |
|---------|------|
| PCIe 5.0 x16 | 64 GB/s |
| NVLink 4 (H100) | 900 GB/s |
| NVLink 5 (B200) | 1800 GB/s |

**对 LLM 的影响**：

- **消费卡（4090/5090）：完全没有 NVLink**，多卡只能走 PCIe
- 数据中心卡 NVLink 让多张 H100 像一张超大 GPU 工作
- 这是 H100 跑 671B 模型不爆显存的关键

**对消费用户**：你不会用到，了解就行。

## 4. 维度 × LLM 能力 影响矩阵

### 4.1 不同 LLM 任务对应的关键维度

| LLM 任务 | 第一关键 | 第二关键 | 第三关键 |
|---------|---------|---------|---------|
| **单用户聊天速度** | 显存带宽 | 缓存 | 算力 |
| **首 token 延迟** | 算力 | 缓存 | 带宽 |
| **能跑多大模型** | 显存容量 | 内存容量 | PCIe（卸载时） |
| **能开多长上下文** | 显存容量 | KV量化能力 | 缓存 |
| **多用户并发** | 算力 | 显存容量 | 带宽 |
| **训练 / 微调** | 算力 | 显存容量 | NVLink（多卡） |
| **跨卡协同** | NVLink | PCIe | 显存容量 |

### 4.2 单用户聊天场景的瓶颈分析

```
你输入问题 → [Prompt 处理：算力密集] → 出第一个 token
                                       ↓
                            [Token 生成：带宽密集] → 持续输出
```

**两个阶段瓶颈不同**：
- **Prompt 阶段**：算力强 = TTFT 短
- **生成阶段**：带宽大 = 速度快

**实际感受**：
- 短问题 → 主要看带宽（4070 vs 4090 差 2 倍速度）
- 长文档分析 → 算力影响首 token 时间（4070 vs 4090 差 3-5 倍延迟）

### 4.3 跑了过大模型时的崩溃链条

```
模型大小 vs 你的硬件
    │
    ├─ 模型 ≤ 显存的 80%        → ✅ 全 GPU 推理，最快
    │
    ├─ 模型 > 显存                → ⚠️ 自动 CPU 卸载
    │   └→ 速度从 50 tok/s 跌到 5-15 tok/s
    │
    ├─ 模型 > 显存 + 内存的 60%  → 🔴 系统启用硬盘 swap
    │   └→ 速度跌到 0.1-0.5 tok/s（不可用）
    │   └→ SSD 寿命被疯狂消耗
    │
    └─ 模型 > 显存 + 内存         → 💀 OOM 报错或系统崩溃
```

**哪个硬件先撑不住（按场景）**：

| 场景 | 第一个撑不住的 |
|------|--------------|
| 全 GPU 推理 | 几乎不会撑不住 |
| 模型刚超显存 | **显存** → 触发卸载 |
| 中等卸载 | **内存带宽** → 速度慢但能用 |
| 大量卸载 | **内存容量** → OOM |
| 极限尝试 | **硬盘寿命** → SSD 被写穿 |
| 长上下文 | **显存容量** → KV cache 爆 |
| 多用户并发 | **显存容量** + **算力** |

## 6. 瓶颈识别方法

### 6.1 实战诊断表

| 症状 | 病因 | 是哪个维度的问题 | 解决方案 |
|------|------|----------------|---------|
| 模型加载 OOM | 显存不够 | **显存容量** | 换更小模型或更激进量化 |
| 加载成功但很慢（< 10 tok/s） | 部分层在 CPU 跑 | **显存容量** | 减少 num_ctx 或换小模型 |
| 速度还行但不够快（30 tok/s） | 带宽限制 | **显存带宽** | 升级 GPU |
| 第一个 token 等很久 | Prompt 处理慢 | **算力** | 减短 prompt 或换更强 GPU |
| 长上下文崩溃 | KV cache 爆 | **显存容量** | 开 KV 量化或减小上下文 |
| 多卡训练慢 | 卡间通信瓶颈 | **NVLink/PCIe** | 用单卡更大显存 |
| 系统卡死 / SSD 狂转 | 模型在 swap | **内存容量** | 立刻杀进程，模型选错了 |
| 跑量化模型不快 | 精度不被原生支持 | **精度支持** | 换支持该精度的新卡 |

### 6.2 自检命令

**llama.cpp 跑模型时观察这些指标**：

```bash
# 看显存占用
nvidia-smi

# 看是否在 CPU 上跑
llama-cli --verbose ... 
# 看输出里 "offloaded X/Y layers to GPU"

# 测速度
llama-bench -m model.gguf
```

**Ollama 用户**：

```bash
# 看模型加载情况
ollama ps
# PROCESSOR 列：100% GPU = 正常；CPU/GPU split = 在卸载
```


```
我要做什么？
│
├─ 跑 7-13B 模型聊天    → 12GB 卡足够（4070 / 3060）
├─ 跑 14-30B 模型      → 16-24GB 卡（4080 / 3090）

├─ 微调大模型          → 多卡 4090 或租云

└─ 多模态（图像/视频） → 显存优先，3090 / 4090
```

### 7.3 升级路径建议

**场景 1：你已经有 4070 12GB**

- **加内存到 64GB**（几百块）→ 能跑 30B MoE 模型
- **不建议**直接换 4070 Ti Super（提升有限）
- **推荐**攒钱直接上 5090 或二手 3090（双卡）

**场景 2：装新机**

- **预算紧张** → 二手 3090，一步到位
- **预算充裕** → 5090 32GB，未来 3 年不用换

## 8. 常见误区

### ❌ 误区 1："我 GPU 算力不够，所以模型慢"

**真相**：99% 情况是带宽或显存不够，**算力很少是单用户聊天的瓶颈**。

### ❌ 误区 2："新卡一定比老卡快"

**真相**：跑 LLM 看带宽，老 3090（936GB/s）比新 4070（504GB/s）快得多。

### ❌ 误区 3："多核 CPU 能加速 LLM"

**真相**：CPU 只在大量内存卸载时才重要。全 GPU 推理时 CPU 几乎不工作。

### ❌ 误区 4："算力翻倍 = 速度翻倍"

**真相**：只有训练任务和长 prompt 处理符合这规律。日常聊天，算力翻倍只能带来 10-20% 提速。

### ❌ 误区 5："Tensor Core 数量决定一切"

**真相**：要看代际。4090 的 512 个第 4 代 Tensor Core ≈ 30 系 1024 个第 3 代。

### ❌ 误区 6："显存带宽和算力可以互相补"

**真相**：不能。它们是串联瓶颈，**短板决定一切**。

### ❌ 误区 7："PCIe 5.0 比 4.0 跑 LLM 快"

**真相**：单卡纯 GPU 推理时几乎无差别。只有 CPU 卸载或多卡才有意义。

### ❌ 误区 8："4090 跑 70B 模型也行"

**真相**：70B Q4 约 40GB，超过 24GB 显存，必须卸载。速度从 80 tok/s 暴跌到 5-10 tok/s。

### ❌ 误区 9："核显也能跑 LLM"

**真相**：理论上能，实际上慢得没法用。核显共享系统内存，带宽通常 < 100 GB/s（独显的 1/10）。

### ❌ 误区 10："苹果 M 系列芯片不行"

**真相**：M3 Max 的统一内存带宽 400 GB/s，跑 LLM 体验跟 4070 差不多。M4 Max 带宽 540 GB/s 更接近 4070。**Mac 跑 LLM 是合格选项**。

## 附录 A：核心公式速查

```
理论推理速度 (token/s) ≈ 显存带宽 / 模型大小

举例：
  4070 跑 14B Q4 模型
  = 504 GB/s ÷ 9 GB
  ≈ 56 token/s 上限
  实际能达到 70-85% = 40-50 token/s
```

```
显存够不够：
  最小需求 ≈ 模型大小 × 1.2 + KV cache

KV cache 估算：
  KV ≈ 上下文长度 × 0.0001 × 模型参数量 (GB)

举例：14B 模型开 8K 上下文
  KV ≈ 8000 × 0.0001 × 14 ≈ 11 GB
  （实际比这少，因为有量化和 Flash Attention）
```

```
精度位数 vs 体积比：
  FP16 → 1.0×（基准）
  FP8  → 0.5×
  Q4   → 0.25×
  Q2   → 0.125×
```

## 附录 C：你的 4070 12GB 真实定位

```
算力角度：117 TFLOPS FP16，处于 2024-2026 消费卡中游
带宽角度：504 GB/s，中等水平
显存角度：12GB，是 LLM 玩家的"刚够用"门槛

擅长：
  ✅ 8B-14B 模型流畅对话（40-60 tok/s）
  ✅ Q4 量化所有 7-14B 模型
  ✅ Phi-4-reasoning、Qwen3.5-9B 等小钢炮
  ✅ 单用户场景

不擅长：
  ❌ 30B+ dense 模型（显存不够）
  ❌ 70B 模型（怎么压也不够）
  ❌ 长文档处理（KV cache 吃显存）
  ❌ 训练 / 微调（算力 + 显存双重不够）
  ❌ 多用户并发（算力不够）

升级建议：
  → 加内存到 64GB（最便宜，能跑 MoE）
  → 长期换二手 3090（24GB + 高带宽）
```
